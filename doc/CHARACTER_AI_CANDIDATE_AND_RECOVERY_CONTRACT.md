### 1.2 核心不变量（必须全程保持）

1. **136 张实体守恒**：全桌固定实体 ID `0..135`（`TileId.MinValue..TileId.MaxValue`），`typeIndex = id >> 2`（万 0–8、索 9–17、筒 18–26、风 27–30、三元 31–33），`copyIndex = id & 3`；赤五判定为 `IsNumberTile && Rank == 5 && CopyIndex == 3`（五万赤 `19`、五索赤 `55`、五筒赤 `91`，见 [TileId.cs](../dotnet/src/Mahjong.Domain/TileId.cs#L53-L109)）。
2. **权威裁决与串行队列**：所有状态变更、扣费、deadline、持久化和结算只在 `TableActor` 单消费者串行邮箱中裁决；AI 策略和评分只在权威队列外消费冻结只读视图，策略**只能返回宿主冻结的有效候选索引或 `OptionId`**，绝不自行读取 `RoundStateMachine`、`TilePositionMap`、`GameState` 或根据牌面拼装未授权计划。
3. **信息隔离**：公共投影与观战不含私有手牌、出千余额、账本、落汗标记、袖里藏花 offer/预留或牌山序列；他席手牌与未授权暗槽对本席不可见（`Marked == false` 时仅知槽位类型与索引，`TileId = null`）。
4. **单局不可复活**：`RoundStateMachine` 终态后不可复活，下一局必须建立新 `roundId` 与新状态机（见 [V5-0-RULE-CONTRACT.md](./v5-重构/V5-0-RULE-CONTRACT.md#L196-L201)）。

## 3. 可选激活 vs 已付费 Offer、时序控制、身份绑定与零副作用合同（验收 2）

### 3.1 可选激活与已付费 Offer 的严格区分

| 维度 | 可选激活窗口（`IsOfferChoice == false`） | 已付费 Offer 窗口（`IsOfferChoice == true`） |
|---|---|---|
| **涵盖动作** | `SubmitTileMark`、`SubmitSleeveBloom`、`SubmitBeamSwap`（及未来 `SubmitSleeveBloomOffTurn`） | `SubmitSleeveBloomChoice`、`SubmitBeamSwapChoice`（及历史/真人 `SubmitSleeveBloomOffTurnChoice`） |
| **索引 0 / 跳过语义** | **索引 `0` = “不使用 / 跳过”**：允许不提交千术命令，直接推进普通动作 | **严格屏蔽“不使用”**：权威与策略均禁用跳过；必须在权威冻结的合法选项中选 1 项（总项数 `<= 64`，含安全默认） |
| **安全默认项（`IsSafeDefault`）** | 索引 `0` 跳过（0 费用、不发命令） | `"sleeve-first"` (`First`) 或 `"beam-keep"` (`KeepOriginal`)，固定计入 64 槽内且绝不被截断 |
| **预算 / 开关 / 托管门禁** | 受四重拦截（任一不满足即不激活/跳过）：<br>1. `AiCheatPolicy.Enabled == true` 且 `Allows(capabilityId)`<br>2. `SpentThisRound + cost <= MaxSpendPerRound` 且 `CheatPoints - ReservePoints >= cost`<br>3. `Takeover` 席必须显式 `allowTakeoverPaidCheats == true`（默认 `false`）<br>4. 模型不可用或超出预算 -> 跳过 | **完全豁免新付费拦截**（激活已扣清，选择 `Cost == 0`）：<br>- 即使处于 `Takeover`（`TakeoverMaySpend == false`）、预算耗尽、`Enabled == false`、模型缺失或版本不兼容，**仍必须通过合法候选或 `IsSafeDefault` 结清**，绝不卡死牌局 |
| **扣费与退款** | 成功激活精确扣一次；跳过/拒绝 0 扣费 | 选择阶段 0 扣费；选 `First` / `KeepOriginal` / 超时 / 漂移清理**均不退款** |

### 3.2 安全默认与到期交由权威的时序合同

1. **队列外推理，队列内单步裁决**：
   - `CaptureAiObservationAsync` / `CaptureAiCheatOpportunityAsync` 在 `TableActor` 串口内抓取不可变快照、捕获身份与权威 `DeadlineMillis`；
   - 策略仅在队列外读取冻结候选索引，不在本地强行重拼提交参数；临近或已过 deadline 不强行投递，交 `TableActor.TickAsync` 统一到期结算。
2. **`TableActor.ProcessTickCoreAsync` 真实时序与到期行为**（[TableActor.cs#L2770-L3260](../dotnet/src/Mahjong.TableRuntime/TableActor.cs#L2770-L3260)）：
   - **Step 1**：`SweepExpiredCheatOffersAsync(now)`（[TableActor.cs#L3068-L3106](../dotnet/src/Mahjong.TableRuntime/TableActor.cs#L3068-L3106)）— **仅扫描他家回合 `OffTurnOffer`**（结算所有 `now >= offer.DeadlineMillis` 或跨启动 `offer.BootId != currentBoot` 的 `OffTurnOffer`，强制 `First` 锁定预留；**不扫描即时 `ImmediateOffer` 或 `BeamSwapOffer`**）。
   - **Step 2**：`PlanTick(request, now)` — 先收集到期决策为 `TickEntryKind.Timeout`，再筛选 `request.AiDecisions`；凡同席已到期或 `now >= aiTiming.DeadlineMillis` 的 AI 结果一律标为 `AiRejected / DeadlineExpired`。
   - **Step 3**：逐项执行前重读权威单调时钟 `TryReadClock(out actionNow)`；一旦 `actionNow >= deadline`，**超时立即胜出**，迟到 AI 丢弃。
   - **Step 4（挂起即时 offer 的超时接管，现行精确行为）**：在 `ExecuteDueTimeoutAsync`（[TableActor.cs#L3160-L3207](../dotnet/src/Mahjong.TableRuntime/TableActor.cs#L3160-L3207)）中，当同席挂起 `ImmediateOffer` 或 `BeamSwap.Offer` 时，权威端以 **`TimingConsumption.Expire`** 提交 **`ExpireImmediate` / `ExpireBeamSwap`**（强制 `First` / `KeepOriginal` 清理 offer，记 `TableCheatSystemCodec` 日志，**不退款**），随后 **立即 `return new TableTickEntry(...)` 结束本次决策执行**！**同一 `Tick` 步内绝不会在同一分支里继续调用 `TimeoutPolicy.Choose` 去自动打牌或立直**；后续普通动作等待新开普通决策或下一个驱动步/Tick 推进。
3. **普通命令隐式结清的同事务与回滚语义**（[TableActor.cs#L1486-L1695, L2455-L2484](../dotnet/src/Mahjong.TableRuntime/TableActor.cs#L2455-L2484)）：
   - 仅当本席主动提交合法普通命令（如 `Discard` / `Riichi` / `Pass` 等），`TrySettleOfferForCommand` -> `RoundCheatTransition.PrepareCommandWithOfferSettlement` 才在同一权威事务内先将挂起的 `ImmediateOffer` / `BeamSwapOffer` 按 `First` / `KeepOriginal` 结清，再执行该普通命令；
   - 若该普通命令本身不合法而被拒绝（如无效牌、阶段/轮次/身份不符），整次事务不提交，**原待决 `Offer` 完整保留不受影响**。

### 4.2 旧指纹校验与四席角色迁移顺序（M1-02 合同）

> [!CAUTION]
> **先验旧指纹，后迁移**。严禁在校验原签名/指纹前修改字段或填充默认值；校验失败立即 fail-closed 拒收，不得降级为 `"player"` 或新开对局。

#### 4.2.1 严格校验与解码顺序

1. **外层载荷与 SHA-256 校验**：
   - 本地存档：`LocalSaveCodec.DecodeEnvelope` 先校验 `SaveMagic` (`LH4P`)、`SaveEnvelopeVersion == 1` 与整包 SHA-256（[LocalSaveCodec.cs#L45-L99](../dotnet/src/Mahjong.LocalHost/LocalSaveCodec.cs#L45-L99)）。
   - 通用恢复：`TableRecoveryService.RecoverWithLeaseAsync` 先核对 `TableCheckpoint.SchemaVersion == 2`、`RulesetVersion`、`RoomId`，再逐段比对所有 `PayloadSha256`（[TableRecoveryService.cs#L341-L404](../dotnet/src/Mahjong.TableRuntime/TableRecoveryService.cs#L341-L404)）。
2. **`TableCheatLedgerCheckpointCodec.Decode` 分版本读取与原指纹校验**：
   - 读 `Magic == 0x4D4A4C43` 与 `schema`：
     - **未知或不支持的 `schema`**（`< 4` 或 `> 7`）：直接抛 `InvalidDataException`（上层转为 `CheckpointInvalid`），拒绝恢复。
     - **尾部多余字节或截断**：`stream.Position != payload.Length` 或 `EndOfStreamException` 直接抛 `InvalidDataException`。
   - 依据原 `schema` 按**各自原始格式**校验 `totalVersion` 与 `fingerprint`：
     - **Schema 4（无角色字段）**：无 `ThirdTile`、无角色字段；以单席旧口径（`characterId = "player"`, `traitsVersion = 1`）重建并计算**旧 FNV-1a 指纹**，断言匹配 `totalVersion` 与 `fingerprint`（[CheatState.cs#L254-L258](../dotnet/src/Mahjong.Domain/Cheat/CheatState.cs#L254-L258) 对 `"player"` v1 不混入字符，故 v4 与 v5/v6 `"player"` 原指纹一致）。
     - **Schema 5 / Schema 6（单席旧档）**：读取 `ThirdTile`（若有）及单个 `characterId`、`characterTraitsVersion`；先校验 `PlayerCharacterIds.IsSupported(characterId)` 与 `characterTraitsVersion == 1`，不合法直接抛 `InvalidDataException`；再按**旧单席 FNV-1a 指纹公式**校验原 `totalVersion` 与 `fingerprint`。
     - **Schema 7（四席新档，M1-02 新增）**：读取 `ThirdTile`（若有）及长度为 4 的 `characterIds[0..3]` 与 `characterTraitsVersions[0..3]`；逐席校验 `PlayerCharacterIds.IsSupported` 与 `traitsVersion == 1`；再按**四席 FNV-1a 指纹公式**校验 `totalVersion` 与 `fingerprint`。
3. **四席映射规则（仅在原指纹校验通过后执行）**：

| 原 Schema | 原角色字段内容 | 迁移后 `CharacterIds[0..3]` | 迁移后 `CharacterTraitsVersions[0..3]` | 说明 |
|---|---|---|---|---|
| **Schema 4** | 无角色字段 | `["player", "player", "player", "player"]` | `[1, 1, 1, 1]` | 四席均为默认普通角色 |
| **Schema 5 / 6** | `"player"`, `v1` | `["player", "player", "player", "player"]` | `[1, 1, 1, 1]` | 0 席为 `player`，1–3 席补齐 `player` |
| **Schema 5 / 6** | `"octopus"`, `v1` | `["octopus", "player", "player", "player"]` | `[1, 1, 1, 1]` | 旧 0 席 `octopus` 映射到 0 席，1–3 席补齐 `player` |
| **Schema 5 / 6** | 未知 ID 或非法 `traitsVersion` | **拒绝**（`InvalidDataException` -> `CheckpointInvalid`） | — | 禁止静默回退为 `player` |
| **Schema 7** | `[c0, c1, c2, c3]`, `[v0, v1, v2, v3]` | `[c0, c1, c2, c3]`（原样保留） | `[v0, v1, v2, v3]`（当前仅支持 `1`） | 写入新检查点统一采用 Schema 7 |

4. **迁移后指纹与 `table_state.CheatFingerprint` 兼容目标（供 M1-02 实现与验证）**：
   - `TableRecoveryService`（第 610–620 行）和 `LocalTableRecoveryFactsReader`（第 356–359 行）会在恢复末期比对最终 `cheat.Version`/`cheat.Fingerprint` 与持久化的 `table_state.CheatVersion` / `table_state.CheatFingerprint`。
   - **M1-02 设计目标（待 M1-02 编码落地并实测验证）**：`CheatState.ComputeFingerprint`（64 位 FNV-1a）须保持单席默认前缀兼容性：
     - 当 `seat 1..3` 均为 `("player", 1)` 时：若 `seat 0` 也为 `("player", 1)` 则保持旧默认不混入字符；若 `seat 0` 为非默认角色（如 `"octopus"`, `1`）则仅按旧格式 `MixString(c0); MixValue(v0)` 混入；
     - 当 `seat 1..3` 中任一席非 `("player", 1)` 时：混入显式四席版本标记及 4 个 `(seat, characterId, traitsVersion)`。M1-02 须通过 `M1T-01`、`M1T-04` 实测单席/多席变更敏感度及静态恢复与日志重放哈希匹配。

### 4.3 待决与历史第三候选的冷恢复及日志重放语义

1. **待决 `SleeveBloomOffer`（`ImmediateOffer` 或 `OffTurnOffer`）含 `ThirdTile`**：
   - Schema >= 5 均持久化 `ThirdTile.HasValue` 及实体 ID `0..135`；恢复后 `ThirdTile` 原样保留在 `Offer` 上。
   - Schema 5/6 `octopus` 存档映射后 `CharacterIds[0] == "octopus"`；Schema 7 任意席 `octopus` 保留 `CharacterIds[seat] == "octopus"`。
   - `TableCheckpointValidator` 与 `TableVisibilityProjection.ValidateRecoveredFacts` 校验 136 张实体守恒与私有投影一致。
2. **已提交事件日志含 `SleeveBloomKeep.Third` 与 `canLegacyRetry` 全部精确条件**（[TableRecoveryService.cs#L534-L559, L1793-L1988](../dotnet/src/Mahjong.TableRuntime/TableRecoveryService.cs#L534-L559)）：
   - **Schema <= 5（`isLegacyCheatSchema`）**：允许将历史 `Third` 不可验证且等于 `FirstTile` 的 `ResultTile` 归一化为 `null`（若存在可验证实体第三张则归一化为 `verifiableThird`）。

     1. 首次重放失败原因为 `TableRuntimeReasonCode.RecoveryReplayMismatch`；
     2. 检查点格式版本 `FormatSchemaVersion <= 5`（`ThirdTileAndCharacterSchemaVersion`）；
     3. 检查点/首轮重放中确实曾见待决他家第三张候选（`sawPendingOffTurnThird == true`）；
     4. 以 `protectOffTurnThird: false` 二次重放须**完全成功（`attempt2.Failure == null`）且确实消费了该曾挂起的他家第三张（`attempt2.ConsumedPendingOffTurnThird == true`）**，否则仍按首轮失败返回，绝不盲目放宽。
   - **Schema >= 6（含 Schema 7）**：
     - 存在可验证第三张实体证据时，历史 `ResultTile` 必须精确匹配 `verifiableThird`；
     - 曾由 v5 归一化保存的 `ResultTile == null` 在无实体第三张证据时允许在 v6/v7 重存与冷恢复中继续有效（[TableRecoveryService.cs#L1935-L1940](../dotnet/src/Mahjong.TableRuntime/TableRecoveryService.cs#L1935-L1940)）；
     - 严禁伪造非空 `ResultTile`（如 `SecondTile`）且禁止 Schema >= 6 触发 `canLegacyRetry`。
3. **重放未合并入检查点的千术日志（`TableCheatCommandCodec` schema 2）**：
   - `TableCheatCommandCodec`（[TableCheckpointCodecs.cs#L1101-L1184](../dotnet/src/Mahjong.TableRuntime/TableCheckpointCodecs.cs#L1101-L1184)）仅持久化 `RoundId, Seat, Action, RequestId, Payload, TurnNumber, NowMillis, RoundOrdinal, LastDrawKind, BootId`，**无单独 `TraitInput` 日志字段**，本阶段保持既有 Schema 2 读取格式不变。
   - 重放先完成四席映射（Schema 4/5/6 -> 四席；Schema 7 原样读入），再由 `CheatSubmission` 按 [CheatSubmission.cs#L329](../dotnet/src/Mahjong.Domain/Cheat/CheatSubmission.cs#L329) 从**重放后的权威牌面状态或请求本身确定性重建 `traitInput`**：确认路径由重放至当前步的 `TileStateHash.Format(map.StateHash)` 得出，非确认/他家路径由原日志 `command.RequestId` 得出；结合日志中的 `DrawKind` / `TurnNumber` / `NowMillis` / `BootId` 保证重放确定性。

4. **未知/损坏版本与备份边界**：
   - **单检查点损坏**：任意 Magic/Schema/FormatVersion 错误、未知角色或版本、SHA-256 或 FNV-1a 不匹配、截断/尾随字节 -> **Fail-Closed 拒收**（`CheckpointInvalid` / `CheckpointSchemaUnsupported` / `RecoveryStateHashMismatch`），不降级 `"player"`、不覆盖存档。
