# 耗时构建与验证任务通用模板

适用于昂贵构建、共享 Unity/设备/数据库资源、真实客户端端到端验证，以及容易因重复返修而长时间运行的任务。普通文案修改和短单测不需要套用完整流程。

目标是把可便宜发现的问题提前暴露，保留最终验证标准。预计耗时是规划信息，不是完成承诺；不能因时间预算耗尽改判 PASS。

## 一、先填写任务卡

```text
任务 ID / 具体目标：
执行者 / 复核者（如现有流程要求）：
工作树 / 分支 / 当前 HEAD / 已接受基线：
允许修改的具体文件 / 明确排除的范围：
已有有效结果、源码或输入身份、原始证据路径：
全部已知缺陷 / 已关闭且不重开的子项：
固定场景分母 / 每个场景的真实成功断言：
依赖是否就绪 / 文件范围是否冲突：
本次唯一输出根 / 临时目录 / 自有进程及清理边界：
阶段表：阶段、实际命令、进入条件、成功条件、超时、产物：
共享资源 / 锁名 / 等待上限 / 心跳间隔 / 取消方式：
失败分类 / 可重试条件 / 无法自行处理时的最小请求：
最终源码身份 / 构建与包身份 / 必须重验的组合：
```

沿用已存在的任务 ID、契约和输出约定，不为使用模板重新实现一套调度器、验证器或报告系统。目录、命令、文件清单必须核实后填写，不把拟议参数当成现有能力。

## 二、按成本逐级推进

| 阶段 | 主要工作 | 进入下一阶段的条件 |
|---|---|---|
| A：核定与环境短预检 | 读现有任务/验收记录；检查范围、依赖、工具、空间、许可或设备是否可被当前进程识别 | 前置可用；缺项有明确原始证据和影响范围 |
| B：核心实现与组件回归 | 最小范围批修已知缺陷；用真实组件入口和确定性场景验证功能、生命周期、并发及拒绝边界 | 已知相关缺陷全部修复，必要正负例通过 |
| C：生产端与验证端对齐 | 对齐真实序列化、请求/回执/事件/后态、脚本判断和失败退出；验证超时、取消与失败封存 | 相同原件能通过完整验证链；指定无效输入被拒绝；失败不会被摘要吞掉 |
| D：冻结并执行完整验证 | 冻结完整源码身份，构建真实产物，按固定矩阵运行同包场景 | 所需实际用例、退出码、状态和完整证据均满足合同 |
| E：交付与复核 | 停止自有 writer；核对最终结果、输入变化、包清单和哈希；按现有流程复核 | 明确本任务结论、未覆盖边界与可接续检查点 |

阶段可按实际技术栈合并，但不能把昂贵验证当成廉价脚本调试循环。阶段通过后在既有授权内继续；不新增逐阶段人工批准。已有流程明确要求复核或外部授权时才等待，并写明等待谁、等待什么。

### 环境预检

- 使用小型、独占且有界的预检；不要先完整跑完组件套件再首次检查许可或设备。
- 首次导入/冷缓存与单纯许可查询分别设定合理上限，避免把正常导入误判为挂死。
- 报错只证明该进程当次失败。例如“批处理没有识别许可”不能直接解释为“用户没有许可”；先比较实际工具路径、用户会话、环境继承与授权客户端连接。
- 检查和使用现有环境；本模板不授权激活、返还、购买许可或修改机器配置。

### 便宜阶段必须提前发现的合同问题

- 真实 producer 字段与解析器必需字段一致；检查实际序列化结果，不只比较源码声明。
- 分开命令载荷与事件载荷的字段、空值和枚举语义；提交牌选择不一定等于事件牌集合。
- 分开目标事件序号与回执高水位、接收计数与流游标、精确提交态与最新状态；依据实际契约关联，不假设数值相等。
- 后台还会推进时，保留并校验目标提交的原始状态；增加“随后又有合法提交”的正例和错误身份/版本/事件绑定负例。
- 公私数据比较按 owner、audience、版本和当前可见性进行，不用裸标量巧合推断泄露。
- 对验证器和脚本入口运行有意义的负例，确认其非零退出向上传递。预期失败的 stderr 不能因 PowerShell 异常策略而中断测试矩阵。
- 工具夹具只能证明工具行为，不能改标签冒充真实应用、Player 或设备执行。

## 三、运行与等待边界

以下是默认值，按真实阶段成本调整并记录理由，不擅改已有生产 deadline 或任务验收标准。

| 项目 | 默认约定 |
|---|---|
| 共享资源等待 | 总计最多 10 分钟；分段等待，记录实际锁名和等待原因 |
| 心跳 | 每 30 秒记录阶段、耗时、进程状态及当前产物；长哈希扫描也报告进度 |
| 每个外部阶段 | 启动前给出有限超时；首次导入、编译、运行分别估计 |
| 无可见进展 | 先检查自有进程、CPU、日志与当前扫描；不能仅因日志暂未刷新就杀进程 |
| 取消 | 使用 runner 支持的取消或正常退出，等待自有 writer 停止后封存 |
| 输出目录 | 每次独占 GUID 根，拒绝覆盖已有证据；临时缓存与稳定产物区分 |

先用短负例验证锁等待超时、取消、原生非零与稳定封存，避免用数小时真实等待才发现收尾错误。不要双重持锁导致跨进程死锁，不绕过共享锁，不终止别人的进程。

父任务/复核者的等待状态必须如实更新。发出继续指令后核实执行已开始；子任务仍在运行时不要复制启动。异步工具要求结束当前回合并等待回调时，遵守工具合同，不轮询同一无变化进度。

## 四、失败、重试与恢复

| 分类 | 处理 |
|---|---|
| 产品实现或验证工具缺陷 | 定位原始失败，批量处理同类已知问题，组件正负例通过后再进入昂贵阶段 |
| 资源忙或环境不可用 | 保存当次证据，标明后续 NOT_RUN；条件改变或具体原因已处理后再试 |
| 会话/桥接中断 | 先检查任务和自有进程是否仍在；根据提交、阶段记录和证据接续，避免重复执行 |
| 原因未明 | 保留 UNKNOWN、未确认结果与必要原件，先诊断，不假定退出码或自动重做副作用 |

每次重试必须说明新证据、修复或前置条件变化。资源等待不算代码返修；反复执行相同输入不能作为修复。连续缺陷升级和人工裁决遵守当前适用协议，本模板不另设相互冲突的轮次阈值。

优先正常退出。若中断导致原 runner 未封存，后续恢复记录必须注明 `RECOVERED_AFTER_INTERRUPTION`，未知原生退出记为 UNKNOWN，不伪装成原 runner 正常结束；保留全部原始文件。

恢复时先核对最后一个可验证检查点，再继续必要阶段。原生会话确实丢失时，以真实提交和证据重建上下文并记录接续关系；任务替换和范围调整仍需现有授权，不删除旧历史掩盖失败。

## 五、重验范围与最终证据

已通过且相关输入未变化的检查不机械重复。任何复用都要说明源码、输入、工具、环境条件与结果的对应关系，不能把旧候选的测试写成新候选通过。

| 变化 | 重验要求 |
|---|---|
| 仅文档 | 核对文档与已测源码/包绑定，通常无需重建 |
| 组件代码 | 重跑受影响正负例及必要关联模块；最终应用证据按受影响闭包重新绑定 |
| runner / 验证器 | 先用真实原件和篡改负例验证；最终运行需证明使用修正后的生产入口 |
| 应用源码、共享 DLL、依赖或构建输入 | 重新冻结相关源码与包，执行合同要求的受影响集成验证 |
| 最终合同要求同候选同包全矩阵 | 即使有历史通过结果，也必须取得该最终候选同包的完整证据 |

不得为节约时间绕过 provenance、降低断言、添加 skip 或引入未经验证的阶段恢复机制。现有 runner 强制 fresh 完整闭包时，按合同执行；确需优化 runner，作为明确范围内的工具变更先验证。

状态逐项区分：PASS（实际满足）、FAIL（实际失败）、BLOCKED（前置阻断）、NOT_RUN（未运行）、UNKNOWN（结果无法确认）。缺证据不算成功。组件、工具、真实客户端、平台和项目阶段结论分别记录。

最终记录最少包括：源码提交与输入闭包、完整包清单、实际命令、原生退出/超时、真实用例计数、逐场景结果、请求与可见结果绑定、首次失败、日志和哈希、未覆盖范围。当前项目继续保留 136 张实体守恒、幂等、控制代次与模块边界等有效合同。

先停止自有 writer，再写最终 summary 和 manifest，封存后不得继续写已哈希文件。复核者记录自己实际重跑了哪些检查、哪些是原件复核，不能把接收方执行改称独立重跑。已有结论满足后结束该任务；进入后继范围、推送、合并或部署仍按原授权处理。

## 六、可复制的下发模板

```text
任务：{ID 和本次具体目标}。
先读取 AGENTS.md、适用协议及 doc/LONG_VALIDATION_TASK_TEMPLATE.md。
工作树/分支/当前 HEAD：{已核实值}。
修改范围：{具体文件}；排除范围：{明确列出}。
保留结果/检查点：{源码身份、通过项、原件路径、关闭子项}。
已知缺陷全集：{完整分组、复现、期望、修复要求、验收断言}。
固定矩阵：{每案真实入口、预期效果和拒绝边界}。

A 先核范围、依赖和当前进程环境，以短预检证实昂贵阶段可运行。
B 批量修完全部已知缺陷，完成确定性组件和必要关联模块回归。
C 对齐真实 producer/载荷/事件/状态与验证器；验证失败传递、短超时、取消及封存。
D 前置全过后冻结完整源码身份，运行 {实际完整命令}，取得 {同包矩阵}。
E 核对证据闭包并按当前协议复核，交付 {唯一报告路径}。
阶段通过后在已有授权内自动继续；不要新增逐阶段确认。

锁/总等待/心跳/阶段超时：{实际值及理由}。
取消入口/自有进程边界：{已验证方式}。
证据与缓存：{本次独占根、空间/磁盘要求、稳定与临时产物分类}。
失败先诊断并批修，只有原因已处理、输入变化或资源恢复才重试。
保留首次失败；恢复记录注明接续关系和未知退出，禁止覆盖旧原件。
最终报告精确源码/包身份、命令/native exit/XML计数、各案状态、原件及哈希。
不扩大修改范围，不把组件结果升级为项目阶段通过；外部变更遵守既有授权。
```

## 七、D05 的应用示例

先冻结已接受的 D03 集成基线，再做单 room/多 connection 的纯 .NET 实现和真实通道回归，覆盖四席、观战、票据、关闭单个连接、控制/断线 deadline、默认 AI、恢复和幂等。通过后接 Unity 多视图与隐私验证，提前对齐角色、序列化字段、可见性和旧 binding 延迟投递；最后一次冻结候选，运行所需 Player 矩阵并封存。

该示例只说明执行顺序，不构成 D05 派发、额外文件授权或三绝技人工裁决范围的解禁。
