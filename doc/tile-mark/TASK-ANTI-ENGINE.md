- 每位玩家有效标记总数最多 12，即最多三组；不可见区域里的有效标记仍占名额。

- 首版沿用设计建议：本人可弃牌阶段、未立直才能新施术；同一玩家的有效组不重叠、不替换、不续期；满足额度、期限和容量时可连续使用；不新增随机失败、怀疑度或抓包判定；AI 暂不主动施术。以上是设计默认决策，区别于用户明确指定的数量、费用、期限和位置要求。

## 实现顺序与契约

### 1. 整场状态与生命周期

新增强类型标记规则、组状态、请求和投影，名称以设计为基线。`MatchSession` 持有跨局状态，接入 `SessionChange` 的 prepare/install 和防御复制；旧的整场变更必须保留这些状态。不要把跨局状态塞进单局 `GameState` 或可变的全局表。

同一 `roundId` 首次成功发牌才登记一次局次；覆盖直接发牌、码牌准备后发牌以及测试已发牌 initialState。每组在最后有效局的结果首次被接受时清除，只释放自己的 4 个名额。结算重复调用幂等。整场结束/关闭清理；断线、接管、显式收回控制保留原期限。

### 2. 权威写入口、费用与时钟

新增 `TableAuthority.submitTileMark(seat, request, now)` 成员。请求含 requestId、sessionId、roundId、decisionId、controlEpoch、tileIds；座位身份和时间由可信宿主提供。`coordinator` 保持封装，不能重新公开给 server。

区分校验责任：网络绑定、观战身份和连接代次在第二阶段宿主接线时校验；engine 本阶段校验领域座位控制权、整场/局/决策/控制代次、阶段、立直、暂停、有效计时、归属、数量、去重、容量和余额。不得为补网络校验让 engine 依赖 server 或 protocol。

通过 `ApplicationCoordinator` 的既有提交机制原子安装扣费及标记状态。拒绝不扣费、不留半组、不移动牌；不能先提交账本再尝试创建组。施术属于出牌前的补充操作，不能完成弃牌、换人、摸牌或重开倒计时。沿用 `DecisionClock.rekey()` 保留原 opensAt/deadline、储备及 generation；`now == deadline` 必须拒绝。

幂等记录包含操作类别和载荷指纹；排序规范化合法 tileIds。相同请求返回原结果，标记到期后重放也不能复活；改载荷或跨写接口复用同一 ID 必须冲突。审查既有去重结构并兼容其生命周期，避免新增一个可绕过普通动作去重的孤立缓存。

### 3. 私有投影与牌河位置

`PlayerSnapshot` 提供本观察者的可用性、可选牌、费用、容量和全部有效组。公开观战投影不得增加标记数据；不要把其他玩家的有效组或整副牌的位置映射泄漏出去。

牌河位置由 engine 在同一已提交版本的牌河中按实体 ID 查询：`view.discards[seat][discardIndex].tileId` 必须等于标记实体。仅 DISCARD 位置带 `riverPosition`；鸣牌移走时同一快照清空牌河位置并切换公开副露，其他牌如发生索引变化则重新定位。准备、换局、到期清理旧位置。重连查询可完整重建当前位置，旧快照保持不变。

隐藏牌山、未公开王牌和袖牌统一显示 NOT_VISIBLE，不提供隐藏座位或位置；对手手牌不提供真实排序索引。请求、状态候选、各级快照集合均防御复制，外部无法改写已提交状态。

## Codex 独立编写的行为测试

测试应通过真实的权威入口、状态变更与查询验证行为，不能只测 DTO 构造或伪造落汗结果。按设计验收清单覆盖本阶段，并至少包含：

1. 4/8/12 张累计成功、费用合计 30；第四组、重复实体、选 3/5 张、非本人牌及余额 9 均拒绝；余额 10 成功。
2. 同组当局和后三局有效；不同局创建的三组分别到期；不可见牌仍占容量；同一局回调不重复计数；码牌与直接发牌一致。
3. 扣费与标记原子；旧决策/旧控制代次/到期提交被拒绝；相同请求只扣一次，到期后重放不复活，跨 API 请求 ID 冲突。
4. 施术前后 deadline 等计时数据不变，下一次正常出牌仍可提交；正好截止时拒绝；请求原列表被修改不影响状态。
5. 四座位私有信息隔离、公开投影无标记；同种不同副本及赤五不混淆；不同玩家可各自标记同一实体。
6. 对手手牌到牌河、牌河到副露的投影真实变化；牌河首张/换行边界/末张位置；局次、座位、索引、实体 ID 一致；旧快照不漂移。
7. 所有施术前后 136 张守恒，跨局仍跟随原实体；功能关闭时旧行为不变；重连、接管、整场结束的保留或清理正确。
