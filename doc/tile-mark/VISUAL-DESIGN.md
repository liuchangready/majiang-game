# 落汗图形展示与牌河提示设计

日期：2026-10-12。状态：已由 Anti 实施，Codex 编写测试并独立验收通过：1050 项测试、双端构建、两种视口真实 GL，见[展示验收报告](ACCEPTANCE-VISUAL.md)。

落汗效果改为直接显示在牌上：三名对手的暗手牌全部绘制，普通牌显示不透明牌背，落汗牌显示半透明牌面。新增可开关的牌河提示面板，用牌面、数量、东南西北分栏和位置高亮表达信息，移除原有文字位置追踪栏和独立的“落汗识别”牌列。

本设计接续[已验收的落汗规则](DESIGN.md)，每次 4 张、费用 10、最多 12 张、当局及后续 3 局有效保持原规则。开发依据见[Anti 任务单](TASK-ANTI-VISUAL.md)；既有验收结果不代表本次界面已经实现或测试通过。

## 已确认的展示口径

用户已确认以下两点：

| 内容 | 确认口径 |
|---|---|
| 还有多少张牌 | 牌山剩余可摸的总张数 |
| 东南西北的持牌展示 | 按东南西北展示手牌背面，仅落汗牌能看见牌面；未知归属不显示 |

提示面板四方手牌统一使用牌背，只有本人有效落汗牌显示半透明牌面，包括本人所在的方位行。主牌桌本人手牌继续正常显示，便于选牌和弃牌。牌山或其他隐藏区域中的标记牌，不分配到任何一家；本次不展示牌种余量、未知数量或归属预测。

## 牌桌展示

### 完整对手手牌

三家各有一条暗手牌行，与各自副露区分开；总张数来自 `PlayerView.handTileCounts[seat]`。摸牌、弃牌、吃碰杠后跟随快照更新，不能固定画 13 张，也不能把已知落汗牌额外加在暗手牌行旁而导致多画。

若某家暗手牌 13 张，其中 2 张为本人落汗牌，则画 11 张牌背和 2 张半透明牌面，总共 13 张。没有落汗效果时也绘制完整牌背行。

服务端没有下发对手真实手牌顺序。展示时将已知落汗牌放在该家牌行的固定一端，按牌种及实体 ID 排列，其余槽位画牌背；仅表达该家持有这些牌，不表达真实排序、摸牌槽位或下一张会打出的牌。牌背槽位不绑定未知实体 ID。

上家、下家牌行按座位旋转，对家牌行横置；牌面方向沿用各家桌面朝向。副露沿用独立区域，避免暗手牌增长后挤入副露。布局应同时容纳 14 张暗牌和现有副露布局的合法组合。

### 半透明视觉

| 位置 | 普通牌 | 本人有效落汗牌 |
|---|---|---|
| 对手暗手牌 | 不透明牌背 | 半透明牌面，建议 alpha 0.55，细轮廓保持可辨 |
| 本人手牌 | 原牌面 | 同样使用半透明牌面；选择抬起与选中框另行绘制 |
| 牌河及已获准显示的副露、指示牌 | 原牌面 | 半透明牌面，并保持实体所在槽位 |
| 提示面板四方手牌 | 不透明牌背，包括本人所在方位 | 半透明牌面 |
| 提示面板牌河网格 | 已公开牌面 | 半透明牌面 |
| 隐藏区域 | 不展示真实牌面和位置 | 不因有效标记而揭示所在区域或持有方 |

半透明作用于牌的底色与图案，细轮廓保留，避免牌在桌布上消失；赤牌、立直横置、副露方向仍须可识别。绘制完成恢复批次颜色与混合状态，不能使后续整排牌、按钮或文字一起变透明。0.55 为首轮视觉验收值，可在可读性检查后微调。

常驻效果区不再显示“自己手中”“下家手中”“牌河第几张”“当前不可见”“落汗识别”等句子。按钮名、方位字、数字、必要的操作失败提示仍可保留。使用费用、选择数量用额度图标与 `10`、`n/4` 表达。

三组寿命使用三组各四个小牌图标及四格寿命点表示：本局那格描边，后续有效局用实心点，已经消耗的局用空心点；最后有效局只剩本局一格。局间本局格变空，后续格留存，下次成功发牌后再将其中一格变为本局。每组独立更新，隐藏位置的牌仍占组内名额；这里表达已标记的身份和寿命，不表达其当前位置。

## 牌河提示按钮与面板

### 操作与布局

牌河外围增加固定的“牌河提示”切换按钮，使用牌叠图标及亮起状态，默认关闭。再次点击或按 Esc 关闭。手机使用相同点击交互，不依赖悬停。

打开后显示非模态侧面板，牌桌缩入剩余区域，牌河、本人手牌、操作按钮和倒计时保持可见且可操作。面板不暂停权威计时，不发起游戏动作，不消耗额度。面板内点击和滚动不得穿透到弃牌；选牌面板或结算弹窗打开时自动收起提示。

最终实现使用 1280×720 逻辑坐标：面板宽 410，主牌桌等比缩入左侧约 840 宽区域，渲染与点击使用对应变换；960×540 整体按比例缩放。两种尺寸均经桌面 GL 与真实截图验收，牌桌和面板不相互覆盖。

面板顶部显示牌山图标和 `wallRemaining`，表达剩余可摸总张数。主体固定四行，顺序为东、南、西、北；各行绘制该方全部暗手牌，普通牌为牌背，落汗牌为半透明牌面。每行结构如下：

| 方位 | 手牌图形 |
|---|---|
| 东 | 完整暗手牌行：牌背与落汗半透明牌面 |
| 南 | 同上 |
| 西 | 同上 |
| 北 | 同上 |

四行均按 `handTileCounts` 绘制，不另加标记牌列；即使某方没有任何落汗牌，也显示完整牌背行。普通牌背只表达这家有多少张暗手牌，不关联未知牌种或实体 ID。所有缩略牌面在面板中正向绘制，便于辨认；同种的多个落汗实体分别占槽，不合并数量。面板不保留万筒索字分页、各牌种余量或问号统计列。

东南西北表示本局门风，用 `view.seatWind(seat)` 映射，随换庄更新，与屏幕上下左右和玩家加入房间的座位编号分开。本人所在行可增加小圆点标识。

点击落汗实体缩略图，只高亮这张实体的当前可见位置；牌背不提供定位。再次点击清除。高亮使用牌槽轮廓，落汗牌的半透明样式保持。面板下部按东南西北显示各家当前牌河的小型位置网格，顺序复用桌面牌河布局；点击网格内实体牌可定位桌面对应槽位，无需文字描述位置。牌河较长时只在网格区域滚动，顶部总数和四方手牌保持可见。

示意：牌山剩余可摸 42 张，西家暗手牌 13 张，其中有一张本人落汗的一万。顶部显示牌山图标及 `42`；西行显示 12 张牌背和 1 张半透明一万，其余三行按实际暗手牌张数绘制。某张已标记牌当前归属不可见时，不在任何方位行中出现，也不推测它会由谁摸到。

### 牌山剩余总数

直接读取同一份已授权 `GameSnapshotView.view.wallRemaining`。现有领域值为 `maxOf(0, wallEndExclusive - wallPointer)`，经现有映射到客户端；表现层不重新用 136 张减手牌、牌河或副露计算。

普通摸牌、杠及补牌后的数值均以最新权威快照为准，不根据动画事件自行加减，也不额外把王牌或岭上牌加入可摸总数。面板收起后再打开、重连或新局开始时直接恢复当前快照值，不使用上次打开时的缓存数。

尚未发牌或缺少有效快照时显示 `—`，合法的剩余零张显示 `0`。不新增每种牌的统计、隐藏位置查询或概率模型。

## 牌河位置与状态变化

继续使用已有 `(roundId, seat, discardIndex, tileId)` 精确定位。绘制前验证当前牌河对应槽位的实体 ID；被吃碰杠拿走后，旧牌河位置立即失效，当前副露位置接管显示。

动画中的飞牌只绘制一次：飞牌阶段隐藏落点处同一实体的静态牌和高亮。牌山总数读取完整权威快照，牌河网格与桌面位置显示采用相同的动画可见性门控；不能依据事件再重复加减。切换新局、到期、断线恢复或换房间时，旧位置焦点按局标识与实体重新校验，失效即清除。

重连收到完整快照后整份重建牌行并更新牌山总数；空标记立即将对手牌面及提示面板的手牌牌面恢复成牌背。标记到期且对手仍持有该牌时，不保留“曾经见过”的透明牌面或其已知归属。普通牌河公开牌面不因标记失效而隐藏，仅恢复正常不透明绘制。

## 层次与接口设计

现有接口已经包含所需数据：`handTileCounts`、`discards`、`wallRemaining`、`seatWind()` 及 `tileMark.activeGroups` 内的区域、座位、牌河位置。主牌桌本人牌面及公开副露继续使用原有视图。已确认口径不增加 engine 状态、网络动作或全知位置 API。

表现层新增纯视图派生组件，类型只依赖 `client.api`：

```kotlin
// 以下为拟定职责签名，非已实现接口。
OpponentHandPresentation.build(snapshot): List<OpponentHandRow>
RiverHintPresentation.build(snapshot): RiverHintView
RiverHintSelection.reconcile(snapshot, selection): RiverHintSelection
```

`OpponentHandRow` 包含座位、总张数及展示槽位；槽位分 `Back` 和 `MarkedFace(tile)`，不携带未知牌身份。`RiverHintView` 包含牌山剩余可摸总数、按门风排列的四家手牌行和有效牌河定位。提示面板本人行只以 `OWN_HAND` 标记替换牌背，对手行只以相应座位的 `OPPONENT_HAND` 标记替换牌背；与主牌桌共用槽位生成规则。所有结果为只读值，快照替换时重建，不能积累上一局的位置猜测。

`GameScreen` 接入完整对手手牌行及新面板；`TileMarkPanel` 保留施术选择，移除文字追踪与独立识别牌列。透明绘制能力放入现有牌绘制流程共用，手牌、牌河、动画、副露、提示面板采用同一种样式参数；UI 页面继续只依赖 `client.api`。

观战只使用原有公开视图，不接收任何玩家的落汗效果。观战若复用牌背绘制组件，也不获得半透明私有牌面或玩家专属统计。暂不为观战增加提示功能。

## 实施顺序与验收

用户已授权按本设计进入实现。按现有分工由 Anti 实现，Codex 编写测试并独立检视，问题退回修正后复验。

1. 按已确认口径，Codex 建立牌山总数、四方牌背与透明牌面、布局数据和身份定位的行为测试。
2. Anti 实现完整对手牌行及共用半透明绘制，替换旧文字效果展示。
3. Anti 实现提示面板、四方手牌行和牌河定位，处理小视口及触控命中。
4. Codex 独立审查、退回问题并复验，通过后再按后续授权提交。

| 验收项 | 必须覆盖 |
|---|---|
| 暗手牌完整性 | 0、1、13、14 张及鸣牌后张数；标记牌取代牌背而非增加总数；单家最多 12 张标记可同时看到 |
| 透明视觉 | 只有本人有效标记采用半透明；普通牌背不透；赤五、立直横置和旋转牌面仍清楚；绘制状态不污染其他控件 |
| 信息范围 | 未标记暗牌无牌面和真实槽位；隐藏标记无归属；对手、观战和重连不混入他人落汗信息 |
| 牌山总数 | 普通摸牌、杠及补牌后与权威快照一致；不因重复事件或动画重复扣减；零张、未发牌、重连与新局正确 |
| 提示面板手牌 | 东南西北四行完整；本人行也只翻落汗牌；无标记时全为牌背；未知归属不分配到任何一家；无牌种余量或预测 |
| 方位 | 本人可坐四个座位；换庄、连庄后的东南西北正确；屏幕方位不混同门风 |
| 精确定位 | 四家牌河首尾与换行位置、同种不同副本、被鸣走、飞牌、到期、新局与快照恢复 |
| 图形交互 | 无旧位置文字和独立识别列；按钮开关、牌河网格滚动、实体定位、取消焦点、点击不穿透；倒计时不停 |
| 布局与实机 | 1280×720、960×540 真实 GL 截图；完整手牌、牌河、副露和提示面板不重叠；Android 构建与真机触控分别记录 |

文档阶段仅检查设计一致性和引用；不把已有 1000 项测试通过作为新版展示的验收。实施阶段运行相关新增测试、全量回归、桌面及 Android 构建和真实 GL 检查。
