# 疯狂动物麻将 · 正式 APP 主菜单方案

本轮交付正式 libGDX APP 的图层设计、交互时序、预期图和可加载素材。运行代码现已按本方案接入正式 APP；实施与验收记录见 [DELIVERY.md](DELIVERY.md)。浏览器 Demo 的方案不是本轮实现入口。

- [1280×720 布局与分层图](LAYOUT-1280.svg)：精确按钮位置与图层关系。
- [正式资源包](../../../assets/ui/main-menu/README.md) 与 [坐标/动画清单](../../../assets/ui/main-menu/manifest.json)。

## 1. 现有正式代码与范围

`presentation.menu.MainMenuView` 提供六个回调，`MenuScreen` 管理大厅状态、单机启动、弹窗和异步导航，`UiAssets` 由组合根创建并释放。此次视觉设计围绕已有六个入口：单机对局、联机对战、牌面皮肤、千术秘籍、游戏设置、退出游戏。单机依然调用 `onPlaySingle`，联机依然走 `onOpenLobby` 的连接流程，不能从浏览器原型复制假房间数据。

章鱼作为菜单吉祥物，不显示“已选角色”、角色加成、解锁或货币等尚未接入正式 APP 的信息。正式菜单可见标题改为“疯狂动物麻将”；跨平台窗口名与 Android 应用标签的统一更名作为后续运行代码落地项记录。

## 2. 图层设计与绘制顺序

libGDX 的顺序由绘制调用决定，下表的层号用于约束顺序，不是 CSS z-index。所有装饰都不参与点击。

| 层 | 内容与素材 | 绘制方式 | 输入 |
| --- | --- | --- | --- |
| L0 场景 | `club-background.png` | SpriteBatch 全屏 cover；宽屏边缘只扩展场景 | 无 |
| L1 阅读遮罩 | 左侧标题区与右侧菜单区的渐暗、边缘暗角 | ShapeRenderer/颜色渐变四边形，不全屏压黑 | 无 |
| L2 环境光 | 右侧菜单后柔和金光、左侧角色背光 | 低透明图元；静止或极缓慢变化 | 无 |
| L3 吉祥物 | `octopus-hero.png`，等比完整显示 | SpriteBatch，不能裁脸、扭曲或盖右侧按钮 | 无 |
| L4 标题 | “疯狂动物麻将”与“三大千术 · 牌桌心战” | 共享字体体系，专用较大字号增量字库，金色文字 | 无 |
| L5 六项菜单 | 朱红主底板/翡翠次底板、图标、动态中文 | NinePatch + TextureRegion + BitmapFont；从右依次入场 | 唯一主菜单命中区 |
| L6 状态 | 皮肤当前名称、单机初始化状态/连接失败原因 | 动态文字与提示条；成功/错误不只靠颜色 | 无穿透按钮 |
| L7 弹窗 | 秘籍/设置/连接等既有弹窗 | 父层当前状态控制，位于菜单上方 | 父层独占派发 |

绘制顺序为 L0→L7。SpriteBatch 和 ShapeRenderer 必须成段 begin/end，不可嵌套；绘制后恢复 batch/font 的颜色与缩放，避免污染大厅和弹窗。画面中不使用网页顶栏、Demo 标识或概念图里的错误小字。

## 3. 1280×720 布局

坐标原点为 libGDX 左下角。主要内容保持在 x=64..1192、y=58..688 的安全区内。

| 元素 | x | y | 宽 | 高 |
| --- | ---: | ---: | ---: | ---: |
| 标题 | 64 | 612 | 620 | 76 |
| 副标 | 72 | 574 | 600 | 26 |
| 章鱼 | 96 | 64 | 530 | 506 |
| 单机对局 | 752 | 480 | 440 | 80 |
| 联机对战 | 752 | 388 | 440 | 80 |
| 牌面皮肤 | 752 | 318 | 440 | 58 |
| 千术秘籍 | 752 | 248 | 440 | 58 |
| 游戏设置 | 752 | 178 | 440 | 58 |
| 退出游戏 | 752 | 108 | 440 | 58 |
| 状态提示 | 752 | 58 | 440 | 38 |

两个主入口使用朱红底板，四个次入口使用翡翠底板；金边、图标和高对比文字组成状态层。背景图局部纹理可见，菜单正文下有实色底板。图标为六格小图集，不能靠 emoji/系统字形替代。标题建议专用 64–68px 字库，按钮主文案 24px、次项 21px、辅助/状态 16–17px，沿用仓库 NotoSansSC 与既有许可证。

皮肤项显示“牌面皮肤”及当前皮肤中文名称，名称变化在原位置更新。单机和联机只展示产品文案，不将 TCP 或领域架构细节放在主入口上。

## 4. 右侧移入与点击同步

进入 MAIN 的每轮入场累计时间从 0 计时；六项都从自身最终位置右侧 96 单位移入。这里是“每项由右到左落位”，不能只对整个页面做一次淡入。

```text
p = clamp((elapsedMs - delayMs) / 420, 0, 1)
ease = 1 - (1 - p)^3
drawX = baseX + 96 * (1 - ease)
alpha = p
```

| 顺序 | 入口 | 延迟 | 落位时间 |
| --- | --- | ---: | ---: |
| 1 | 单机对局 | 120ms | 540ms |
| 2 | 联机对战 | 200ms | 620ms |
| 3 | 牌面皮肤 | 280ms | 700ms |
| 4 | 千术秘籍 | 360ms | 780ms |
| 5 | 游戏设置 | 440ms | 860ms |
| 6 | 退出游戏 | 520ms | 940ms |

每项绘制矩形和 hitRect 来自同一帧布局对象；未入场/未落位的项不接受点击和键盘激活，落位后独立启用，不让其他晚入场菜单阻塞已可用主入口。不能用最终矩形接收仍在移动的按钮点击。hover 只提亮描边/底板，不额外平移；pressed 只压暗底板，保持命中几何稳定。

首次 show 或从大厅/对局返回 MAIN 重播一次；应用从后台恢复不重播，普通状态文字刷新与皮肤切换不重播。关闭设置/秘籍等覆盖弹窗时恢复原菜单，不重复入场。后续实现需以明确的 enterMain/reentry 状态切换管理，不能仅靠原 `animTimer` 不断递增。

减少动态效果时直接把所有项设置到落位态，立即可点。正式 APP 当前没有该设置，设计中的 motionEnabled 是未来表现层配置，不冒称已存在或影响对局权威时钟。

## 5. 输入、忙碌、弹窗与跨平台

- 鼠标 hover、触控 press、键盘上下/Tab 聚焦、Enter/Space 确认均基于同一菜单项模型。Esc/Android 返回沿父层导航规则处理。普通背景与角色画面不吞主菜单输入。
- 单机初始化与连接等待由 `MenuScreen` 管理 requestGeneration、状态提示和重复提交门禁，子视图只上报意图。失败显示原因并恢复入口，不为视觉动效改变会话逻辑。
- MAIN 上弹出秘籍/设置时先画完整稳定菜单，再画遮罩与弹窗；关闭后恢复原焦点。现有 `MenuScreen` 不是这种底图绘制方式，属于之后实现的必要改造点。
- 设计采用 1280×720 交互坐标与等比内容视口，背景独立 cover。桌面 1280×720、960×540、Android 16:9 与 19.5:9 都要验证；超宽区域用场景填充，按钮留在安全内容区。
- 当前 `MenuScreen.resize()` 为空、输入通过 camera.unproject 转换；之后实现时需统一 viewport.apply/update/unproject，不能只改绘制缩放而漏掉点击坐标。Android 刘海/导航安全边距由平台适配传递，不让 presentation 引用 Android SDK。

## 6. 素材与资源生命周期

根 `assets/ui/main-menu` 已放入背景、透明章鱼、三张按钮底板/焦点层、六图标图集和机器可读 manifest。所有纹理边长 ≤2048，不依赖浏览器 Demo 路径。PNG 独立透明边已检查，按钮图元无文字。

未来新增的菜单资源所有者建议为 `presentation.menu.MainMenuAssets`，由 `UiAssets` 延迟创建、统一释放；View 和 Screen 借用，禁止每帧加载或重复 dispose。未进入 MAIN 的自动化/无头场景不能强制创建 GL 资源，缺失素材时应有可见的纯色降级并记录日志。

美术图片由内置 imagegen 生成；主菜单预期图提示词见 [PROMPTS.md](PROMPTS.md)。PNG 控件/图标为程序从零绘制，可通过仓库脚本重建。保守 RGBA8888 纹理占用约 12.2 MiB，无 mipmap；加载时间/帧率需在运行代码接入后测量，当前未宣称通过。

## 7. 后续代码落地与验收清单

后续主要改动点为 `MainMenuView.kt`（绘制/菜单态）、`MenuScreen.kt`（入场触发/输入/覆盖弹窗）、`UiAssets.kt`（共享资源）、新增的菜单布局/资源类；跨平台名称需同时考虑 DesktopLauncher 和 AndroidManifest。引擎、协议、服务端、业务幂等与七模块依赖保持现有边界。

验收需要真实桌面 GL 截图 0/240/540/940ms 的动画状态、六入口落位与焦点态；滑入途中点击不得误触；六回调/皮肤即时更新/连接失败与单机忙碌都要验证；窗口 resize 后点击与绘制一致；弹窗关闭不重播；返回 MAIN 应重播。之后运行相关 presentation 菜单用例、桌面构建与 Android 构建，并真实测 Android 点击/安全区。设计和素材阶段无需将这些运行验收写为已通过。

设计素材阶段已验证文件完整性、图像尺寸/透明通道、资源路径、菜单矩形无重叠、回调映射与现有源码一致。运行实施与复验记录见 [DELIVERY.md](DELIVERY.md)；未提交 Git。
