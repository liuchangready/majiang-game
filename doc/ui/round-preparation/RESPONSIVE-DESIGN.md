## 1. 本次设计决策

**环境填满窗口，交互内容保持16:9并居中等比缩放。** 宽屏多出来的左右区域展示麻将馆，4:3或16:10多出来的上下区域展示环境。不使用黑条，也不把头像拉成椭圆，不让准备栏单独贴物理窗口右沿而远离桌面。

此规则取代 `VISUAL-COMPOSITION.md` 旧版“扩展世界相机、面板锚定实际窗口右沿”的建议。所有牌桌、公开HUD、目标卡、底部按钮共用同一内容坐标。准备、抽屉、确认和发牌后采用相同内容区，切换不压窄桌面。

| 条件 | 处理 |
| --- | --- |
| 16:9 | 内容区填满安全窗口，布局与1280×720基准保持一致 |
| 21:9或更宽 | 以安全高度决定比例，内容左右居中，多余空间仅绘制环境 |
| 4:3、16:10 | 以安全宽度决定比例，内容上下居中，多余空间仅绘制环境 |
| 有系统安全边距 | 先扣除边距，再进行同一fit计算；装饰环境可延伸，按钮不可进入安全边距 |
| 小于960×540 | 尽力绘制，不越界、不产生无效投影；可读性不列常规支持，桌面后续接入建议设置窗口最小尺寸 |
| 竖屏 | 不在本次横屏游戏设计范围；不为竖屏强行挤压六卡和四席 |

## 2. 唯一坐标体系

设计画布：`1280×720`，左上角原点。窗口输入坐标与逻辑显示单位一致。安全边距为 `L/T/R/B`。

```text
availableW = windowW - L - R
availableH = windowH - T - B
scale = min(availableW / 1280, availableH / 720)
stageW = 1280 * scale
stageH = 720 * scale
stageX = L + (availableW - stageW) / 2
stageY = T + (availableH - stageH) / 2

screenRect = (stageX + x*scale, stageY + y*scale, w*scale, h*scale)
localX = (inputX - stageX) / scale
localY = (inputY - stageY) / scale
```

`scale<=0`或窗口宽高为0时停止绘制/命中计算，不做除法。libGDX实际绘制的Y只在最后一步转为 `windowH - screenBottom`。纹理图集仍用原PNG的左上角切片，不和屏幕Y转换混用。

内容外的环境区不响应牌桌按钮。绘制、点击、焦点框和动画使用同一矩阵；高DPI的帧缓冲比例只影响GL viewport和字体输出像素，不把输入坐标再乘一次DPI。

## 3. 图层和裁切

| 顺序 | 图层 | 坐标空间 | 输入/裁切 |
| --- | --- | --- | --- |
| Z0 | 无牌麻将馆环境 | 整个窗口 | cover居中，不接收输入 |
| Z10 | 翡翠锦纹桌面、朱红木沿 | 中央stage | 固定设计矩形，不依面板压缩 |
| Z20 | 罗盘、四席头像与名牌 | stage | 公开信息；头像不接收输入 |
| Z30 | 发牌后的手牌、牌背、牌河、副露 | stage | 正式接入时使用真实快照，准备态不画实体牌 |
| Z40 | 准备栏/目标抽屉/只读回执 | stage | 局部动画，超出stage的移入部分被裁切 |
| Z50 | 名称、费用、计时、焦点与选中标记 | stage | 必须和底板用同一变换 |
| Z100 | 退出/暂停等系统弹窗 | 安全窗口 | 覆盖牌桌输入，沿用正式模态优先级 |

抽屉右移进入时，环境和桌面不跟随；在宽屏也不能让待移入的按钮先露在环境侧边。示例为stage设置scissor，并在入场未结束时禁用该面板交互。保持减少动画时直接终态的能力。

## 5. 字体、纹理缩放和高DPI

| 用途 | 设计字号 | 960×540时约占窗口像素 |
| --- | ---: | ---: |
| 大标题 | 34 | 25.5 |
| 抽屉标题 | 28 | 21 |
| 主按钮 | 25 | 18.75 |
| 目标名/分数 | 21 | 15.75 |
| 正文 | 19 | 14.25 |
| 名称/辅助 | 17/16 | 12.75/12 |

字体根据`设计字号 × stageScale × framebufferRatio`生成原生FreeType字形，绘制时只抵消帧缓冲像素比例。不使用17px字库放大做标题，也不按宽高分别缩放。示例用白色细描边补足小字笔画、大标题轻度加粗和暗色阴影；描边随输出像素保持相近视觉粗细。

本次实际截图发现627px源头像缩到100px附近时仅Linear过滤有明显锯齿，因此独立绘制示例对美术纹理采用`MipMapLinearLinear + Linear`，图集留原有透明间隔。源PNG未改动。此条覆盖旧方案的“无mipmap”建议；正式接入时预计七张美术纹理从约42MiB增至约56MiB，需在移动端按预算选择预缩小图集或mipmap。字体仍用原生输出尺寸与Linear，不能靠mipmap弥补小字放大。

1.5×/2×高像素密度已通过FBO模拟绘制和点击映射检查；未将它写成Windows系统缩放、跨屏拖动或Android真机已验证。桌面最小窗口不等于Android触控标准，移动端还应独立保证最小触控目标约48dp及真实安全区。

## 6. 窗口改变时的交互规则

1. 窗口大小改变只重算view、stage、scissor和输入反变换。纹理不重载，合法字号命中字体缓存。
2. 选中牌型、看破、预计费用、当前roundId与权威截止时间属于页面状态，窗口改变不能重建它们。
3. 已按住按钮时发生窗口变化，取消该次按压；用户重新按下才可提交，避免按钮移到指针下产生误确认。
4. 抽屉正移入时，保持原动画进度和目标状态，在新stage继续绘制；不从起点再播放。已冻结35%进度绘制不同窗口的示例截图，移入部分被stage正确裁切，输入被关闭。
5. 最小化/零尺寸时停止无效投影，恢复后先更新view再处理新输入。示例已做0×0状态保持检查，OS级最小化/最大化仍是正式接入后的独立验收项。
6. 只读回执不因缩放恢复按钮或延长等待。正式接入时发牌仍由权威推进，绘制和动画不门控发牌。

连续缩放实测序列：`1280×720 → 1160×700 → 1024×768 → 960×540 → 1440×810 → 1600×600 → 1280×720`。每个尺寸均实际绘制、截图，并通过InputProcessor点击目标卡与看破，最后仅确认一次。

## 7. 位置验证方法

不能只检查设计常量是否等于自身，采用以下证据：

- 已知比例的独立golden：4:3的1024×576内容区必须位于y=96；1600×600必须水平留出266.67；2560×1080左右各320。
- GPU拾取：把实际点击区绘制为唯一颜色ID，从像素读回，与CPU输入逆变换的结果比对，包含按钮中心、四角内侧、环境区和动画禁用态。
- 美术实际边界：独立读取源PNG对应切片的Alpha边界，按目标矩形预测；再将桌面、罗盘、四头像单独GL绘制并读回Alpha边界，检查最大误差。已在标准、超宽、高像素密度三种画面验证。
- 文本实际尺寸：用正在绘制的原生字体做GlyphLayout测量，检查目标文本盒，不将文字宽度猜成字符数。
- 几何约束：检查内容区/安全区包含、交互区两两不重叠、四席HUD不挡按钮、罗盘不碰四席名牌。
- 保存无标注原图及对应边界图；不是把断言通过当作目视效果通过。已逐张查看代表尺寸和四种状态，用户可继续从检视页看全部原图。

详细运行数值以[本次验证报告](responsive-validation/REPORT.md)为准，原始像素数据与坐标记录均保留。
