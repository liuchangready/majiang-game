# 多分辨率绘制验证记录

## 实际结果

- 最终运行：**PASS**，26 组绘制场景，5936 项断言。
- GPU ID 缓冲与 CPU 输入反变换：1352 个位置比对通过。
- 从实际图像 Alpha 读回的 18 个边界：最大偏差 **0.589844 像素**（门限3像素）。
- 7 个连续窗口状态（6次尺寸变更），每步真实调用 GLFW 窗口尺寸接口，并通过 InputProcessor 点击目标/看破；已选国士无双、看破、40点草稿保留。
- 缩放发生时取消按住的提交，序列结束确认只触发一次。
- 标题、按钮、卡名、名牌使用 GlyphLayout 实测，无超出其指定文本盒的记录。
- 检查了图层在内容区内、交互区之间不重叠、头像名牌不遮挡按钮、罗盘不碰四席HUD。

这是设计绘制代码的验证，示例牌/姓名/分数为固定布局样例；未改正式 APP 入口、未替换正式请求或权威逻辑。

## 实测范围与缺口

- 960×540、1280×720、1920×1080、1024×768、1280×800、1600×600、2560×1080为真实 GLFW 窗口帧缓冲。
- 请求原生3440×1440时，测试机将宽限制到3124；已保留[首次限制记录](attempt-01-window-limit.txt)。最终3440×1440使用真实 GL FBO，不能称原生3440窗口通过。
- 1.5×和2×是更高像素密度的FBO模拟；未切换Windows系统缩放或进行跨显示器拖动。
- 0×0仅为合成生命周期/有限数值检查，未宣称实际OS最小化、最大化已实测。
- 800×450只验证不越界和输入一致；正常可读性下限为960×540。
- Android真机安全区和48dp触控目标不在本次桌面绘制验证通过项内。
