# D2：TableHost 实际接线与生命周期返修

仅修改host/**、access/local/**、access/BoundMahjongGameAccess.kt、access/LocalSessionAccess.kt（确认不再使用可删除）。不要改Coordinator、Round/Session/GameState等领域；D3会独占领域账本整合。E只生成移动脚本，不会在你工作期间移动源码。Codex测试TableHostAcceptanceTest已在core/src/test/.../v3。

检视发现重大接线问题，务必修复并自查全部实际逻辑，不以注释代替：

1. startSession判断SessionLifecycle.ROUND_ACTIVE就返回APPLIED。但Coordinator构造时已经ROUND_ACTIVE且Round仍STACKING未发牌，因此start永远不发牌！依据实际Round未发牌状态调用coordinator.start，重复已发牌start才幂等。
2. buildClientDecision用ConnectionControl初始epoch0覆盖Coordinator.initializeMatch产生的epoch1，再原样传coordinator.submitChoice导致全部合法操作被拒。外部只使用Coordinator真实controlEpoch作为唯一令牌；AI任务也绑定同一代次。ConnectionControl只管连接/角色，不能制造平行公开代次。
3. 编译核对 `round.responseWindow` 自定义getter不能smartcast，先保存局部window。E正在写Gradle暂时不能运行构建，Codex负责。
4. rhythmIntervalMillis默认0且完全未使用；默认150ms且对AI/自动摸切真正生效，每tick最多一步。长帧不追赶。动画门控允许本地等待，超时计时不能因动画忙被无限延期；明确处理到期的事实优先于自动节奏。
5. 禁止AI/自动动作先complete计时再提交，提交拒绝不能消耗计时。execute成功后再complete/expire。过期玩家命令应触发合法超时默认动作或确保下一tick可以执行，不能关闭时钟但不执行动作导致永远卡住。
6. syncDecisionsAndClocks对SESSION-dealer-choice不能open roundId="session"到当前round DecisionClock，B2现已严查roundId；局间用独立时限或暂不启动单局计时。真人ready和庄家终了不扣局内储备。
7. Round终局后Session.activeRound已为null，当前sync里只看activeRound.result导致丢失历史结算。按已结束的roundId缓存该次完整公开结算来源（可用coordinator.lastEndedRoundSnapshot与收到events，或Coordinator已保存结果接口），保证activeGame旧绑定queryResult不会读到新局且不是永远emptyList。
8. BoundMahjongGameAccess.snapshot/decision当前无round检查返回新局；旧绑定必须返回旧只读结果或明确已结束，不能伪装当前round。
9. LocalSession.close当前不会移除自己的subscribe，也没有实际生命周期管理。跟踪每endpoint订阅，close移除自己的监听器；不能影响其他仍连接端点，最后连接断开按政策托管。host.close后connect/query/submit都正确拒绝。监听器重入查询可以给一致快照，重入变更应明确拒绝，不抛出被吞导致初始化缺失。
10. repeated disconnect/requestControl不得无变化也coordinator.setSeatController递增epoch；reclaim只允许仍拥有绑定身份且connected，不允许已失效连接收回。新epoch使旧AI结果失效但不重置当前决策截止/储备。
11. onStateChanged不能给每席位私密无可见变化也increment cursor；比较可见投影/decision/control/有意义clock变化（不要把serverNow自然流逝视为更新），无变化不发。initial subscribe基线合法，resume同seat另一个端点不应永久因epoch改变停滞，采取明确单连接替换或给现存端点同步新基线。
12. 对手不可见原始事件仍用既有filter，result事件按受权筛选；每个listener独立副本。
13. allReady之前WAITING_DEALER_CHOICE必须由庄家明确决定继续，其他席位ready不能绕过庄家。网络重新提交ready只对当前局间生效，不能连开两局。
14. bounded AI队列RejectedExecutionException必须捕获，不能中断已经提交的状态发布；卡住AI靠时钟兜底。dispatchedAiTasks按过时局/决策清理，防整场无限增长。
15. 配置防御复制，不让外部修改controllers/startingScores/winds/tieBreakSeats导致运行中配置变更。coordinator/cheatLedger等宿主内部字段改private（除必要可信宿主接口），不为测试公开权威对象。
16. D3新增GameState.cheatPoints(IntArray)、RoundResult和MatchSession作弊点数账本。你在host创建初始GameState时从config.cheatEconomy.initialPoints写入cheatPoints；snapshot从活动局/Session对应账本读余额，删除独立host CheatLedger平行可写账本。D3的ledger原子提交接口由独立可信奖励/技能服务使用，不向一般Client提供随意加点接口。

现有独立规则测试不能删除。交付delivery-D2.md，具体说明每项修复与尚存缺口。
