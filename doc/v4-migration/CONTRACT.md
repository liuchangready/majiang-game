# V4 最终架构与迁移契约

2026-10-06 09:10更新开发分工。用户授权：按检视顺序继续 V4 迁移，恢复由 Anti 开发，Codex 监督与测试验收；最后删除无用 V3，不保留旧入口兼容性。本契约统一 V4 总方案、接口细化与旧任务简报的冲突；当前任务范围由新版 PLAN 和 R 系列任务定义。历史 Anti 与 GLM 交付保留作为证据。

## 最终依赖与职责

- engine：纯 Kotlin/JVM 领域、规则、算分、单局与整场状态，以及不感知连接的 TableAuthority。允许 Kotlin 标准库；禁止 client、server、protocol、libGDX、Gson 与 socket。保留可复用的规则及领域算法，不重写已验证的算法。
- protocol：独立线协议 DTO、接口、错误码、编解码、UDP 数据报与可靠性组件；不依赖 engine/client/server/presentation。现有 server.api 包可在迁移中保留名称，模块身份以源集归属为准。
- server：依赖 engine+protocol，拥有领域到协议的映射、房间与连接代次、玩家/观战权限、每桌权威执行队列、AI/超时调度、订阅历史及本地/UDP 两种绑定。
- client：只依赖 protocol（及通用运行库），拥有 client.api 视图/输入/回执模型、协议到视图映射、会话缓存、有序同步、pending 状态、自动重连、可注入线程派发。不可 import engine 或 server 实现。
- presentation.menu/game/common：只使用 client.api 与展示基础库，不使用领域规则、protocol 或 server 实现。不自行判定权威动作合法性；预览/待牌等展示数据通过 client 契约取得。
- 应用组合根和平台启动器：可以装配 client、server，负责资源和画面切换；禁止作为绕过 server 的第二个 engine 入口。最终没有 engine 直连启动重载。

protocol 与 engine 的类型必须分离；client 视图与协议类型也必须分离。ActionChoice 在历史 T5 中的透传例外最终撤销，配置、码牌方案、回执、动作选择全部使用 client 自有输入/输出类型。禁止 Any/Object/Map 原样夹带领域对象。

## 运行与同步

远端采用 UDP，单机采用进程内调用；旧 TCP 最后删除。两种绑定使用相同会话/业务语义，区别只在传输。允许单机通过装配策略预填 AI。

最终接口必须真实异步：调用方只入队，不能等待权威锁；每桌按确定的调度规则提交玩家动作、超时、AI 结果和控制操作，至多提交一个成功动作。超时仍按权威 deadline 校验，不能通过玩家请求饥饿策略无限延迟。事件通知和网络发送移出权威状态修改临界区。AI 推理可在队列外执行，返回时验证 roundId、decisionId、controlEpoch。

快照/推送游标按座位（观战为独立投影）单调连续；绑定 sessionId+syncEpoch，切换代次时重置旧序列。PUSH 是完整快照加可见事件，不引入第二套增量状态模型。推送重传窗口为 256 条；窗口外明确标记全量替换，直接建立新基线。首次订阅、快照请求、早期推送和重连不能造成乱序回滚。

UDP 版本 4，22 字节头，单报文上限 1200，分片阈值 1090，心跳 3 秒、入站超时 10 秒。请求幂等覆盖大厅绑定、动作、离房和重连；完成回执及在途状态有界。重组按来源/连接/消息隔离。可靠重试不能被防重放机制永久阻断。明确全量标记、分片元数据检查可以作为 V4 尚未发布时的协议完善，不要求兼容旧 V4 试验包。

client 自动重连保留房间身份、最后基线和 UI 状态；关闭/主动离房/顶号/房间关闭禁止自动抢占重连。暂时断网使用可注入调度器指数退避，绑定成功后重新订阅并对账；收回控制权必须显式请求，不回滚托管期间动作、不重置用时。

## 控制与大厅

最终用 claimControl()/releaseControl() 明确表示收回/交出控制权。R1 仍保留 requestControl(Boolean) 时按详细接口 true=收回、false=交出，在绑定边界翻译旧 engine 的相反语义；不得更改旧 engine 内部语义破坏原规则回归。

房主主动 leave 返回成功并回到未绑定大厅；其他成员收到 ROOM_CLOSED。普通成员 leave 与意外掉线不同：显式退出撤销原座位令牌/成员身份，开赛后该座由 AI 继续，开赛前释放座位。丢失离房回执仍可幂等重放。停服发送 SERVER_SHUTDOWN 后再释放 socket。无主机迁移。

大厅补齐 roomInfo、ready、配置更新、开赛和观战只读接入，房间状态显式统一。单机自动准备/AI 补座通过策略实现；联机 ready 校验在 server。历史与最终结果可由快照包含的公开记录及查询接口提供，不重复建立不同账本。

不扩大到公网账户、自动匹配、三人规则、持久化恢复、主机迁移或加密上线。保留已有四人日麻、结算、计时、码牌与出千行为，不把架构迁移变成规则重写。

## 验收与清理

指定开发者 Anti 可修改当前任务授权生产代码并补模块测试；Codex 独立运行构建、测试与真实联调，维护审查测试。禁止通过删除/跳过有效规则测试使迁移变绿。确实仅验证旧接口形状的测试可在最后阶段替换，逐项列明替代覆盖。

迁移不要求旧构造器、SessionAccess 启动入口、旧网络协议继续兼容。为阶段编译暂时共存的文件必须记入清理清单，最终删除而非转发壳/typealias。删除范围以引用审计和功能替代为依据，不能按 V3 字样批量删除可复用算法或历史设计记录。
