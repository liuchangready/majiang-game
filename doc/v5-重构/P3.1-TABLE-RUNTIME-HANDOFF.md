## 2. Actor 语义

### 2.1 串行化与调度

- 一个 actor 一个 FIFO mailbox；所有 player 命令、tick、AI 完成、打开决策、恢复、失租、快照、关闭都进入同一队列。
- 消费由共享线程池上的**短 drain task** 完成：`EnsurePump()` 通过 `Interlocked` 保证同一 actor 只有一个 drain task；队列排空后任务退出，不创建每桌常驻线程，也不使用无限 `Task.Run` 循环。
- 同一 actor 不持有锁跨越 `await`。提交端口等待期间，后续同桌消息只入队、不执行；测试断言 `MaxConcurrentCommits == 1` 且后一消息在提交完成前不完成。
- mailbox 总线程序列。业务消息（player 命令、AI 完成）使用 `MailboxCapacity`；权威控制消息（tick、打开决策、恢复、失租、快照、关闭）使用额外 `ControlReserve`，因此业务队列满时不会丢弃 deadline/租约语义。总上限为 `MailboxCapacity + ControlReserve`，关闭标记作为最后一个控制消息额外占一个槽位（仍然有界）。
- 业务队列满返回 `MAILBOX_FULL`，关闭后返回 `ACTOR_CLOSED`，两者都 `Admitted=false`，不提交、不推进版本。
- 关闭时先在 mailbox 锁内停止接受并把 close 标记排在所有已准入消息之后；已准入消息仍会完成，关闭标记之后的新消息立即拒绝。

### 2.2 版本与事件

- `state_version` 是命令版本：每个“已接受且改变状态”的命令在提交成功后恰好 `+1`。
- 一个命令的 N 个 Domain 事件共享本命令的新 `command_version`，`event_ordinal=0..N-1`；`event_seq` 独立全局递增。
- Domain 接受但事件为空时返回 `STATE_EVENT_MISSING`，不提交、不安装、不发布。
- 拒绝/提交失败不推进版本、不写事件、不发布、不返回成功回执。
- 当前 P3.1 接受**已授权的 Domain `RoundCommand`**；`ProtocolCommand`/canonical payload 到 Domain 的线路映射不在 P3.1，由 P3.3/TableService 接入，避免 actor 内解析 protobuf/canonical payload。
- 当前 P3.1 仅支持 Domain 已能执行的 player 命令；tick/AI 的 `LegalActionOption` 只映射 `Pass` 与 `Discard`。`Tsumo/Ron/Chi/Pon/Kan/Riichi/Cheat` 需要结算/候选/控制层，返回 `UNSUPPORTED_ACTION`，不伪造结算。

### 2.3 提交后安装与发布

顺序固定：

1. Domain `Prepare`/`Execute` 生成候选（不修改 actor 权威状态）。
2. 构造 `TableCommitRequest`，含 `roomId`、`ownerEpoch`、`expectedStateVersion`、`commandVersion`、`lastEventSeq`、`stateFingerprint`、事件、最小回执。
3. `await ITableCommitPort.CommitAsync(..., CancellationToken.None)`。
4. 只有 `Committed` 才：安装 Domain 候选、推进 `state_version`/`event_seq`、完成匹配决策、更新最近事件窗口、构造 `TableSnapshot`、调用 `ITablePublicationSink.Publish`、返回 `TableOperationResult.Accepted`。
5. `Failed/StaleOwner/StaleState/Cancelled/异常` 均不安装、不发布；返回 `Failed` 及稳定原因码。

`ITablePublicationSink` 的异常被记录到 `TableActor.PublicationFault`，不回滚已提交状态（提交是权威事实），也不会把成功伪装成失败。

### 2.4 Deadline、AI 与控制代次

- tick 读取注入的 `ITableClock.MonotonicMillis`，将当前 `PendingDecision` 与同 tick AI 提交交给 Domain `DeadlineArbiter.ProcessTick`。
- `DeadlineArbiter` 保证 timeout 条目总是先于同 tick AI 条目；`now >= deadline` 时 timeout 先消耗决策，AI 返回 `DeadlineExpired`。
- AI 推理不在 actor 内执行；`CompleteAiAsync` 只接收已完成的 `AiDecision`，在 mailbox 内重新校验：
  - `roundId` 与当前 round 一致（`StaleRound`）；
  - 当前 seat 的 `DecisionKey` 一致（`StaleDecision`）；
  - `controlEpoch` 与 `ControlRegistry` 当前值一致（`StaleEpoch`）；
  - 决策未截止（`DeadlineExpired`）；
  - 所选动作仍是当前候选（`IllegalAction`）。
- 被拒绝的 AI 结果不推进版本、不发布、不消耗决策；测试随后用合法 AI 结果证明决策仍可被接受。
- player 命令若绑定当前决策，先校验 decisionId 与 deadline；在/超 deadline 返回 `DEADLINE_EXPIRED`，由后续 tick 执行权威 timeout。未绑定决策的 command 不做此检查。

### 2.5 恢复与失租

- `BeginRecoveryAsync` 将生命周期置为 `Recovering`，清空待决决策与时钟；随后命令/tick/AI 返回 `RECOVERING`，不推进版本。
- `CompleteRecoveryAsync(TableRecoveryBaseline)` 只接受 `Recovering` 状态，要求 `ownerEpoch` 不回退、`stateVersion`/`eventSeq` 不回退；安装基线后发布 `Recovered` 并恢复 `Serving`。P3.1 不读取 checkpoint、不校验 136/账本/哈希，这些属于 P3.4。
- `ReportLeaseLostAsync(ownerEpoch)` 通过控制保留进入 mailbox；旧 epoch 的失租报告返回 `STALE_OWNER_EPOCH`，不污染当前租约。匹配当前 epoch 后进入 `LeaseLost`，此后所有状态变更返回 `LEASE_LOST`，但已准入消息仍会完成（拒绝结果，不丢弃完成源）。
- 失租/恢复消息在已准入提交之后串行执行；测试验证了“提交中不并行、提交完成后再失租/恢复”的顺序。

## 3. 最小端口与后续归属

### 3.1 P3.2（投影与快照恢复）交接

P3.1 只提供：

- `TableSnapshot`：权威侧摘要（`state_version`、`lastEventSeq`、round/phase/currentSeat/scores、`stateFingerprint`、最近事件窗口、生命周期）。**不是**线路快照，不包含暗牌、牌山顺序、种子、袖牌或私有出千明细。
- `TablePublication`：只在提交成功（或已持久化恢复/失租控制事件）后发布；`Applied` 带最小 `TableCommandReceipt` 与事件。
- `ITablePublicationSink.Publish`：在 actor 单消费者线程同步调用，P3.2 应把构建好的按座位/公开投影入队，而不是在这里做重计算或阻塞 I/O。

P3.2 必须：

1. 从 Domain 状态构造 `StreamId -> 白名单视图`，不得“先序列化完整状态再删字段”；
2. 保持“提交成功后才发布”的顺序，但把发布内容替换为每流基线和事件，不以 `TableSnapshot` 直接上线；
3. 用 `TableEventRecord.CommandVersion/Ordinal/Seq` 建立恢复/缺口检测；完整流游标、早期缓冲和全量基线策略由 P3.2 定义；
4. 处理恢复基线：`Recovered` 发布后重建所有流基线，旧 binding/epoch 拒绝；P3.1 只负责安装和发布触发点；
5. 增加逐座位可见性、暗牌/种子扫描、旧 binding/epoch 拒绝测试。P3.1 的 17 项测试不覆盖这些。

### 3.2 P3.3（计时、托管与控制竞态）交接

P3.1 提供：

- `ITableClock`：只要求 `MonotonicMillis` 与 `UtcNowMs`；deadline 只使用单调时间。
- `OpenDecisionAsync(PendingDecision)`：P3.1 的最小决策 seam；不做断线宽限、AI 接管/收回、grace 配置。
- `TickAsync(TableTickRequest)`、`CompleteAiAsync(AiDecision)`：统一走 Domain `DeadlineArbiter`。
- 内部 `DecisionClock`/`ControlRegistry` 由构造函数初始化；P3.1 没有运行时 reclaim/takeover 消息。

P3.3 必须：

1. 用统一时钟/租约适配器替换 P3.1 的最小 `ITableClock` 注入，并把断线宽限与规则 deadline 分离；
2. 增加控制权变更（接管、显式收回、epoch 自增）的 actor 消息，并在同队列内排序；不得在 actor 外改 `ControlRegistry`；
3. 把 tick/AI/玩家命令/控制变更的竞态测试扩展到“同一 deadline 上玩家/AI/tick 三方竞争”；
4. 决定 player 命令在 deadline 到达时的完整处理（P3.1 当前直接拒绝，timeout 由后续 tick 执行）；
5. 为结算类动作（Tsumo/Ron/ExhaustiveDraw 等）接入 Scoring/结算适配器；P3.1 的 `MapAction` 只支持 Pass/Discard，不伪造支付。

### 3.3 P3.4（回执、租约、检查点）交接

P3.1 只定义：

- `ITableCommitPort.CommitAsync(TableCommitRequest, CancellationToken)`；
- `TableCommitRequest`：期望版本、命令版本、lastEventSeq、ownerEpoch、stateFingerprint、非空事件、最小成功回执；
- `TableCommitResult`：`Committed/Failed/StaleOwner/StaleState/Cancelled`；
- 内存 fake 仅在 `Mahjong.TableRuntime.Tests` 中，用于验证事件/版本顺序，不是生产实现。

P3.1 **没有**：

- 幂等键 `(accountId, scopeId, requestId)`、payload digest、同键同载荷重放/异载荷冲突；
- REJECTED 回执持久化（P3.1 拒绝直接返回，不调用 commit port）；
- `ownerEpoch + stateVersion` 双栅栏的真实事务、租约 TTL/续租、checkpoint、`ISettlementOutbox`；
- 冷恢复重放、136/账本/哈希校验、`PAUSED_STORAGE`；
- PostgreSQL 或任何文件持久化。

P3.4 必须保留 P3.1 的公开不变式：

1. 接受且改变状态的命令必须至少一个事件；拒绝/失败零版本；
2. 同命令多事件共享 `command_version` 且 ordinal 连续；
3. commit 成功后才安装/发布/返回成功回执；
4. 已准入命令不因关闭/失租被静默丢弃；关闭/失租仍要完成调用方的结果；
5. 提交失败后 actor 不发布；若 P3.4 选择进入 `PAUSED_STORAGE`，必须由显式恢复路径恢复，不能用重试掩盖状态漂移。

真实 PostgreSQL 属于 P5.2。
