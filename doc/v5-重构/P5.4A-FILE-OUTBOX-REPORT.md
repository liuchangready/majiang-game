### 1.2 文件格式与持久语义

`FileOutboxStore` 使用单文件版本化快照，默认 `outbox.dat`：

- 头部：8 字节魔数 `MJOUTBX1`、`u32` formatVersion=1、`u32` flags=0、`u32` bodyLength、`u32` reserved=0、`SHA-256(body)`。
- 主体：未决条目 + 已解析键的 tombstone。条目保存：
  - `(accountId, scopeId, requestId)`；
  - 命令 kind、payload schema version、`expectedStateVersion`；
  - `roundId`、`decisionId`、`controlEpoch`、`ownerEpoch`；
  - 原业务字节（canonical payload）与 32 字节 digest；
  - `sessionId`、`roomId`；
  - 完整 `RequestScope`：scope id、account、role、room、issuedAtMs、expiresAtMs。
- 解析记录保存 disposition、receipt status、reason、evaluated/command version、event seq、committedAt、payload SHA-256、是否来自 receipt lookup。
- 写入顺序：临时文件 → `Flush(true)` → `File.Replace` 原子替换。`SaveAsync` 只有在该顺序完成后才返回；`TableSession` 保持“先持久化、后发送”。
- 锁：进程内按 store 路径的 `SemaphoreSlim` + 跨进程 `.lock` 文件（`FileShare.None`，有界等待）。
- 取消：提交替换前检查取消；已写临时文件在 `finally` 中删除，旧快照保持不变。替换完成后不再因取消回滚（调用方最多看到未发送的已持久记录，安全）。
- 半写/临时文件：启动/加载时清理 `outbox.dat.tmp-*`。没有 committed 文件而只有临时文件时返回空库，因为该次 `SaveAsync` 从未成功返回，不能作为已保存记录；**已存在的 committed 文件损坏则抛异常，绝不当空库**。
- 损坏检测：魔数、format version、header flags、body length、reserved、SHA-256、计数上限、字符串长度/UTF-8、payload 上限、digest 重算、键/scope/room 一致性、重复键、已解析与未决同键、尾部多余字节等逐项校验。
- 有界：默认最多 256 条未决、4096 条 tombstone、单 payload 1 MiB、单文件 32 MiB、锁等待 10 秒；超限抛 `OutboxStoreFullException`，不静默淘汰已有记录。
- 幂等/冲突：同键同字节且同身份/版本元数据 → 幂等成功；同键不同字节或不同元数据 → `InvalidOperationException`；已解析键再次 `SaveAsync` → `already resolved`。
- 解析持久化：`ResolveAsync` 在同一原子快照中删除未决条目并写入 tombstone；重启后 `LoadUnresolvedAsync` 不会复活该请求，重复同解析幂等，不同解析被拒绝。

### 1.3 token / 票据与业务载荷边界

- `OutboxEntry` 不包含 `TableSessionOpenRequest.Ticket`；`FileOutboxStore` 没有 ticket 参数，也不会接收、序列化或记录传输票据。
- 为防止把凭据写进明文文件，store 对 `ResumeSession` / `ResumeSpectator` 中带 `ResumeToken` 字段的命令**显式拒绝**（`NotSupportedException`），不静默截断、替换或重建字节。此类 token-bearing 恢复命令需要平台安全存储适配器；本任务未实现该适配器，列为边界缺口。
- 非 token 命令按 P5.4a 要求保存原业务字节。业务载荷仍可能是敏感数据；本实现**不加密**，也不主动设置目录 ACL/Unix mode。调用方必须把目录放在 app-private 数据目录，并依赖平台沙箱/文件保护/密钥存储。Windows 测试目录使用临时目录的默认继承 ACL；未做 ACL 加固验证。

### 1.4 平台与宿主文件系统边界

已实际验证：

- Windows 10 19045，x64，NTFS 临时目录。
- `D:\Unity\dotnet\dotnet.exe` SDK 8.0.426，Debug 与 Release。
- 子进程终止使用 .NET `Process.Kill(entireProcessTree: true)`（Windows `TerminateProcess` 语义），覆盖保存前、提交中、提交后、解析前、解析后。
- 同一 snapshot 的临时文件 + `File.Replace` + `Flush(true)`；跨进程 `.lock` 文件在 Windows 上通过 `FileShare.None` 实测 6 个 worker 并发写。

未验证/未覆盖：

- 真实断电、磁盘控制器/文件系统缓存丢失、硬件坏道；`Flush(true)` 是宿主文件 API 层面的 flush，不等于断电测试。
- 目录项独立 fsync（本实现只 flush 文件内容，未做平台目录 fsync）。
- Windows ACL 最小权限、Unix/macOS 权限位、Android/iOS app sandbox 与 fsync、IL2CPP/Mono 运行时。
- 不支持原子 replace 的文件系统；本实现不静默降级为“删除再改名”。
- 真实 WSS、PostgreSQL、票据签发/校验、端到端远端对账（P5.4b/G3）。

## 3. 兼容性与未决边界

1. `FileOutboxStore` 是新增 `IOutboxStore` 实现，既有 `InMemoryOutboxStore`、`TableSession`、`OutboxEntry`、`OutboxResolution` 的公开签名和语义未改。
2. 没有改 `Mahjong.sln`；worker 工程不在 solution 中，仅由测试工程的项目引用构建并复制到测试输出。
3. 没有改 Wire schema 或任何 V4 文件；Client 仍只依赖 Contracts/Wire/BCL。
4. 解析 tombstone 按配置上限保留，不做 TTL/压缩；达到上限会显式失败，要求上层制定保留/清理策略。清理接口不在既有 `IOutboxStore` 合同中，本任务未擅自扩展。
5. 文件存储是明文、单机文件语义。若产品要求“token/票据绝不落盘”覆盖 resume token，必须接入平台安全存储或加密存储适配器；当前实现选择显式拒绝而不是静默剥离字节。
6. 本报告中的“进程重启恢复”只指同一宿主上进程被强杀后重新打开同一文件；不指同一内存对象跨 session，也不指断电/设备重启/远端服务恢复。
