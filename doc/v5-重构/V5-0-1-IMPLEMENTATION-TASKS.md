# V5-0 / V5-1 详细开发任务与交接单

日期：2026-10-23
状态：执行任务书；任务完成与验收以实际产物和复核记录为准。
基线：`v5` 分支，从 `a8e2f06` 切出。V4 仍是生产基线。

本任务书细化 [模块迁移方案](DEEPSEEK-V5-MODULE-MIGRATION-PLAN.md) §4.3、§5 与 [V5 架构草案](V5-ARCHITECTURE-DESIGN.md) §13。方案中的工程估算和目标值不是完成记录。V4 的 1,275 项历史运行数、1,826 个静态测试方法、T4 实测缺口均不可写作 V5 验收结果。

## 共同执行规则

1. 开发只在 `v5` 分支进行；保持 V4 七模块生产代码、既有验收文档和他人未提交 Unity 环境改动不变。每个任务交付文件清单、命令、退出码、测试结果及未覆盖项。不要把未运行的测试写成通过。
2. 先完成 V5-0 门槛，再进入 V5-1 规则实现。发现 V4 文档与代码不一致时，以实测源码行为建证据，记录待裁决项，不自行改变规则。涉及用户产品选择的项目列为待决，不阻塞与选择无关的基线工作。
3. 共享 C# 库使用 `netstandard2.1`、C# 9；`Domain` 只依赖 BCL，且不读取系统时间、不创建随机数或 ID、不依赖 Unity、Contracts、网络、数据库。线上隐藏状态只能在权威端存在，客户端模型只接收授权投影。
4. 每个任务独立提交可复核的最小变更。新增代码须有针对性测试；阶段门槛由 Codex 独立复核，不由实现者自行宣布通过。环境无法运行的测试须列出阻塞条件、已做的替代检查和补验命令。
5. 现有工作树的 `UNITY-ENVIRONMENT.md`、Unity Resources 删除及 Burst 设置文件为未提交改动；除非任务明确列入范围，不能还原、覆盖或顺带提交。

## V5-0：契约盘点与黄金样本

### P0.1 迁移追踪矩阵与黄金样本目录

**输入**：迁移方案 §1.3 的 266 个生产文件清单；V4 `engine/protocol/server/client` 源码和测试；V4 TCP 验收记录。
**产物**：`V5-0-TRACEABILITY.md`、`V5-0-GOLDEN-MANIFEST.md`；如生成可机器读取样本，存于 `tests/v5-golden/`，每个样本注明生成器版本、V4 提交、种子或随机结果、命令、预期事件、完整状态摘要、可见投影摘要与来源测试。
**实施**：逐项将现有有效规则、状态机边界、三绝技、码牌、经济、计时、控制代次、回执、投影、协议错误映射到 V5 目标模块与 P1/P2/P3 任务；区分“直接行为黄金样本”“需新增 V4 回放提取”“只属 V5 新能力”。样本至少覆盖 136 张位置转移、34 类牌与赤五、常见及边界和牌算分、连庄/终局/流局、CHANKAN_WINDOW、三绝技成功/拒绝/回退、AI 托管与真人收回、超时裁决、多事件命令与无事件拒绝。建立字段级来源和样本可复现命令，严禁手填预期哈希伪装自动提取。
**验收**：矩阵每行有源码/测试证据、V5 归属、状态；无“待定”而缺责任任务。清单每例有唯一 ID 和预期结果来源；未能导出的例子明确标为 `pending`，不计入对齐率。静态文件数与测试数仅标审计口径。

## V5-1：共享核心与桌运行时

### P1.1 Domain 基础、牌实体与守恒

**依赖**：G0。**位置**：`dotnet/src/Mahjong.Domain/` 与独立测试工程。
固定 `TileId=0..135`、`typeIndex=id>>2`、`copy=id&3`、赤五 copy=3；使用 136 槽位置表表达牌山、死山、手牌、河、副露、袖牌等互斥位置，复制与非法双占必须失败。提供只读状态/不可变转移、显式随机抽取记录、稳定的 `stateHash` 字段编码及守恒审计。覆盖开局、摸牌、打牌、鸣牌、杠、出千后的守恒与错误注入。**退出**：黄金样本全部一致，非法状态被拒绝，构建无 Unity/Contracts/网络/DB 引用。

### P1.2 和牌判断、役种与整数算分

**依赖**：P1.1；可与 P1.3 并行。**位置**：`Mahjong.Domain` 规则包。
按 P0.2 冻结清单移植役种、符、宝牌/赤宝、支付、点棒和结算。权威计算只使用整数，base/支付用 `long`，明确上溢与舍入。先移植独立规则用例，再跑 V4→C# 差分样本；随机 10,000 手牌/局面的目标需记录生成分布与实际运行量。**退出**：所有已导出算分黄金样本一致；未覆盖役种逐项列出，不以测试数量替代规则覆盖。

### P1.3 单局、整场、计时与控制代次

**依赖**：P1.1；可与 P1.2 并行。
实现 Round/Match 生命周期、终态不可复活、新局全新 `roundId`、CHANKAN_WINDOW、连庄/本场/立直棒、deadline 与 AI 托管/显式收回。UTC 持久时间与单调运行时间分开，ID、随机结果、时间由外部注入；旧 `controlEpoch` 决策不可生效。**退出**：V4 回放在相同记录输入下得到相同事件与状态摘要；超时优先于同 tick 的 AI 结果。

### P2.1 Contracts/Wire 与版本化 schema

**依赖**：G0；可与 P1.1–P1.3 并行。**位置**：`Mahjong.Contracts` 与独立 `Mahjong.Contracts.Wire`。
冻结 `.proto`、字段号/reserved/oneof、稳定错误码和兼容矩阵，生成代码纳入可重复构建；`Domain` 不依赖 Wire。涵盖 HELLO/WELCOME、COMMAND/RECEIPT、玩家/公共快照、SYNC、RECEIPT_QUERY、HEARTBEAT、ERROR/CLOSE。客户端重复请求保持原始业务字节；不把 Protobuf 重新序列化字节当规范摘要。**退出**：major 拒绝、minor 可选字段、未知字段/事件、超限消息与生成 diff 测试通过。

### P2.2 AOT 最小加载与平台边界

**依赖**：P2.1。
在可用环境中验证 .NET 与 Unity Editor 加载生成代码；若具备工具链，完成最小 Windows/Android IL2CPP 序列化与反序列化构建。记录裁剪、反射、TLS/WSS 适配风险与实际命令。若缺 MSVC/SDK/NDK/iOS 设备，标阻塞并提供补验脚本，不宣称通过。**退出**：可用平台有原始构建日志，缺口有具体资源清单。

### P1.4 三绝技、出千账本与私有状态

**依赖**：P1.1–P1.3；可与 P1.5/P1.6 并行。
移植落汗、袖里藏花、偷梁换柱的资格、费用、窗口、候选冻结、等额物理移动、过期和拒绝零副作用；扣费与状态变更原子化，entryId 相同载荷重放/不同载荷冲突。私有信息只进入按座位投影接口。**退出**：三绝技黄金样本及守恒/余额/隐藏信息负面例通过。

### P1.5 码牌与可记录随机源

**依赖**：P1.1；可与 P1.4/P1.6 并行。
移植洗牌/码牌目标和约束；随机结果作为明确输入记录，回放按记录逐张复现。是否精确复刻 V4 RNG 的产品决策未定时，保留 V4 已有样本作为行为对照，不擅自更改规则版本。**退出**：同一记录输入重放一致、136 张唯一、非法目标无副作用。

### P1.6 AI 能力与意图记录

**依赖**：P1.1–P1.3；可与 P1.4/P1.5 并行。
AI 仅消费本座位观察与合法候选，异步推理不持有权威状态；入队提交前复核 `roundId/decisionId/controlEpoch`。记录最终 `CommandIntent` 作为回放输入，浮点启发式不进入权威哈希。**退出**：迟到/过期结果拒绝；同一记录意图回放一致；AI 无暗牌读取路径。

### P3.1 有界单桌 actor 与版本语义

**依赖**：P1.1–P1.6、P2.1。**位置**：`Mahjong.TableRuntime`。
单消费者有界 mailbox 串行处理命令、tick、AI 返回、恢复、失租；先裁决已过 deadline，再处理同 tick AI。每个改变状态的命令恰好推进 `state_version` 一次，至少产出一个事件；同命令多事件共享 `command_version`，按 `event_ordinal` 排序；拒绝不占版本。DB/持久端口提交后才发布状态。**退出**：并发顺序、背压、失租和多事件/无事件拒绝测试通过。

### P3.2 按流投影和快照恢复

**依赖**：P3.1、P0.2；可与 P3.3 并行。
按玩家座位/观战分别从 Domain 状态构造白名单视图；公开流独立身份，首基线与订阅在 actor 内原子建立。版本缺口或早期缓冲超限请求全量基线；不先序列化全状态再删字段。**退出**：逐事件逐席位可见性测试、暗牌/种子扫描、旧 binding/epoch 拒绝测试通过。

### P3.3 计时、托管与控制竞态

**依赖**：P3.1；可与 P3.2 并行。
统一时钟端口、deadline、超时动作和 AI 接管/收回的 actor 消息顺序；断线宽限配置与规则 deadline 分离。**退出**：同 deadline 玩家/AI/tick 竞态稳定；旧 controlEpoch 和旧 roundId 不可生效；恢复期间不超时推进。

### P3.4 回执、租约和恢复端口合同

**依赖**：P3.1–P3.3。
定义 `ITableStore/IReceiptStore/ITableLease/ISettlementOutbox`，内存假实现执行与 PostgreSQL 同形的事务约束：同键同载荷返回原回执、同键异载荷冲突；接受命令事件非空；REJECTED 写回执但无事件且版本不变；`ownerEpoch` + `stateVersion` 双栅栏；检查点后重放校验 136/账本/哈希。这里仅完成接口与内存契约测试，真实 PG 实现属于 V5-3A。**退出**：注入提交失败不发布状态；重复与并发命令不重复扣费/出牌/结算；冷恢复重放一致。
