## 共同执行规则

1. `v5` 是集成分支；任务可在从其已验收提交派生的隔离分支/工作树执行，再经复核集成。保持 V4 七模块生产代码和既有验收文档不变，保留任何非本任务的未提交改动。每个任务交付文件清单、命令、退出码、测试结果及未覆盖项。不要把未运行的测试写成通过。
2. 先完成 V5-0 门槛，再进入 V5-1 规则实现。发现 V4 文档与代码不一致时，以实测源码行为建证据，记录待裁决项，不自行改变规则。涉及用户产品选择的项目列为待决，不阻塞与选择无关的基线工作。
3. 共享 C# 库使用 `netstandard2.1`、C# 9；`Domain` 只依赖 BCL，且不读取系统时间、不创建随机数或 ID、不依赖 Unity、Contracts、网络、数据库。线上隐藏状态只能在权威端存在，客户端模型只接收授权投影。
4. 每个任务独立提交可复核的最小变更。新增代码须有针对性测试；阶段门槛由 Codex 独立复核，不由实现者自行宣布通过。环境无法运行的测试须列出阻塞条件、已做的替代检查和补验命令。
5. 任何任务都不得还原、覆盖或顺带提交其他任务/用户的改动；特别注意曾出现过的 `UNITY-ENVIRONMENT.md`、Unity Resources 和 Burst 设置混入任务提交的问题。提交前逐文件审计暂存区。
6. **复核必须一次性给全缺陷清单，返修必须批量完成。** 复核方每轮必须提交本轮发现的全部缺陷（同类合并），不得逐轮只报一条、把已知可复现问题留到下一轮。每条缺陷至少包含：编号、严重级别（BLOCKER/MAJOR/MINOR）、精确位置、可复现命令/脚本/输入、实际结果与期望、证据路径、修复要求、验收断言。返修请求（rework prompt）必须原样包含本要求，并明确要求在同一轮内批量修复全部 BLOCKER/MAJOR；仅当出现新信息（新代码、新环境、新攻击面）时才允许追加缺陷，并须说明此前为何不可发现。复核方在发出请求前须按《V5 复核与返修协议》的检查清单自检，确认没有未报告的已知缺陷。详见 [V5-REVIEW-REWORK-PROTOCOL.md](V5-REVIEW-REWORK-PROTOCOL.md)。
7. **证据类任务按台账收口，不按发现式无限扩张。** N-3/P0.1 等以字段/样本为单位的证据补全任务，必须先冻结分母（census），再对每行做 `bound` / `classified` / `pending` 三选一销账；不得用逐字段发现替代完整清单，也不得因粒度细化无限重开已关闭门槛。具体规则见「G1 阶段验收」后的 N-3 收口规则。

### N-3 收口与 G1 重审规则（2026-10-25 增补）

G1 门 2 的“已导出黄金样本对齐率 100%”按**字段级**口径判定，不以用例数或测试是否全绿代替。当前审计分母为 **1,516 条归一化路径（1,147 条叶子路径）、1,821 个 case×path 语义单元、532,444 个叶子实例**；缺口为 **286 个单元 / 14 个 `GAP:N3-*` 包**（见 `V5-G1-N3-GOLDEN-FIELD-AUDIT.md`）。为防止“越证明越多”和无限重开，规定：

1. **冻结 census 作为唯一分母。** 以审计报告的全量 census 为准，路径与单元数不再手工增补。新 fixture（movement、reversed-wall、visibility 等）走增量登记：只追加该 fixture 的路径/单元，不重算全量，也不改变既有分母。
2. **按包批量派单。** 286 个缺口按 14 个 `GAP:N3-*` 包下发；每轮至少覆盖 2 个包或 50 个单元，禁止逐字段、逐 case 挤牙膏。每包交付：逐单元修复映射、C# 消费锚点、至少一个“改一个字段必须失败”的变异探针、真实命令/exit/计数/日志 SHA。
3. **三选一销账。** 每个单元必须落入：`bound`（有 C# 值级断言 + 变异反证）、`classified`（V4-only、平台阻塞、internal/meta/container、未导出，须写理由、责任任务和复访条件）、`pending`（有责任任务和期限）。禁止 `unknown`；`classified` 必须进入“未覆盖但已分类”清单，不得冒充 `full`。
4. **硬收口点。** 审计 r6 若未发现新的**系统性类别**，即冻结缺口分类并关闭门 2；新发现只允许两类：已登记包的实例补充，或一个新的系统性类别。后者只处理该类别，不重算已分类项。不得以“还可以更细”无限重开 G1。
5. **G1 重审。** N-3 收口后，基于当前集成头做一次完整 G1 重审；重审请求按《V5 复核与返修协议》一次性给全缺陷，不逐轮挤牙膏。重审只判定九门，不重新设计规则。
6. **并行准备，不写生产代码。** G1 重审期间可并行完成 P4.1 的 `ITableChannel`/`ILocalSaveStore` 接口、P4.2 的装配根/场景清单/输入矩阵/文件范围冻结；实现代码仍以 G1 通过为门槛。
7. **合并窗口。** G1 通过后的第一个集成窗口（不超过 24 小时）将 PR19 合并到 `v5`；合并前按最终差异审查，不挑拣中间提交，不把“合并延迟”留到 V5-2 之后。

## V5-3：远端服务、大厅与客户端对账

阶段集成入口为 G1；P5.1/P5.2 可按 WSS 宿主与存储文件/进程隔离并行，P5.3 与 TableService 并行，P5.4a 在 P2.1 之后可提前并行。P5.4b 必须等待 P5.1–P5.3 及 TableRuntime，不把客户端骨架通过误记为远端端到端通过。服务专用工程目标为 .NET 8；共享公开 API 仍遵守 netstandard2.1/C# 9 下限。

### P5.1 TableService WSS 宿主与准入

**依赖**：G1 的 TableRuntime/Contracts.Wire，P5.3 的票据合同可用假签发器先测。**位置**：新 `dotnet/src/Mahjong.TableService/` 与传输测试。
**产物**：`/v1/table` WSS、HELLO/WELCOME 版本协商、票据签名/aud/role/room/assignment 校验、按座位/观战订阅、入站限速和双限缓冲、关闭码/脱敏日志/健康与排空接口；TLS 可在受控入口终止。
**验证**：一个 WebSocket 消息对应一个 Envelope，累积 ReceiveAsync 分片至 EndOfMessage；半消息、多个连续消息、超限/压缩炸弹、慢读、断线、握手超时和顶号；major 不兼容拒绝且 V4/V5 不混连；无效票据/观战提交命令不可进入 actor；心跳与规则 deadline 独立。入口 64 KiB 命令和 1 MiB 快照为待实测初值，超限明确拒绝/分块，禁止截断。
**退出/回退**：合法连接获得原子基线，所有非授权连接零副作用；协议边界或隐藏信息失败时停服而非放宽校验。

### P5.2 PostgreSQL 事件、回执、租约与冷恢复

**依赖**：G1 的 P3.4 端口与事件 schema；可与 P5.1 并行，接口集成后联合验收。**位置**：新 `dotnet/src/Mahjong.Infrastructure/`、数据库迁移、测试容器/故障注入。
**产物**：`table_lease/table_state/table_event/request_scope/request_receipt/table_checkpoint/settlement_outbox` 迁移与端口实现；每房间 advisory lock、scope 行锁、租约 `ownerEpoch` 和 `stateVersion` 双栅栏；周期检查点、加密/限权数据访问、冷恢复、结算 outbox 与幂等消费者合同。
**验证**：已准入命令的事件/回执/outbox 同一事务；状态改变必须有事件，同命令多事件共享 `command_version` 且 ordinal 连续，REJECTED 只写回执且版本不变；同 `(accountId,scopeId,requestId)` 同载荷回原结果、异载荷冲突；过期/撤销 scope 无旧回执时零副作用，已有回执仍可查；scope 在提交边界过期/并发撤销；DB 提交后推送前杀进程、双实例/旧 owner 写入、DB 慢/断、检查点损坏与事件缺口。恢复不跳过坏事件，恢复期不接命令，时钟按记录的 UTC/bootId 调整并写审计；备份从空库恢复至少演练一次。
**退出/回退**：无成功无回执、双写、重复结算或恢复状态漂移；任一发生则停止服务并保留 V4，不能以重试掩盖。

### P5.3 LobbyService 账户、目录、匹配与票据

**依赖**：G0 的产品参数/边界、P2.1 的协议版本；与 P5.1/P5.2 并行。**位置**：新 `dotnet/src/Mahjong.LobbyService/`、大厅存储与 API 测试。
**产物**：账户/OIDC 或受限游客会话、建房/加房/观战、分页目录、`QUEUED→RESERVED→CONFIRMED→CANCELLED/EXPIRED` 匹配、assignment/席位唯一预订、短期一次性 `TableTicket`、JWKS/公钥轮换和大厅幂等回执。票据带 assignmentId，不带 TableService 的 ownerEpoch；大厅只读公开 room_projection，不读私有事件/暗牌。
**验证**：双开并发、重复建房/匹配、取消与过期竞态、无双预订；票据签名、aud、角色、席位、重放、过期、顶号和跨房越权；TableService 不同步调用 Lobby 运行时；目录/权威桌暂时不一致时可对账。游客排位、观战延迟、匹配规则和账户数据保留仍待产品定案时用显式临时配置并限制可上线能力。
**退出/回退**：不能出现双席位/越权票据；若目录与桌分配不可恢复则关闭匹配入口，不接受不确定预订。

### P5.4a Client 通道、持久 outbox 和会话骨架

**依赖**：P2.1 的 Wire schema；可早于 P5.1–P5.3。**位置**：`dotnet/src/Mahjong.Client/`、平台 `ITableChannel` 适配与 fake channel 测试。
**产物**：WSS 适配接口、连接/重连状态机、发送前持久 outbox、稳定 requestId/scopeId/原始业务字节、`SYNC_REQUEST`/`RECEIPT_QUERY`、有界早期推送缓冲和 binding/sync/version 检查；Unity 主线程投递仍由平台层完成。
**验证**：fake channel 注入响应与 PUSH 交错、重复/回退/缺口、队列溢出、服务端已提交但回包丢失、进程重启；未知结果先查回执，绝不分配新 ID 盲重做，旧 binding 消息不覆盖新基线。
**退出/回退**：断线未知结果保持可对账，outbox 数据不丢；此阶段只证明状态机，不宣称真实 WSS 集成。

### P5.4b 真实远端端到端与对账

**验证**：登录/建房/匹配/入桌/观战/整场结算；断网在提交前后、回包丢失、杀客户端/服务端、DB 提交后崩溃、票据过期/顶号、owner 转移与公开流版本缺口。先恢复全量基线，再查询未决回执；重复发送不能重复打牌/扣费/建房/结算；本地 `origin=LOCAL` 结果调用线上端点被拒绝。账户资产唯一写者与结算 outbox 消费者明确，若钱包尚未实现则线上资产功能保持关闭。
**退出/回退**：未知结果可查且无重复副作用；任一双写、私有泄露、LOCAL 入账或断线后无安全恢复路径阻断 G3。
