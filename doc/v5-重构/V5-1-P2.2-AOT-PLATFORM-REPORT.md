## 6. 裁剪、反射与 AOT 风险

1. **生成代码描述符/解析器**：Google.Protobuf 生成类持有静态 `MessageDescriptor`/`MessageParser`。`link.xml` 对 `Mahjong.Contracts.Wire`、`Mahjong.Contracts`、`Google.Protobuf` 和探针程序集整体 `preserve="all"`，优先避免 IL2CPP 裁掉描述符、枚举或 oneof 元数据。代价是包体/保留面偏大，后续可在有真实 IL2CPP 日志后收窄。
2. **反射边界**：Unity 侧只在 `WireAotSmoke` 中用 `System.Reflection` 按名称加载探针；实际序列化路径是直接调用生成代码，不使用反射序列化、`dynamic`、`Reflection.Emit` 或 JSON。探针本身是 `netstandard2.1` 直接消费者，设计为可由 IL2CPP 编译，但本机没有构建证据。
3. **AOT 泛型**：`WireCodec`/Protobuf 使用的集合、`ReadOnlySpan<byte>`、`CodedInputStream` 等尚未在 IL2CPP 下实测。`System.Memory`、`System.Buffers`、`System.Runtime.CompilerServices.Unsafe` 在 Unity 6.3 的 netstandard compat 目录中存在，但未在真实 IL2CPP 构建中验证；不得据此宣称可用。
4. **裁剪**：`link.xml` 只是保留声明；没有 IL2CPP 构建日志、没有 `MissingMethodException`/`MissingFieldException` 实测。P2.2 不把 `link.xml` 解析通过当成裁剪通过。
5. **Unity 许可**：batchmode 的 404/198 是环境阻塞，不是代码问题；在许可恢复前，Unity Editor 的“生成代码加载”没有实测证据。

## 7. TLS / WSS 适配风险（P2.2 未实现传输）

P2.2 只验证 Wire 编解码加载，不包含 WSS/TLS 端点或证书测试。后续 P5.1/P5.4/P6.2 需要覆盖：

1. **消息边界**：一个 WebSocket 二进制消息必须对应一个 `Envelope`；接收端要累积分片到 `EndOfMessage`，不能把 TCP/WebSocket 分片当成独立消息。P5.1 的 64 KiB 命令 / 1 MiB 快照限制应在传输层再次拒绝，而不是截断。
2. **TLS 证书链/SNI/代理**：Unity 的 `ClientWebSocket` 在 Android/iOS 上依赖平台 TLS 栈；自定义 CA、证书轮换、企业代理、时钟偏差都没有实测。iOS ATS、Android Network Security Config 需单独验证。
3. **后台/断线**：Android/iOS 后台恢复、锁屏、切网后的重连与未决回执，不能由本任务的 Editor 探针证明。
4. **压缩**：不得在长度上限校验前解压；压缩炸弹与慢消费者属于 P5.1 的负面测试。
5. **二进制与幂等**：`canonical_payload` 是原始业务字节，TLS/WSS 层不得重编码或改写；Protobuf 重新序列化字节不能替代 canonical digest。
