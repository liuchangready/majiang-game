### 1.2 保存模型决议：Checkpoint + Tail 模型
**【裁决结论】**：本地单机模式严格采纳 **Checkpoint + Tail 模型（检查点基线 + 增量尾部日志 + 独立最新时序与事实）**。
- **架构必然性理由**：
  1. 查阅 [`TableActor.cs:3269-3358`](file:///D:/majiang-wt/p41-contract-addendum-anti-20261026/dotnet/src/Mahjong.TableRuntime/TableActor.cs#L3269-L3358)，权威端 `TableActor` 在处理通常的单步打牌、鸣牌、出千等业务命令时，生成的 `TableDurableCommitRequest.Checkpoint` 保持为 `null`；仅在对局终局（`terminal = true`，`nextState.IsFinished`）或显式投递 `SaveCheckpointAsync` 邮箱控制消息（[`TableActor.cs:338`](file:///D:/majiang-wt/p41-contract-addendum-anti-20261026/dotnet/src/Mahjong.TableRuntime/TableActor.cs#L338)）时才构造全量 `TableCheckpoint`。`TableActor` 并未向 `ITableStore` 暴露“每步命令同步生成全量检查点”的现成能力；
  2. [`ITableStore`](file:///D:/majiang-wt/p41-contract-addendum-anti-20261026/dotnet/src/Mahjong.TableRuntime/TableDurableContracts.cs#L1467-L1522) 与 [`TableRecoveryService`](file:///D:/majiang-wt/p41-contract-addendum-anti-20261026/dotnet/src/Mahjong.TableRuntime/TableRecoveryService.cs#L320-L450) 的冷恢复流水线天生基于 Checkpoint + Tail 设计：先加载基线检查点，再通过 `LoadCommandsAfterAsync` 与 `LoadEventsAfterAsync` 顺序重放尾部动作，并优先使用 `LoadCommittedFactsAsync` 校验重放后的最终投影事实；
  3. 因此，不能要求 `TableActor` 在每次命令提交时必须刷新检查点，也不得以不存在的每步 actor 检查点端口作为现成能力。`LocalSave` 必须显式具备承载 post-checkpoint 增量事实与独立时序的能力。

### 1.4 `LocalTableStore` 对 `ITableStore` 各持久方法的数据流、版本与事务栅栏映射
`LocalTableStore` 位于 `Mahjong.LocalHost`，直接实现 [`ITableStore`](file:///D:/majiang-wt/p41-contract-addendum-anti-20261026/dotnet/src/Mahjong.TableRuntime/TableDurableContracts.cs#L1467-L1522) 全部 13 个接口方法，严格对齐 [`InMemoryTableStore.cs`](file:///D:/majiang-wt/p41-contract-addendum-anti-20261026/dotnet/src/Mahjong.TableRuntime/InMemoryTableStore.cs) 既有已测试语义：

1. **`CreateRoomAsync(TableCheckpoint initialCheckpoint, CancellationToken ct)`**：
   - 构造初始 `LocalSave` 实例，将 `initialCheckpoint` 序列化为 `CheckpointBlob`；
   - 提取 `initialCheckpoint.TimingPayload` 赋给 `LatestTimingPayload`（SHA-256 同步设置）；
   - 提取 `initialCheckpoint.CommittedFactsPayload` 赋给 `LatestCommittedFactsPayload`（可为空）；
   - 初始状态版本安装：`CurrentState.StateVersion = initialCheckpoint.StateVersion`（0），`CurrentState.LastEventSeq = initialCheckpoint.LastEventSeq`（0），`CurrentState.ControlVersion = initialCheckpoint.ControlVersion`（0），`CurrentState.TimingVersion = initialCheckpoint.TimingVersion`（固定为 1）；
   - 清空 `CommandJournal` 与 `EventJournal`；
   - 走 §1.5 之【初次创建分支】（`File.Move`），安全落盘 `<roomId>.save` 并创建 `<roomId>.save.prev` 初始有效备份。
2. **`LoadStateAsync(string roomId, CancellationToken ct)`**：
   - 从当前内存安装的 `LocalSaveState` 重建并返回 [`TableStateRow`](file:///D:/majiang-wt/p41-contract-addendum-anti-20261026/dotnet/src/Mahjong.TableRuntime/TableDurableContracts.cs#L1250)（含 `StateVersion`, `LastEventSeq`, `StateFingerprint`, `StateHash`, `ControlVersion`, `TimingVersion`, `CheatVersion`, `CheatFingerprint` 等）。
3. **`LoadCheckpointAsync(string roomId, CancellationToken ct)`**：
   - 反序列化 `LocalSaveState.CheckpointBlob`，校验 `CheckpointSha256` 匹配后返回基线 `TableCheckpoint`。
4. **`LoadTimingAsync(string roomId, CancellationToken ct)`**：
   - 反序列化 `LocalSaveState.LatestTimingPayload` 为 `TableTimingCheckpoint`；
   - 组装并返回 [`TableTimingJournalRecord`](file:///D:/majiang-wt/p41-contract-addendum-anti-20261026/dotnet/src/Mahjong.TableRuntime/TableDurableContracts.cs#L1348)：
     - `TimingVersion = LocalSaveState.TimingVersion`；
     - `StateVersion = CurrentState.StateVersion`；
     - `ControlVersion = CurrentState.ControlVersion`；
     - `BootId`、单调时钟与 UTC 时钟从解码后的 `TableTimingCheckpoint` 提取。
5. **`LoadCommittedFactsAsync(string roomId, CancellationToken ct)`**：
   - 若 `LatestCommittedFactsPayload != null`，校验 `LatestCommittedFactsPayloadSha256` 并返回 [`TableCommittedFactsSnapshot`](file:///D:/majiang-wt/p41-contract-addendum-anti-20261026/dotnet/src/Mahjong.TableRuntime/TableDurableContracts.cs#L1442)；
   - 若为空，则返回 `null`（恢复流水线自动回退到 `checkpoint.CommittedFactsPayload`）。
6. **`AppendTimingAsync(TableTimingAppendRequest request, CancellationToken ct)`**：
   - **完整栅栏核对**：校验 `request.RoomId` 已初始化；校验租约持有者与 Epoch（`lease.OwnerInstance == request.OwnerInstance && lease.OwnerEpoch == request.ExpectedOwnerEpoch && now < lease.ExpiresAtUtcMs`）；校验状态版本 CAS（`state.StateVersion == request.ExpectedStateVersion`）；校验控制版本 CAS（`state.ControlVersion == request.ExpectedControlVersion`）；校验时序版本 CAS（`state.TimingVersion == request.ExpectedTimingVersion`）；
   - **版本与载荷安装**：
     - **不递增** `StateVersion`，**不递增** `LastEventSeq`，保持 `ControlVersion` 不变；
     - `state.TimingVersion` 严格递增 1：`long nextVersion = checked(state.TimingVersion + 1L); CurrentState.TimingVersion = nextVersion;`；
     - `LatestTimingPayload = TableTimingCheckpointCodec.Encode(request.Timing)` 及其 SHA-256；
     - `LatestCommittedFactsPayload` **严格保持现有值不变**（时序调整不修改事实快照）；
   - 走 §1.5 原子替换流水线持久化；成功后更新内存并返回 `TableDurableCommitResult.Committed(null)`。
7. **`SaveCheckpointAsync(TableCheckpoint checkpoint, TableCheckpointFence fence, CancellationToken ct)` [D-R1-01 核心修复]**：
   - **完整栅栏核对**：校验租约及 Epoch；校验 `state.TimingVersion == fence.ExpectedTimingVersion`；校验检查点与当前状态一致性：
     - `checkpoint.StateVersion == state.StateVersion`；
     - `checkpoint.LastEventSeq == state.LastEventSeq`；
     - `checkpoint.StateFingerprint == state.StateFingerprint`；
     - `checkpoint.StatePayloadSha256 == state.StateHash`；
     - `checkpoint.ControlVersion == state.ControlVersion`；
     - `checkpoint.RulesetVersion == state.RulesetVersion`；
   - **时序版本推进必须满足严格等于当前加一**：
     `if (checkpoint.TimingVersion != state.TimingVersion + 1L) return Failed(CheckpointInvalid);`；
   - **版本与载荷原子安装 [D-R1-01 关键修复]**：
     - **将当前状态时序版本更新为检查点时序版本**：`CurrentState.TimingVersion = checkpoint.TimingVersion;`；
     - 将 `LatestTimingPayload` 更新为 `checkpoint.TimingPayload` 及其哈希；
     - **已确认事实保留规则**：若 `checkpoint.CommittedFactsPayload != null`，更新 `LatestCommittedFactsPayload = checkpoint.CommittedFactsPayload`；若检查点事实载荷为 `null`，**严禁清空现有事实，必须完整保留既有的 `LatestCommittedFactsPayload`**；
     - 替换 `BaseCheckpointBlob = checkpoint` 及其哈希；
     - **日志压缩（Compaction）**：从 `CommandJournal` 移除 `StateVersion <= checkpoint.StateVersion` 的命令，从 `EventJournal` 移除 `EventSeq <= checkpoint.LastEventSeq` 的旧事件；

   - 走 §1.5 原子替换流水线持久化。
8. **`CommitControlAsync(TableControlCommitRequest request, TableCheckpoint checkpoint, CancellationToken ct)`**：
   - **完整栅栏核对**：校验租约及 Epoch；校验 `state.StateVersion == request.StateVersion`；校验控制版本 CAS（`state.ControlVersion == request.ExpectedControlVersion`）；校验检查点与状态/时序一致性（`checkpoint.TimingVersion == state.TimingVersion + 1L`）；

#### 1.5.1 初次创建分支 vs 已有主文件替换分支
- **分支 A：初次创建（`File.Exists(primary) == false`，主要用于 `CreateRoomAsync`）**：
  1. 临时文件 `<roomId>.save.tmp.<guid>` 写入完整初始存档并 `Flush(flushToDisk: true)`；
  2. 使用同一文件卷原子移动：`File.Move(tmpPath, primaryPath)`；
  3. 立即建立初始可恢复备份：`File.Copy(primaryPath, backupPath, overwrite: true)`；
  4. 此时 `primary` 与 `backup` 均已安全存在，后续所有更新均可走分支 B。
- **分支 B：已有替换（`File.Exists(primary) == true`，用于所有后续持久更新）**：
  1. 临时文件写入并刷盘；
  2. 调用原子替换 API：`File.Replace(tmpPath, primaryPath, backupPath, ignoreMetadataErrors: true)`；
  3. 该调用由 OS 原生原子性保障：旧 `primary` 原子移至 `backup`，`tmp` 原子就位为新 `primary`。

#### 1.5.2 确定结果提交点（Commit Point）与取消边界
- **提交点判定**：`File.Move` 或 `File.Replace` 执行成功的瞬间即为**全系统唯一的持久提交生效点（Linearization Point）**；
- **替换前取消（Pre-Replace Cancel）**：若在文件替换前 Token 触发取消或 I/O 报错，立即删除 `.tmp.<guid>` 文件，磁盘原文件与内存状态完全不变，不返回 `Committed`；
- **替换后取消（Post-Replace Cancel）**：若在文件替换已成功返回、但在向内存安装或返回调用方之间发生取消或线程中断：
  - **已提交事实不可撤销**：磁盘上的新状态、`Receipts` 与 `SettlementOutbox` 已经生效；
  - 内存安装必须继续完成；若进程退出，冷恢复必须从磁盘完整加载该新版本；
  - 客户端 Outbox 重连对账（`RECEIPT_QUERY`）时，该请求明确视为已提交（`APPLIED`），**绝不允许将已落盘事实当作未提交而自动重做**。

#### 1.5.3 `OutcomeUnknown` 的隔离栅栏与磁盘对账
- 若在原子替换瞬间发生未捕获的 I/O 异常或操作系统异常导致提交结果未知（`OutcomeUnknown`）：
  - **立即对 TableActor 施加隔离栅栏（Fence Actor）**：停止处理任何新的命令或 Tick，禁止向外继续提供基于旧内存的服务；
  - **禁止仅凭陈旧内存做决策**：系统绝不能单凭内存状态宣称成功或失败；
  - **主动触发磁盘状态对账**：重新对 `<roomId>.save` 与 `<roomId>.save.prev` 进行校验读取，检查 CRC、SHA-256、状态版本号与租约，确证哪一份文件处于有效终态，根据磁盘实际状态安装内存并恢复对外发布。

#### 1.5.4 损坏主文件回退时的有效备份防腐保护（Backup Preservation）
- 当冷恢复检测到 `<roomId>.save` 损坏（如写入不完整或 SHA-256 校验失败）并成功回退至 `<roomId>.save.prev` 时：
  - **防腐保护原则**：已验证的有效备份 `<roomId>.save.prev` 是唯一的救命副本；
  - 在下一次执行持久化写回时，**严禁直接调用 `File.Replace(tmp, primary, backup)`**，因为这会将损坏的 `primary` 覆盖到 `backup` 上，彻底摧毁仅存的有效备份；
  - **安全写回顺序**：将新状态写入 `tmp`，先直接覆盖损坏的主文件（`File.Copy(tmp, primary, overwrite: true); File.Delete(tmp);`），只有当新 `primary` 写入并自校验完全通过后，才允许将新状态同步至 `backup`。

### 3.4 四状态生命周期矩阵（New / Open / TransientClosed / PermanentlyClosed）

### 3.5 取消边界、并发 Join 与出箱对账
1. **取消安全性与零泄露防线**：
   - 工厂入口预取消：`cancellationToken.IsCancellationRequested` 为真时，`CreateChannelAsync` 立即返回 `Task.FromCanceled`，不触发任何文件锁或 Actor 实例化；
   - `OpenAsync` 执行期取消：必须确保在抛出 `OperationCanceledException` 之前，已获取的 `LocalLease` 文件锁被立即释放，避免外部重试时报告“文件被占用”；
   - `CloseAsync` 执行期取消：若调用方传入的 Token 被触发取消，**底层的关闭与文件锁释放逻辑必须在后台继续执行直至完成**，绝不允许因调用方放弃等待而把 Actor 或文件锁遗留给系统。
2. **并发调用 Join 语义**：
   - 多个线程并发调用 `OpenAsync` 或 `CloseAsync` 时，后续调用必须挂载并等待正在执行的真实 Task 完成，严禁产生竞争写或并发释放底层锁。
3. **出箱对账与防重复提交（Outbox Reconciliation）**：
   - 掉线前已由宿主落盘但未回包的请求，回执已永久记录在 `LocalSave.Receipts`；
   - 处于 `TransientClosed` 的信道被同一 `TableSession` 重新 `OpenAsync` 后，客户端自动从持久 Outbox 读取未决请求并发出 `RECEIPT_QUERY(requestId)`；
   - 本地宿主直接从 `LocalSave.Receipts` 返回已持久化回执，客户端将出箱命令标记为已完成，严禁重新分配命令序号或当作新命令重复执行。

### 4.2 本地存档路径规范（严格对齐 P4.2 标准）
依据 `V5-P4.2-SHELL-PREPARATION.md` §5.5，本地单机运行环境必须严格遵循以下目录分配与边界：

| 逻辑标识 | 标准路径规则 | 所有权归属 | 读写权限与隔离约束 |
|---|---|---|---|
| `PersistentRoot` | `Application.persistentDataPath` | Unity 平台层 | 宿主只读感知；禁止写到工程源码或 Asset 目录 |
| `OutboxDirectory` | `<PersistentRoot>/client/outbox` | Client 客户端 (`FileOutboxStore`) | **客户端私有**；本地服务端（`LocalTableStore`）严禁扫描、读写该目录 |
| `LocalSaveDirectory` | `<PersistentRoot>/local` | Server 服务端 (`LocalTableStore`) | **服务端私有**；客户端层严禁直接读写其中的 `<roomId>.save` 文件 |
| 临时工作文件 | `<target>.save.tmp.<guid>` | `LocalTableStore` 事务 | 必须位于同一 `LocalSaveDirectory` 目录下，确保单卷原子替换（`File.Replace`）有效 |

- **无 Unity API 污染**：Unity App 负责计算 `<PersistentRoot>/local` 的真实物理路径字符串，并通过 `LocalTableOptions.SaveDirectory` 纯字符串参数注入。`Mahjong.LocalHost` 内部仅使用 `System.IO.Path`，绝对不调用 `Application.persistentDataPath`；
- **路径安全性校验**：`LocalTableStore` 在打开目录时，校验其绝对路径不包含 `..`、空路径或重解析点注入。

### 4.3 LOCAL 模式安全边界与在线资产绝对隔离
1. **来源标识（Origin Invariant）**：
   本地单机模式生成的所有存档头部、对局回执、出箱记录及事件快照，其 `origin` 字段必须强制固定为 **`LocalSaveOrigin.Local`（`origin = LOCAL`）**。
2. **三项绝对禁止的安全底线（Security Invariants）**：
   - **禁止生成/上传在线凭证**：LOCAL 模式严禁生成、签名或向任何外部网络上传有效的在线身份 JWT、线上账户票据或安全 Claims；本地票据发行器（`ILocalTicketIssuer`）仅在内存中生成一个 30 秒有效期的随机占位句柄，用以满足 `TableChannelConnectRequest.Ticket != null` 的契约形式约束，绝不写盘、不进入日志、不发往网络；
   - **禁止生成/上传线上资产**：LOCAL 模式的终局结算结果严禁包含任何在线钱包代币、付费筹码、赛季积分或排位胜点变动，出箱记录仅用于单机战绩与本地成就归档；
   - **线上服务端无条件拒绝**：任何带有 `origin = LOCAL` 的结算出箱载荷，若被恶意篡改尝试上传至线上端点（Lobby/TableService/Ranked/Wallet），线上服务端必须在鉴权与网关层无条件直接拒绝并记录安全告警。
3. **文档实跑状态口径**：
   在当前纯文档契约阶段，明确将“线上端点对 LOCAL 结果的拦截实测”标注为 **`NOT_RUN`**（纯架构契约约束，未在物理线上服务器实跑攻击注入）。
