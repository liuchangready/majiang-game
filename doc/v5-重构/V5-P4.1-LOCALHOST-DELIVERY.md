## 2. 存档与生命周期实现要点

### 2.1 Checkpoint + Tail

- `LocalSave` 使用 `BaseCheckpointBlob` + 增量 `CommandJournals/EventJournals` + receipts/outbox + 最新 timing/facts/control 快照。
- 普通命令只追加 journal/event 并原子替换整个 envelope；终局/显式 checkpoint 才替换 base checkpoint 并压实 tail。
- `LocalTableStore` 复用 accepted `InMemoryTableStore` 的 `ITableStore/IReceiptStore/ITableLease/ISettlementOutbox` 事务规则：先由 accepted 实现做 owner/state/control/timing/receipt/scope 校验，成功后才写盘；**没有复制或修改 Domain 状态机**。
- 冷启动时根据 base checkpoint 重放持久化的 durable operations 恢复 accepted store，再交给 `TableActor.RecoverFromStoreAsync` 做 Domain 级恢复；两步都失败则拒绝，不静默开新局。

### 2.2 原子文件流水线

- 临时文件：`<roomId>.save.tmp.<guid>`，同目录、写入后 `Flush(true)` 并校验长度/SHA。
- 初次创建：`File.Move(tmp, primary)` 为提交点；随后 best-effort `Copy(primary, prev)`，Copy 失败只标记 `BackupNeedsRepair`，不回滚。
- 已有文件：`File.Replace(tmp, primary, prev, true)` 为提交点。
- 替换失败：先探测 primary 是否已经是 candidate（成功但抛异常 => COMMITTED）；可读旧 primary/prev => 返回不可提交并由 actor fence；primary 不可读 => `OutcomeUnknown` 并 fence。
- 取消：提交点前取消删除 tmp 并返回失败；**提交点后取消仍安装内存并保留已落盘 receipt/状态**。
- 坏 primary + 好 prev：同卷重命名隔离损坏 primary，再把 prev 的 exact bytes 原子提升；双坏拒绝，不新建。
- 文件格式/规则集版本不兼容：明确拒绝，不回退旧 prev。

### 2.3 生命周期

- 首次 Open 才拿 `<roomId>.lock`（`FileShare.None`）并创建 actor；第二通道得到 `LocalTableException(LeaseConflict)`。
- 并发 Open 共享同一 open task；每个 waiter 独立取消；初次全取消清理 actor/锁并进入 `PermanentlyClosed`。
- 暂态重开全取消保持 `TransientClosed` 与 actor/锁；永久关闭 single-flight，取消后后台继续清理，后续 Close await 同一任务。
- `New.Close(false)` 无操作；`New.Close(true)` 零资源直接终态。
- 未取消的 I/O/损坏失败返回稳定 `LocalTableException`；不伪造 OCE。

## 4. 单局离线 E2E 的实际行为

测试 `FullRoundCanBePlayedOfflineThroughClientCommands`：

1. `LocalTableHost.CreateChannelAsync` -> `New`（零文件/锁）。
2. `TableSession.OpenAsync` -> HELLO/WELCOME -> SYNC_REQUEST/SYNC_RESPONSE -> Ready；`PlayerSnapshot` 来自真实 `ProjectionWireMapper`。
3. seat 0 由 Client `SubmitAction` 提交 Draw/Discard/Pass；seat 1–3 由 `LocalTableDriver` 在 actor 外基于 `CaptureAiObservationAsync` 计算候选，走 `OpenDecisionAsync` + `CompleteAiAsync`，actor 复核 roundId/decisionId/controlEpoch。
4. 牌墙耗尽时由宿主 N-2 settlement authority 以 `SubmitSettlementAsync(ExhaustiveDraw)` 结算；终局 checkpoint 原子提交。
5. 客户端收到 receipt + PlayerUpdate；断言 round 进入 `RoundEnd`，版本前进，回执 Applied。

测试 `TerminalRoundSurvivesColdRestart`：

- 单局终局后关闭物理通道；重新打开同一 `<roomId>.save`。
- 冷恢复后客户端重新收到 WELCOME/SYNC；断言 stateVersion、roundId、`RoundEnd`、finalScores 与终局前一致。

三绝技测试：

- TileMark：从 Client 私有视图取 4 张手牌，经 `SubmitTileMark` 提交；断言 receipt Applied、私有 `TileMark.Groups` 与提交 tiles 一致、cheat points 下降。
- SleeveBloom：在 seat 0 的 CheatWindow 提交 `SubmitSleeveBloom`；断言 offer 出现在私有投影；再提交 `SubmitSleeveBloomChoice(First)`；断言 Applied。
- BeamSwap：下一轮 seat 0 CheatWindow 提交 `SubmitBeamSwap`；断言 BeamSwap offer；提交 `KeepOriginal` 选择；断言 Applied。
- 上述均经 `TableSession`/`WireCodec`/Loopback，不经 actor 内部旁路。

## 6. 已知缺口与风险（必须由后续任务闭环）

1. **整场多局未实现（BLOCKER，对 P4.1 退出条件）**
   - 当前 `LocalTableHost` 是单局宿主；`TableActor` 没有公开的 round-transition/match 合同，`LocalTableStore` 的 base checkpoint 也是单局状态。
   - 本任务没有修改 Domain/TableRuntime 去扩展多局状态机（不允许复制/改 Domain 规则），因此“局间→下一局→整场终局”的自动回放为 **NOT_RUN**。
   - 需要 caller 在集成阶段决定：新增 match 编排合同，或在 P4.5 以多局独立存档 + MatchSession 编排实现；无论哪种都需要新的授权与合同，不应由本任务私自扩展。

2. **托管收回未做 Client 闭环（MAJOR）**
   - actor 已有 `RequestTakeoverAsync/ReclaimControlAsync`，但 Client 协议 `ClaimControl/ReleaseControl` 没有可安全对应的 durable receipt 语义（控制变更不推进 state_version）。
   - 本轮没有伪造 receipt 或控制事件；因此“客户端托管/收回”标 **NOT_RUN**。AI 决策路径本身已通过 `CompleteAiAsync` 复核。

3. **未决回执断线对账未 E2E（MAJOR）**
   - `LocalTableRuntime.HandleReceiptQueryAsync` 已实现，`LocalTableStore.TryGetAsync` 可返回持久化 receipt；但本轮没有构造“发送后断线、重连 RECEIPT_QUERY”的完整用例。
   - 需要下轮补：真实发送 → 关闭通道 → 重新 Open → Query → 断言原结果/不重复副作用。

4. **终局胜利（Tsumo/Ron）投影 facts 未验证（MAJOR）**
   - 单局 E2E 以流局终局；`LocalSnapshotFacts` 对 Tsumo/Ron 只提供了 finalScores/loser，未提供真实 yaku/han/fu（N-2 calculator 的 `ScoreBreakdown` 未接入投影 facts）。胜利局终局 checkpoint 可能被投影校验拒绝。
   - 需要在 projection facts source 中接入 accepted `RoundSettlementCalculator.Breakdown`，并补 Tsumo/Ron 终局 + cold restart 用例。

5. **CrashWorker 未使用（MINOR）**
   - 冷启动用正常关闭后重开验证；没有用强杀子进程模拟断电。文件原子性/提交点语义已有故障注入测试，但“真实强杀”仍未跑。

6. **Cheat 私有投影的完整字段未逐项断言（MINOR）**
   - 三绝技只断言 offer/group/points 与 Applied；未逐字段对照 SleeveBloom 的 second tile/reservation、BeamSwap 的全候选/槽位。

7. **Unity/IL2CPP/P4.2-B（NOT_RUN）**
   - 未跑 Unity Editor/IL2CPP；P4.2-B 只可按本报告 API 做薄适配，不得把本报告当作 G2。

## 7. P4.2-B 交接

1. `LocalTableHost.CreateChannelAsync(options, ct)` 返回 `ITableChannel`；App 的 `LocalTableChannelFactory` 只需构造/注入 options，不在 UI/Platform 暴露 LocalHost 类型。
2. `SaveDirectory` 必须是 Unity `Application.persistentDataPath/local` 绝对路径；`Mahjong.LocalHost` 不调用 Unity API、不读写 `client/outbox`。
3. 每次连接需 `LocalTableHost.IssueTicket(options)`；ticket 为进程内一次性句柄，30 秒过期，不写盘、不上报、不是 JWT。
4. `LocalTableHostOptions.Environment` 可注入 Unity 的 clock/random/id；默认系统实现只用于桌面/测试。
5. `CloseAsync(permanent: true)` 后锁才释放；App 不要假设 `ITableChannel` 有 `Dispose`。
6. P4.2-B 仍需真实 Unity 构建/PlayMode 验证；本报告的“离线 E2E”只覆盖纯 .NET 宿主。
