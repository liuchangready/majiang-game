## 4. 客户端端到端提交覆盖补充说明

为纠正前期报告中领域探针与真实客户端提交表述混淆的问题，本次在客户端端到端（Client End-to-End Loopback）层面补充了以下用例：

1. **暗杠后立直真实客户端提交 (`RiichiAfterClosedKanClientSubmissionTest`)**：
   - 流程：Seat 0 摸牌听牌 -> 宣告暗杠 1m -> 摸岭上牌 -> 客户端收到 `DeclareRiichi` 动作候选 -> 客户端生成并提交立直命令 -> 权威服务端接受并扣除 1,000 点棒，公共视图更新立直状态。
2. **无役听牌 AI 平滑摸打 (`NoYakuAiDoesNotGetStuckOnIllegalRonTest`)**：
   - 流程：人类玩家 Seat 0 舍出 5p（契合 AI Seat 1 听牌面子但 AI 无役） -> 权威层不向 AI 派发 `DeclareRon` 动作 -> AI 在自身回合正常摸牌并打出，牌局持续推进无卡死、无非法和牌。
3. **未决候选冷恢复真实提交 (`PendingChiCandidateSurvivesColdRecoveryAndSubmitsSuccessfully`)**：
   - 流程：上家舍牌触发吃牌窗口，Seat 0 获得带 `[8, 0, 4]` 实体的 `DeclareChi` 候选 -> 进程冷重启恢复 -> 还原快照中保留完整实体列表 -> 客户端直接基于恢复候选提交 `DeclareChi` -> 服务端返回 `Applied` 并在公共视图中建立 `Chi` 副露。
4. **吃/碰后 Discard 阶段端到端出牌履约 (`ChiOrPonAfterCallDoesNotOfferTsumoAndDiscardSucceedsTest`)**：
   - 流程：Seat 1（AI 庄家）打出白板 126，Seat 0（人类南家）持 `[124, 125]` 收到 `DeclarePon` 候选并提交副露 -> 副露生效后进入 Discard 阶段，手牌 11 张虽然成和了形但摸牌证据为空 -> 验证客户端收到的决策中绝无 `DeclareTsumo`，且仅含合规 `DiscardTile` 候选 -> 客户端选择并提交打出候选 109u，权威层返回 `Applied` 并在公共台面正确记入舍牌。
5. **AI 吃/碰后平滑舍牌不陷入非法自摸循环 (`AiChiOrPonDiscardsNormallyWithoutLoopingOnIllegalTsumoTest`)**：
   - 流程：Seat 1（AI 庄家）打出 126，Seat 2（AI 南家）吃/碰 126 形成副露进入 Discard 阶段 -> 验证 AI 不会因非法伪造自摸候选而反复尝试 `AI_TSUMO`，而是平滑选择合法舍牌打出，`Melds.Count == 1` 且 `Discards.Count == 1`，牌局顺畅推进。
