## 1. 缺陷归因与修复

R35 指出的“正常回包后直接读 store 不能替代丢回包后的 Client 持久 outbox 对账”成立。原实现存在四个真实缺口：

1. **控制结果持久化使用单槽 pending**：`LocalTableRuntime` 在调用 actor 前写入一个进程级 pending，`CommitControlAsync` 再消费它。并发控制命令、或与 driver/控制事件交错时，可能把 A 请求的 digest/kind 记到 B 的控制变更上。改为按 `(account, scope, request)` 键控的 pending 表，并以 `seat + changeKind + previousEpoch` 与真实 `TableControlEvent` 对齐后才写入。
2. **控制命令未校验 scope 过期/撤销**：actor 的控制入口不经过 `ValidateScope`，过期 scope 仍能改变控制权。新增 `ValidateControlScopeAsync`，在产生副作用前校验角色、账户、房间、撤销与 24h 过期。
3. **旧 decision 走的是传输错误而非回执**：`HandleCommandAsync` 在 try 之外抛 `DecisionMismatch`，Client 收到 ERROR 而不是 REJECTED 回执，outbox 无法按拒绝语义闭合。改为直接返回确定性的 `RejectedReceipt`。
4. **控制回执查询被“当前 scope 必须存在”隐含限制**：冷重启后内存 scope authority 为空，而旧 scope 的已提交回执应按原 `(account, oldScope, request)` 可查；查询只需当前连接绑定，不应要求旧 scope 仍在内存。查询改为只绑定当前会话，并同时接受持久化控制记录。

另：精确同字节重放的直接回执现在显式置 `Replayed = true`；Changed 与 Unchanged 两条路径都只在**持久记录可读回**之后才发出 Recorded 回执。

## 4. 关键实现细节

1. **键控 pending 与真实 change 对齐**：`PrepareControlResult` 不再写单槽；`CommitControlAsync` 在克隆出的 candidate 上按 `Seat + ChangeKind + PreviousEpoch` 找到对应请求，只有该匹配存在时才把 `Digest/Kind/EvaluatedStateVersion` 写入 `ControlResults`。driver 产生的控制事件不会误消费 Client 请求的记录。
2. **Changed 原子、Unchanged 单独提交**：Changed 沿用既有 `CommitControlAsync` 的同一文件原子替换；Unchanged 走 `CommitPreparedControlResultOnly`。两者都在回执前排他地读回记录，读不到就返回 `INTERNAL_ERROR` 而不是伪造 Recorded。
3. **scope 授权**：控制副作用前检查 `TableScopeRole.Player`、账户、房间、撤销、`IsExpiredAt(now)`；过期/撤销返回 `REQUEST_SCOPE_EXPIRED`，未知/错绑返回 `UNAUTHENTICATED`。
4. **回执查询**：只要求当前会话绑定（`SessionId/RoomId/SeatId/BindingEpoch`）；查询 scope 可以是旧连接甚至冷重启前的 scope，仍按 `(account, scope, request)` 读持久控制记录，不重新执行副作用。
5. **旧 decision**：`HandleCommandAsync` 在校验到 `ExpectedDecisionId` 与当前 pending 不一致时直接入队 `RejectedReceipt`（`DECISION_MISMATCH`），Client 的 outbox 得到确定性拒绝而不是传输故障。
6. **重放标记**：精确同字节重放返回原 digest/evaluated，并置 `Replayed = true`；异字节/异 kind 同 request id 返回 `REQUEST_ID_CONFLICT`。
7. **独立进程**：`CrashWorker` 新增 `control-outbox-reconcile`，真实打开 save、重新走 baseline + `RECEIPT_QUERY`、消费 FileOutbox，并回读 store 记录；不是父进程内模拟。

  1. `LocalTableRuntime.cs:767-777`：先计算 `expected`，把 `ClaimControl/ReleaseControl` 分支提前到动态 decision 校验之前。
  2. `LocalTableRuntime.cs:1152-1185`：在 `_controlGate` 内先按 `(account, scope, request)` 查询持久 `LocalControlRecord`；同字节返回原 `Recorded + Replayed=true + digest/evaluated`，异字节/异 kind 返回 `REQUEST_ID_CONFLICT`。

- 探针扩展（`LocalHost.Tests/LocalControlTests.cs:32`）：
  - 退休 decision 后原始字节重放 → 原 `Recorded`、`Replayed=true`、原 digest/evaluated。
  - 同一 request id + 异字节 + 退休 decision → `Rejected` / `REQUEST_ID_CONFLICT`。
  - 全新 request id + 退休 decision → `Rejected` / `DECISION_MISMATCH`，无持久记录。
