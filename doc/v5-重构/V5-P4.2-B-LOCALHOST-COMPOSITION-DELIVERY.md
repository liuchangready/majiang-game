## 3. D-ACT-01：真实装配

### 3.1 生产默认与公共门面

- `AppComposition` 默认 `ChannelFactory = new LocalTableChannelFactory(Config, Paths)`；`AppRoot.Initialize` 不传测试工厂时即走该生产默认。
- `LocalTableChannelFactory` 只调用 accepted `Mahjong.LocalHost` 的公共 `LocalTableHost.CreateChannelAsync(LocalTableHostOptions, CancellationToken)` 与 `LocalTableHost.IssueTicket(LocalTableHostOptions)`；无反射、无动态加载、无条件编译藏缺失。
- 每次 open 生成真实一次性 ticket；`AppComposition` 用 `ILocalTableTicketSource` 从真实 channel 取 ticket，再构造 `TableSessionOpenRequest(realTicket, "unity-p42b-localhost")`，不再使用 `("local","local")` 占位。ticket 不写日志、不写 outbox、不暴露给 UI。
- ticket 真实有效性不是只靠代码阅读：accepted host 在 HELLO 时执行 `LocalTableRuntime` → `LocalTicketIssuer.TryConsume(hello.Ticket, roomId)`，缺失/过期/复用/错 room 均回 `Unauthenticated`。本轮真实 host 用例经此路径到达 Ready 并完成动作，说明生产传入的是被 host 接受的真实 ticket，而不是占位串。
- room 固定为 `local-main`；save 目录为 `Application.persistentDataPath/local`（或显式隔离 root），outbox 为 `Application.persistentDataPath/client/outbox`，两者实际不同。主线程在 `AppComposition` 构造时捕获 `UnityAppPaths`。
- 数据流保持 accepted 边界：`LocalTableChannel`（host）→ `ITableChannel` → `TableSession` → `TableSessionOperationQueue` → `SessionCoordinator` → `MainThreadDispatcher` → Table view。UI 不直接驱动领域/AI/ticker。

### 3.2 真实通道顺序修复（D-ACT-01a）

- 位置：`AppComposition.OpenLocalSessionInternalAsync`。
- 实际：初版在 `queue.OpenAsync(...)` 之前就启动 receive pump。准备层 scripted channel 的 `ReceiveAsync` 永远 park，掩盖了该顺序问题；真实 `LocalTableChannel.ReceiveAsync` 在首次 open 之前拒绝接收，pump 会把 session 推入 transport failure，真实 session 永远到不了 Ready。
- 修复：先 `await queue.OpenAsync(...)`（完成 channel open + HELLO 发送），再启动 pump 并 `SetPumpTask`；帧在 host outbound 队列中不会丢失。未改 Client/queue/host 契约。
- 证据口径：该缺陷在本任务开发早期被发现，但当时 scoped 失败 XML 在同名成功运行中被覆盖，未能保留可引用的失败路径；本轮不伪造路径，也不把它写成“有原始 XML 的复验”。当前证据是代码顺序、accepted host 的 `ReceiveAsync` 前置条件，以及本轮 EditMode 27/27、PlayMode 6/6、Player 真实开局 exit 0。

### 3.3 预取消、错误映射与生命周期

- 预取消：factory 在构造 options/ticket 前检查 `cancellationToken`，返回 canceled task；composition 在进入 factory 前 `ThrowIfCancellationRequested`。真实测试确认预取消后 root 目录不存在、无 ticket/lease/actor、无 session，OCE 原样传播。
- 错误映射：`LocalTableException.ErrorKind` 映射为稳定码；只有 `Unavailable` 映射 `LOCAL_HOST_UNAVAILABLE`；`LeaseConflict` → `LOCAL_HOST_LEASE_CONFLICT`；`CorruptState` → `LOCAL_HOST_SAVE_CORRUPT`；其余 → `LOCAL_HOST_START_FAILED`。异常只在 App 层映射，UI 只见稳定码。
- lease/corrupt：失败路径不删除 save、不重写字节、不释放别人的 lease、不暗开替代 room；第二个 owner 失败时第一个 owner 的 session 仍 Ready。
- clean close 后重进：composition 清空 coordinator、重建 session CTS；同一 `local-main` room 重新打开并恢复已提交 state version；PlayMode 证明返回菜单释放 host/文件租约后可再次 Started。
- timeout/close fault 仍进入终态 quarantine，不替换；准备层既有 20 用例与 terminal 断言保持。
- baseline：首个 full snapshot 的 `VisibleEventBatch.Kind=Baseline`，`PlayableEvents` 为空；只有动作后的 `Incremental` batch 才可进入新动画。
