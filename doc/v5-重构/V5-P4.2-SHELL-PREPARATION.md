`check-unity-boundaries.ps1` 的强制规则：

1. 递归解析所有 asmdef，名称唯一；`references` 只能是上表项目/包 asmdef；`precompiledReferences` 只能是上表 DLL；不得把 `Mahjong.*` 插件写入 `references`，也不得把 asmdef 名写入 `precompiledReferences`。
2. 生产 asmdef 必须 `overrideReferences=true`、`autoReferenced=false`、`allowUnsafeCode=false`；测试 asmdef 允许 `UNITY_INCLUDE_TESTS` 约束。
3. 每个 asmdef 的 `references`/`precompiledReferences` 必须是策略文件中的**精确集合**；多一个、少一个都失败。App core 不含 `Mahjong.LocalHost.dll`，App P4.2-B 才加；UI/Table/Spectator/Platform 永不出现 LocalHost。
4. 引用图必须无环：仅对项目 asmdef 做 DFS/拓扑排序；包 asmdef 视为外部叶子。自环、两节点环、三节点环都必须失败。`UI/Table/Spectator/Platform` 不得直接引用 `LocalHost/Domain/TableRuntime/Ai`；`App` 不得直接引用 `Domain/TableRuntime/Ai`。
5. 扫描 `Assets/Scripts/{App,UI,Table,Spectator,Platform}` 的源码，拒绝禁用命名空间/类型；扫描场景 YAML 的脚本 GUID，拒绝内容场景中的 `GameBootstrapper`/`EventSystem` 重复。
6. 用 `System.Reflection.Metadata`（TEMP 生成的小工具）读取编译后的 `Mahjong.Unity.*.dll`，检查**直接 AssemblyRef**。这只能捕获编译期直接引用，**不能**捕获 `Assembly.Load`、`Assembly.LoadFrom`、`Type.GetType`、`Activator.CreateInstance`、`Reflection.Emit`、`dynamic` 等运行期反射/动态加载。
7. 对上述反射/动态 API 做源码扫描；`App/UI/Table/Spectator` 默认全部禁止，`Platform` 只允许 `Assets/Scripts/Platform/WireAotSmoke.cs`（P2.2 AOT 探针，按文件 SHA-256 白名单），其他文件禁止。负例：在 TEMP 夹具加入 `Assembly.Load("Mahjong.Domain")`/`Type.GetType("Mahjong.TableRuntime...")`，检查器必须 exit 1；合法样本 exit 0。
8. 负例矩阵：TEMP 分别制造自环、`App↔UI` 两节点环、`App→UI→Platform→App` 三节点环、缺失必需引用、无环但多余的禁止引用、DLL 放入 `references`、禁止插件放入 `precompiledReferences`、缺 `precompiledReferences`、`overrideReferences=false`、LocalHost 放入非 App、反射 scanner 正例 + 关闭 scanner 的 mutation；每种必须得到预期非 0/失败；合法 7 份 JSON 必须 exit 0。测试 `nunit.framework.dll` 的解析根必须是实际 `com.unity.ext.nunit` 路径，不能要求它位于 `Assets/Plugins`。

## 4. 装配根、对象生命周期与主线程

### 4.1 职责划分

| 组件 | 职责 | 明确不负责 |
|---|---|---|
| `AppRoot` | 唯一持久根；创建/持有 dispatcher、lifecycle、router、composition、theme provider；`DontDestroyOnLoad` | 业务规则、牌桌渲染、网络解码 |
| `GameBootstrapper` | Boot 场景唯一入口；创建/校验 AppRoot，注入 `AppConfig`/`UiTheme`；加载 Menu；失败时显示可诊断错误 | 直接 new `TableSession`、直接 `SceneManager.LoadScene` 绕过 router |
| `SceneGuard` | 内容场景的保护：无 AppRoot 时记 `BOOT_REQUIRED` 并重定向 Boot；不初始化半个 AppRoot | 业务逻辑、重复订阅 |
| `AppComposition` | 组合根；创建 `ITableChannel`/`TableSession`/`IOutboxStore`/`ITableTicketProvider`；按逆序释放；仅此处持有 LocalHost | UI 布局、场景切换策略、权威状态修改 |
| `AppRouter` | 场景序列与重入门；`Boot→Menu→Lobby→[Table/Spectator]`；返回栈；失败回退 | 业务会话、网络泵 |
| `AppLifecycle` | `OnApplicationPause/Focus/Quit` 的主线程顺序；暂停时间记录；恢复通知 | 本地判定超时、直接重发命令 |
| `MainThreadDispatcher` | 线程安全有界队列；按序在主线程执行；generation 丢弃旧会话事件；异常隔离 | 业务状态、网络读取 |
| `SessionCoordinator` | 唯一 `IGameSession` owner；单线程泵循环；在 owner 线程读取状态/待决命令并发布深隔离 `SessionViewState`；关闭序列 | 让 UI 读活 session、在主线程轮询活字典、直接调用 Unity API |
| `ISessionView`（UI 程序集） | UI 只读的 `Current` 深隔离视图与 `Changed` 事件；事件在主线程触发 | `SubmitAsync`、`PumpOnceAsync`、outbox 读写、直接返回活 `PendingCommands` |
| `ISessionCommands`（P4.3，不属于 P4.2-core） | UI 的类型化命令入口；由 App 实现 | 让 UI 构造 `ProtocolCommand`/requestId/scope |
| `ITableChannelFactory`（Platform） | 按 `TableTransportKind` 创建通道；本地/远端由实现决定 | 持有 session、写 outbox、UI |
| `UnavailableLocalTableChannelFactory`（App，P4.2-core） | 实现 `ITableChannelFactory` 的 Local 分支，返回稳定 `LOCAL_HOST_UNAVAILABLE` | 伪造可用本地通道 |
| `LocalTableChannelFactory`（App，P4.2-B） | 同一 `ITableChannelFactory` 的 Local 分支，薄适配 P4.1 工厂；不改变 UI 公共签名 | 定义存档 schema、暴露 LocalHost 类型给 UI |
| `IAppNavigation`（UI 程序集） | Menu/Lobby 只依赖的导航端口：`OpenLobby`/`BackToMenu`/`RequestQuit` | 直接 `SceneManager`、直接持有 AppRouter |
| `UiInputLifecycle`（UI 程序集） | 唯一指针 arm 生命周期：`OnPause`/`OnTransition`/`OnFocusLost` 清 arm/pointer 并递增 pressGeneration；`OnResume`/`TransitionEnd` 只恢复 accept | 直接提交业务命令、创建第二个点击消费者 |
| `UnityAppPaths`（Platform） | `persistentDataPath` 下的 outbox/本地存档/日志根；路径规范化和越界拒绝 | 存档格式、原子写实现 |
| `UiThemeProvider` | 共享字体、TMP FontAsset、颜色、Sprite、按钮样式 | 业务数据、场景切换 |
| `SafeAreaFitter`/`DesignViewport` | 1280×720 设计坐标、16:9 容器、`Screen.safeArea` 内缩 | 改权威状态、按设备改规则 |

创建顺序（`Awake`/`Start`）：

1. `SubsystemRegistration` 重置静态 `AppRoot.Instance`、dispatcher 队列、generation；因为当前 `EditorSettings.m_EnterPlayModeOptionsEnabled=1`、`m_EnterPlayModeOptions=1`（禁用 domain reload），静态字段可能在 Play Mode 间残留。
2. `Boot` 的 `GameBootstrapper.Awake` 检查 `AppRoot.Instance`；不存在则创建并注入序列化的 `AppConfig`/`UiTheme`；若发现多个根，保留最早实例、销毁其余并记录 `APP_DUPLICATE_BOOTSTRAP`。
3. 标记 `DontDestroyOnLoad`；捕获主线程 ID。
4. 创建 `MainThreadDispatcher`（先于任何订阅）。
5. 创建 `UnityAppPaths`、`AppConfig`、`UiThemeProvider`。
6. 创建 `EventSystem`；若场景已有 EventSystem，禁用/销毁场景实例并记录 `UI_DUPLICATE_EVENTSYSTEM`。
7. 创建 `AppRouter`、`AppLifecycle`。
8. 创建 `AppComposition`（会话可延迟到首次进入 Lobby 再打开；Boot 不阻塞在网络上）。
9. `GameBootstrapper.Start` 调用 `AppRouter.LoadAsync(SceneId.Menu)`；失败显示 `BOOT_SCENE_LOAD_FAILED`，不无限重试。

释放顺序（主动退出必须走 `ShutdownAsync`；`OnDestroy` 只是兜底）：

1. 主线程设置 `_quitting`，禁用新命令/新场景请求，记录 `SHUTDOWN_BEGIN`。
2. 取消 `SceneManager` 过渡 token；取消 `SessionCoordinator` 的**运行 token**。
3. **await 泵任务退出屏障**（`PumpBarrierTimeout` 建议 2 s）。只有泵退出（`pumpTask.IsCompleted`）后才允许调用 `CloseAsync`；超时绝不能继续并发 `Close/Dispose`。
4. 泵已退出时，使用**独立关闭 CTS**（不沿用已取消的运行 token，`CloseTimeout` 建议 3 s）调用 `session.CloseAsync("APP_QUIT", closeToken)`；等待 `WhenAny(closeTask, Delay(CloseTimeout))`。超时记录 `SHUTDOWN_CLOSE_TIMEOUT`，同样不得并发 `Dispose`。
5. 取消 `SnapshotChanged`/`ReceiptResolved` 订阅，清空 dispatcher 队列（丢弃未执行的 UI 动作）。
6. 仅当步骤 3、4 均成功完成，才释放通道（若实现 `IAsyncDisposable`/`IDisposable`）；`ITableChannel` 本身没有 Dispose 成员，不能假设。
7. 释放 outbox（`FileOutboxStore` 当前无 Dispose；只停止使用）；销毁 AppRoot；`Instance=null`；记录 `APP_SHUTDOWN_COMPLETE`。

**关闭结果分支**（`ShutdownAsync` 返回显式结果，不吞错）：

| 结果 | 触发 | 后续 |
|---|---|---|
| `Completed` | 泵退出且 `CloseAsync` 在超时内完成 | 正常释放、销毁根、可切 Menu |
| `PumpBarrierTimeout` | 2 s 内泵未退出 | 不调用 `CloseAsync`、不 Dispose；置 `Quarantined`；主动退出记录后继续 `Application.Quit`；返回菜单失败关闭（`RETURN_TO_MENU_BLOCKED`），保留当前画面，不建第二个会话 |
| `CloseTimeout` | 泵退出但 `CloseAsync` 3 s 未返回/忽略取消 | 不 Dispose；置 `Quarantined`；主动退出记录后继续；返回菜单失败关闭 |
| `AlreadyIncomplete` | `_terminal` 已存在（Quarantined 或已 Completed） | 返回 `AlreadyIncomplete`，`PriorOutcome` 为首次结果；不重复 Close/Dispose，`MenuAllowed=false` |

`OnApplicationQuit`/`OnDestroy` 不承诺异步工作一定完成：主动退出路径应先 `await AppRoot.ShutdownAsync()`，根据结果记录后 `Application.Quit()`；Unity 终止通知只做“取消 + 尝试有界关闭 + 记录未优雅关闭”，不得用 `.GetAwaiter().GetResult()` 阻塞主线程，也不得把 `OnDestroy` 当成可等待的关闭入口。Quarantined 任务的异常只在 owner 记录，不再触碰 UI；进程退出时由 OS 回收。UI 释放动作必须回主线程执行。

**`SessionCoordinator` 最小时序伪代码**（同一 owner，关闭只启动一次）：

```text
state: _shutdownTask: Task<ShutdownResult>?, _terminal: ShutdownResult?

ShutdownAsync(kind):
  lock:
    if _terminal != null:
      return AlreadyIncomplete(prior=_terminal.Outcome,
                               quarantined=_terminal.Quarantined,
                               menuAllowed=false)
    if _shutdownTask != null:
      return _shutdownTask                 // concurrent caller shares in-flight task
    _shutdownTask = RunOnce(kind)
    return _shutdownTask

RunOnce(kind):
  _runCts.Cancel()
  pumpBarrier = await WhenAny(_pumpTask, Delay(2s))   // same _pumpTask, not a new task
  if pumpBarrier != _pumpTask:
      _terminal = PumpBarrierTimeout(quarantined=true, menuAllowed=false)
      return _terminal                                // DO NOT Close/Dispose
  using closeCts = new CancellationTokenSource(3s)    // independent token
  closeTask = _session.CloseAsync("APP_QUIT", closeCts.Token)
  closeWait = await WhenAny(closeTask, Delay(3s))
  if closeWait != closeTask:
      _terminal = CloseTimeout(quarantined=true, menuAllowed=false)
      return _terminal                                // DO NOT Dispose
  _disposeChannel()
  _terminal = Completed(quarantined=false, menuAllowed=true)
  return _terminal

Publish(generation, state):
  if _terminal != null or _quarantined: drop
  if generation != _currentGeneration: drop            // old generation never publishes
  dispatcher.Post(state)
```

`AlreadyIncomplete` 只用于已存在 `_terminal` 的后续调用；它不重复 Close/Dispose，`MenuAllowed=false`。`ReturnToMenu` 只在 `Completed` 时放行；`PumpBarrierTimeout`/`CloseTimeout`/`AlreadyIncomplete` 时保留当前画面并显示 `RETURN_TO_MENU_BLOCKED`。主动退出在任一种终态都可 `Application.Quit`，但先记录结果；不把 ActiveQuit 的放行解释为 Menu 可用。

### 4.3 主线程派发规则

1. `TableSession` 在泵线程同步触发 `SnapshotChanged`/`ReceiptResolved`；`SessionCoordinator` 的处理器**不得**直接调用 `UnityEngine`/TMP/UI，也不得把 `IGameSession` 或活 `PendingCommands` 交给 UI。
2. `SessionCoordinator` 是唯一 session owner：泵、状态读取、待决命令枚举、关闭都在同一 owner 线程；每次泵返回后，在 owner 线程构造 `SessionViewState`（复制标量、binding 标量、cursor/error、pending 摘要，并对三个 Wire 快照做 `Clone()` 深拷贝），记录 `(generation, seq)`，再 `dispatcher.Post`。
3. 不得把 `TableSnapshotChangedEventArgs` 的 Wire 快照引用直接交给 UI；`SessionViewState` 在构造时对 Player/Public/Room 调用 protobuf `Clone()` 深拷贝，嵌套 message/repeated 全部独立；`PendingCommands` 复制为新的只读列表/摘要。`TableSession.PendingCommands` 活列表和 owner 的 Wire message 都不能出现在 UI 对象图中。
4. `dispatcher.Update` 在主线程按入队顺序出队；每帧最多 128 个动作或 4 ms 预算，二者先到为准。
5. 出队后先比对 `generation`；旧会话事件直接丢弃并计数。
6. 单个 UI 处理器抛异常：记录 `UI_DISPATCH_HANDLER_EXCEPTION`，继续后续动作；不把异常抛回网络泵，不杀死会话。
7. 队列上限 1024；溢出时**失败关闭**：停止泵、标记 `UI_DISPATCH_OVERFLOW`、显示错误、请求/等待重连；禁止静默丢事件后继续 Ready。
8. UI 只读 `ISessionView.Current`（主线程发布的深隔离对象）和 `Changed` 事件；不允许在主线程读取 `IGameSession.State`/`LastError`/`PendingCommands`。
9. 所有 `IGameSession` 调用必须经过 `SessionCoordinator` 的单一 owner 队列；UI 不得直接持有 `TableSession`。P4.2 只读大厅没有 `SubmitAsync` 路径；P4.3 的命令入口必须在 P42-02 修复后加。

### 4.4 已知并发合同缺口（P42-02）

当前调用链：

```text
TableSessionRunner.RunAsync
  -> _session.OpenAsync(...)
  -> while(true) _session.PumpOnceAsync(...)
       -> _channel.ReceiveAsync(token)  // 可长时间等待
TableSession.SubmitAsync
  -> _outbox.SaveAsync(...)
  -> _commands.Add(...)
  -> _channel.SendAsync(...)
```

`TableSession` 内部没有 `lock`/`SemaphoreSlim`/`Monitor`/`Concurrent*`（证据 `10`，SHA-256 `B5D38D40248238445E68B63203CEB03F0A8236E04F501EAD9CEC4C28BC7BD7B1`）。接口又要求平台边界单线程。因此：

- 若 UI 在 runner 泵等待时调用 `SubmitAsync`，要么被阻塞到下一帧消息之后（大厅/牌桌输入延迟不可控），要么与泵并发读写 `_commands`/快照字段（未定义行为）。
- 通过取消 `ReceiveAsync` 来插入命令会关闭/打断 WebSocket，造成重连；不能作为常规方案。
- P4.2 只读大厅壳不需要提交业务命令，可以先做；P4.2 的命令路径和 P4.3 的第一个输入动作必须等 Client 侧给出可序列化的泵/提交合同。

本文件不修改 Client；修复责任归 Client/P5.4a owner，P4.2 只在 `SessionCoordinator` 预留单一操作队列，不把竞态藏进 UI。

### 4.5 退出、暂停、恢复、后台重连的主线程顺序

**A. 进入后台/暂停（Android `OnApplicationPause(true)`、桌面失焦可选）**

1. 主线程 `AppLifecycle.OnPause` 先置 `Paused=true`，关闭输入/点击，记录 `MonotonicMs` 与 `UtcNowMs`。
2. 不调用 `DisconnectAsync`，不主动取消会话；避免把“系统挂起”误判为业务断线。
3. `MainThreadDispatcher` 保留队列；若平台已冻结主线程，不假设 `Update` 会继续。
4. 记录 `APP_PAUSED`，不显示“已断线”。

**B. 恢复（`OnApplicationPause(false)`）**

1. 主线程重新应用 `Screen.safeArea`/方向/CanvasScaler（顺序：DisplayInfo → SafeAreaFitter → Canvas.ForceUpdateCanvases）。
2. `AppLifecycle` 通过 `SessionCoordinator.PostOwnerCommand(ResumeAfterPause)` 通知 owner；不直接调用 `OpenAsync`，也不在主线程读 `IGameSession`。
3. owner 线程读取 `IGameSession.State` 并发布新的 `SessionViewState`：
   - `Ready`：不重连；刷新 pending 摘要并显示“已恢复/仍有未确认命令”。
   - `Reconnecting`/`Disconnected`：按既有 runner 退避/票据合同重连；UI 显示“正在恢复”，不得显示“已连接”。
   - `Faulted`/`Closed`：显示稳定错误码 + 返回菜单；不自动新建会话。
4. owner 线程检查 pending 摘要中的 `DeliveryUnknown`/`NeedsReconciliation`：发布“结果未知，正在对账”；只允许 owner 调用 `ReconcilePendingAsync`，不自动 `RetryPendingAsync`。
5. 恢复后至少等待一帧，再重新开放输入；避免同一帧内点击触发两次。
6. 所有 UI 更新都在主线程；网络/对账仍在 owner 线程，经 dispatcher 回来。主线程不得枚举 `PendingCommands` 活对象。

**C. 桌面失焦/重新聚焦**

- 与暂停同样处理，但不强制停止泵，不自动重连；只有实际通道失败或心跳超时才进入 `Reconnecting`。
- 关闭窗口/Alt+F4 走 Quit 顺序，不依赖 `OnApplicationFocus(false)`。

**D. 退出到菜单/退出应用**

1. UI 发起 `AppRouter.ReturnToMenuAsync`：设置路由门，禁用输入。
2. 若当前有 Table 会话：调用**同一** `SessionCoordinator.ShutdownAsync("RETURN_TO_MENU")`（cancel→pump barrier→independent close），不直接 `CloseAsync`。
3. 只有结果为 `Completed` 才卸载 Table/Lobby 内容场景并加载 Menu；`PumpBarrierTimeout`/`CloseTimeout` 时停在当前画面，显示 `RETURN_TO_MENU_BLOCKED`，保留 quarantined 会话，不创建第二个会话。
4. 应用退出：主动路径 `await ShutdownAsync` 后按 4.2 结果分支 `Application.Quit`；`OnDestroy` 只兜底。Editor 用 `EditorApplication.isPlaying=false` 的测试路径。

**E. Android 返回键（设计）**

| 优先级 | 状态 | 返回动作 | 备注 |
|---:|---|---|---|
| 1 | 任意 Modal | 关闭最上层 Modal | 不穿透到底层画面；Modal+Transition/Paused 也先关 Modal |
| 2 | 场景/路由转场中 | 消费，忽略 | 防止加载中退出到半场景 |
| 3 | AppLifecycle Paused | 消费，不改变会话 | 恢复由 pause/resume 处理，不把 Back 当恢复 |
| 4 | Table（P4.3） | 打开暂停/退出确认 | 不直接退；第二次返回才确认 |
| 5 | Spectator（P4.4） | 返回 Lobby/Menu | 只读会话关闭 |
| 6 | Lobby | 返回 Menu | 若有打开中的本地会话，先走 4.5D 的 Shutdown |
| 7 | Menu 根 | 打开退出确认 | 确认后才 `Application.Quit` |
| 8 | Boot | 消费，忽略 | 不在 Boot 退出 |

实际 Android 返回事件的投递方式（Input System `Keyboard.escapeKey` 或原生 back）必须在真机验证；当前 `androidPredictiveBackSupport: 0`，没有返回处理代码。Editor 用 `IBackRequestSource` 假实现测试路由，不把 Editor 结果当 Android 通过。

### 4.6 P4.2-core 公共边界（最小可编译签名）

以下类型是未来 P4.2-core 的公共边界；本次不创建源文件，也不做 Unity 编译。命名空间、owner、取消/失败/释放语义如下，避免 core/B 靠猜类型交接。

**`Mahjong.Unity.UI.Session`（UI 程序集，P4.2-core）**：

```csharp
using System;
using System.Collections.Generic;
using Mahjong.Client;
using Mahjong.Contracts.Wire;

namespace Mahjong.Unity.UI.Session
{
    public sealed class SessionBindingView
    {
        public SessionBindingView(TableSessionBinding source)
        {
            if (source == null) throw new ArgumentNullException(nameof(source));
            SessionId = source.SessionId.Value;
            RoomId = source.RoomId.Value;
            TableId = source.TableId;
            Role = (int)source.Role;
            SeatId = source.SeatId;
            ConnectionEpoch = source.ConnectionEpoch.Value;
            OwnerEpoch = source.OwnerEpoch.Value;
            BindingEpoch = source.BindingEpoch.Value;
            ScopeId = source.Scope.ScopeId.Value;
            AccountId = source.Scope.AccountId;
        }

        public string SessionId { get; }
        public string RoomId { get; }
        public string TableId { get; }
        public int Role { get; }
        public int SeatId { get; }
        public ulong ConnectionEpoch { get; }
        public ulong OwnerEpoch { get; }
        public ulong BindingEpoch { get; }
        public string ScopeId { get; }
        public string AccountId { get; }
    }

    public sealed class SessionViewState
    {
        public SessionViewState(
            long generation,
            TableConnectionState state,
            TableSessionBinding? binding,
            PlayerSnapshot? playerSnapshot,
            PublicSnapshot? publicSnapshot,
            RoomUpdate? roomSnapshot,
            IReadOnlyList<PendingCommandSnapshot> pendingCommands,
            string? lastError)
        {
            Generation = generation;
            State = state;
            Binding = binding == null ? null : new SessionBindingView(binding);

            // Protobuf message properties are mutable. Clone() is a deep clone of
            // the message tree (nested messages and repeated fields included);
            // UI and owner must never share a message instance.
            PlayerSnapshot = playerSnapshot?.Clone();
            PublicSnapshot = publicSnapshot?.Clone();
            RoomSnapshot = roomSnapshot?.Clone();

            if (pendingCommands == null)
            {
                PendingCommands = Array.Empty<PendingCommandSnapshot>();
            }
            else
            {
                var copy = new List<PendingCommandSnapshot>(pendingCommands);
                PendingCommands = copy.AsReadOnly();
            }
            LastError = lastError;
        }

        public long Generation { get; }
        public TableConnectionState State { get; }
        public SessionBindingView? Binding { get; }
        public PlayerSnapshot? PlayerSnapshot { get; }
        public PublicSnapshot? PublicSnapshot { get; }
        public RoomUpdate? RoomSnapshot { get; }
        public IReadOnlyList<PendingCommandSnapshot> PendingCommands { get; }
        public string? LastError { get; }
    }

    public interface ISessionView
    {
        SessionViewState Current { get; }
        event EventHandler<SessionViewState>? Changed;
    }
}
```

- owner：`SessionCoordinator`（App）。它只在 owner 线程读取活 session，构造 `SessionViewState`，在主线程通过 dispatcher 触发 `Changed`。
- **隔离语义**：`SessionViewState` 构造时对 `PlayerSnapshot`/`PublicSnapshot`/`RoomUpdate` 调用 protobuf `Clone()`，得到完整深拷贝（嵌套 message、repeated 字段、集合都在新树中）；`Binding` 投影为 `SessionBindingView` 标量副本；`PendingCommands` 复制为新的只读列表。UI 与 session 不共享任何可变 message/binding 实例。
- **写回边界**：`SessionViewState` 的顶层属性只有 getter；深拷贝内的 protobuf message 仍有生成的可写属性，因此 UI 合同是“只能修改自己的副本，禁止写回/缓存到 session”；`SessionCoordinator` 只向 UI 发布新副本，绝不接受 UI 的 snapshot 作为输入。若将来要求对象图本身不可写，必须另做只读 DTO 投影，不能把 `Clone()` 说成不可变。
- 失败/取消：`CreateAsync` 的失败由 App 统一映射为 UI 错误码；`ISessionView` 不暴露异常对象。
- 释放：`ISessionView` 无 Dispose；由 AppRoot 统一释放，UI 只取消订阅。

**`Mahjong.Unity.UI.Navigation`（UI 程序集，P4.2-core）**：

```csharp
namespace Mahjong.Unity.UI.Navigation
{
    public interface IAppNavigation
    {
        void OpenLobby();
        void BackToMenu();
        void RequestQuit();
    }
}
```

- owner：App 的 `AppRouter`/`AppLifecycle` 实现；Menu/Lobby 只依赖该接口，不直接 `SceneManager`，也不引用 App 程序集。
- 失败：路由忙时 `OpenLobby`/`BackToMenu` 返回 void、记录 `NAV_BUSY`，不抛异常；`RequestQuit` 只打开确认，不直接退出。
- 释放：无 Dispose；路由取消由 AppRoot 负责。

**`Mahjong.Unity.Platform`（Platform 程序集，P4.2-core）**：

```csharp
namespace Mahjong.Unity.Platform
{
    public interface IBackRequestSource
    {
        bool TryConsumeBack();
    }
}
```

- owner：`UnityBackRequestSource`（P4.2-core）。Android 使用原生/Unity 返回事件适配；桌面返回 `false`。每次物理返回只允许一次 `true`；主线程调用。
- 失败：无输入源时返回 `false` 并记录一次 `BACK_SOURCE_UNAVAILABLE`；不得抛异常。
- 释放：无 Dispose；AppRoot 在销毁时停止轮询。

**`ISessionCommands`（P4.3，不属于 P4.2-core）**：在 P42-02 解决前不冻结命令签名；P4.2 只交付 `ISessionView` 与 `IAppNavigation`。P4.3 必须使用同一 owner 队列，不能从 UI 直接构造 `ProtocolCommand`，也不能绕开 requestId/scope。若 P42-02 未解决，P4.3 的首个输入保持 `BLOCKED`，不以假接口充数。

## 5. 场景、导航与平台工厂

### 5.1 目标场景序列

| 序号 | 场景 | Build Settings | 进入条件 | P4.2 状态 |
|---:|---|---|---|---|
| 0 | `Assets/Scenes/Boot.unity` | enabled | 进程启动 | 目标 |
| 1 | `Assets/Scenes/Menu.unity` | enabled | Boot 成功 / 从 Lobby 返回 | 目标 |

| 3 | `Assets/Scenes/Table.unity` | 未来 P4.3 | Lobby 且 `ISessionCommands` 可用 + LocalHost 可用 | **不实现** |
| 4 | `Assets/Scenes/Spectator.unity` | 未来 P4.4 | 观战票据/公开流 | **不实现** |

P4.2 只交付 0-2；Table/Spectator 只定义接入边界，不创建场景。当前 Build Settings 只有 `SampleScene`，未来必须替换为 0-2（SampleScene 可保留在工程中但不启用）。

### 5.2 场景切换规则

1. 统一使用 `SceneManager.LoadSceneAsync(sceneId, LoadSceneMode.Single)`；AppRoot 已 `DontDestroyOnLoad`。
2. `AppRouter` 持有 `_transitioning` 与 `_pendingScene`；重复点击同一目标只保留一个请求；不同目标按最后请求排队，禁止并行 `LoadSceneAsync`。
3. 场景加载前关闭当前画面的输入/动画；加载完成后等一帧再启用，避免 `Awake` 中重复订阅。
4. 加载失败：记录 `SCENE_LOAD_FAILED:{scene}:{error}`，回到 Menu；不无限重试。
5. `Boot` 只进入一次；`ReturnToMenu` 不重新加载 Boot。
6. Menu→Lobby 的边界：Lobby 可以显示“本地宿主未接入（P4.1）”并禁用“开始本地对局”；这允许 P4.2 在 P4.1 未完成时验收导航，但**不是**本地对局通过。
7. Lobby→Table 的边界：只有 `ITableChannelFactory.CreateAsync(TableTransportKind.Local)` 返回可用 `ITableChannel`、P4.3 的 `ISessionCommands` 已实现、P4.1 合同已交接时才启用；P4.2 不创建 Table 场景、不伪造对局。

### 5.3 Duplicate Bootstrap / Duplicate EventSystem 防护

1. `AppRoot` 静态 `Instance` + `FindObjectsOfType<AppRoot>(true)` 双重检查；重复对象立即 `Destroy`，只记录一次。
2. `SubsystemRegistration` 在每次进入 Play Mode 前重置静态字段（domain reload 被禁用时尤其重要）。
3. 内容场景的 `SceneGuard` 在 `Awake` 检查 `AppRoot.Instance`；没有根时记录 `BOOT_REQUIRED` 并 `LoadSceneAsync(Boot, Single)`，不创建“半个根”。
4. 唯一持久 `EventSystem` 由 AppRoot 创建；内容场景如误带 EventSystem，`Awake` 禁用并记录，避免双输入模块。
5. 场景 YAML 静态检查：Menu/Lobby/Table/Spectator 不允许出现 `GameBootstrapper` 或 `EventSystem` 的脚本 GUID；Boot 只允许一个 `GameBootstrapper`。
6. 测试：连续加载 Boot→Menu→Lobby→Menu 三次，断言 AppRoot 数量始终 1、EventSystem 数量始终 1、静态 generation 不重复。

### 5.4 平台 `ITableChannel` 工厂

**精确接口已存在**，P4.2 不得另造同名不同签名的接口：

```csharp
public interface ITableChannel
{
    bool IsOpen { get; }
    Task OpenAsync(TableChannelConnectRequest request, CancellationToken cancellationToken);
    Task SendAsync(ReadOnlyMemory<byte> wireEnvelope, CancellationToken cancellationToken);
    Task<ReadOnlyMemory<byte>> ReceiveAsync(CancellationToken cancellationToken);

```

**工厂精确签名（P4.2-core，Platform 程序集）**：

```csharp
using System.Threading;
using System.Threading.Tasks;
using Mahjong.Client;

namespace Mahjong.Unity.Platform
{
    public enum TableTransportKind
    {
        Local = 0,
        Wss = 1
    }
```

**App 的不可用实现（P4.2-core，App 程序集）**：

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;
using Mahjong.Client;
using Mahjong.Unity.Platform;

namespace Mahjong.Unity.App
{
    public sealed class LocalTableUnavailableException : Exception
    {
        public const string ErrorCode = "LOCAL_HOST_UNAVAILABLE";
        public LocalTableUnavailableException(string message) : base(message) { }
    }

    public sealed class UnavailableLocalTableChannelFactory : ITableChannelFactory
    {
        public Task<ITableChannel> CreateAsync(
            TableTransportKind kind,
            CancellationToken cancellationToken)
        {
            if (cancellationToken.IsCancellationRequested)
            {
                return Task.FromCanceled<ITableChannel>(cancellationToken);
            }

            if (kind != TableTransportKind.Local)
            {
                return Task.FromException<ITableChannel>(
                    new NotSupportedException("WSS transport is not part of P4.2-core."));
            }

            return Task.FromException<ITableChannel>(
                new LocalTableUnavailableException("Local host is not available in P4.2-core."));
        }
    }
}
```

**工厂边界**：

- `Mahjong.Unity.Platform` **只**定义 `ITableChannelFactory` 和 `TableTransportKind`；不得包含 `UnavailableLocalTableChannelFactory` 或 `LocalTableUnavailableException`。P4.2 只需要 Local 分支，WSS 分支属于 P5.4b。
- `Mahjong.Unity.App` 定义 `UnavailableLocalTableChannelFactory`（实现 Platform 接口）和 `LocalTableUnavailableException`；P4.2-core 不引用 `Mahjong.LocalHost`。
- P4.2-B 的 `LocalTableChannelFactory` 也在 App，实现**同一个** `ITableChannelFactory`；只把 `Mahjong.LocalHost.dll` 加入 App 的 `precompiledReferences`，不改 UI/Platform 公共签名。
- 取消/失败优先级：**预取消 token → `Task.FromCanceled`**；**非 Local transport → `NotSupportedException`**；**Local 但 P4.1 未接入 → `LocalTableUnavailableException`**。B 适配器必须保留同一优先级，不能把预取消变成 Unavailable。
- `Mahjong.Unity.UI/Table/Spectator` 只接收 `ISessionView`，不知道工厂、LocalHost、TableRuntime；`ITableChannel` 只由 AppComposition 持有。
- 本地工厂的返回值必须是 `ITableChannel`；P4.1 的构造函数/选项类型不出现在 UI/Platform 的公开签名中。P4.2 不假定 `LocalTableHost` 的构造方式；以 P4.1 实际交付的工厂为准。
- `ITableChannel` 没有 `Dispose`；`AppComposition` 在 `CloseAsync` 后按 `IAsyncDisposable`/`IDisposable` 能力释放，不把 Dispose 加进接口。
- 本地票据：`ITableTicketProvider` 返回进程内短期占位票据；不得写日志/outbox/磁盘。`TableChannelConnectRequest` 只要求非 null，本地实现可忽略内容，但不得把票据写入 URL/日志。

**P4.2-B 交接点**（不要求 P4.1 先完成）：

1. P4.1 交付一个可由 App 薄适配的 `Task<ITableChannel>` 工厂；P4.2 的 `LocalTableChannelFactory` 只做构造/注入，不定义 P4.1 的 options/schema。
2. P4.1 的 `ILocalSaveStore`/`LocalSave` schema 由 P4.1 定义；P4.2 只提供 `UnityAppPaths.LocalSaveDirectory`，不读/写 schema。
3. P4.2-B 只在 App 的 `precompiledReferences` 增加 `Mahjong.LocalHost.dll`；UI/Table/Spectator/Platform 不增加。
4. 在 P4.1 未完成时，`UnavailableLocalTableChannelFactory` 返回稳定错误 `LOCAL_HOST_UNAVAILABLE`，UI 禁用开始按钮；不得用空壳 DLL 或假本地对局冒充。

## 6. 共享字体、皮肤与显示/输入设计

### 6.1 设计坐标与安全区

**唯一坐标方案（P4.2 冻结）**：

- `CanvasScaler.uiScaleMode = ConstantPixelSize`；不要同时使用 `ScaleWithScreenSize` 和 `AspectRatioFitter`，避免出现两套互相覆盖的缩放。
- `scale = min(Screen.width / 1280f, Screen.height / 720f)`；把该值写入 `CanvasScaler.scaleFactor`。`DesignRoot` 的 `RectTransform` 固定 `1280×720`、锚点居中；不拉伸 `DesignRoot`。
- 内容屏幕矩形：

```text
contentW = 1280 * scale
contentH = 720 * scale
contentX = (Screen.width  - contentW) / 2
contentY = (Screen.height - contentH) / 2
```

- 背景层铺满屏幕；交互内容只在 `contentRect`（16:9）内；`contentRect` 外是留白/背景，不拉伸。
- 示例（纯数学，未运行 Unity）：

| 屏幕 | scale | 内容屏幕矩形 | 留白 |
|---|---:|---|---|
| 1280×720 | 1.000 | (0,0,1280,720) | 无 |
| 1920×1080 | 1.500 | (0,0,1920,1080) | 无 |
| 1024×768 | 0.800 | (0,96,1024,576) | 上下各 96 px |
| 2560×1080 | 1.500 | (320,0,1920,1080) | 左右各 320 px |
| 2340×1080 | 1.500 | (210,0,1920,1080) | 左右各 210 px |

- 安全区：先把 `Screen.safeArea` 与实际内容屏幕矩形求交，再逆变换到设计坐标；不是把全屏 safeArea 直接归一化到 `DesignRoot`：

```text
safeScreen = Intersect(Screen.safeArea, contentRect)
if safeScreen.width <= 0 or safeScreen.height <= 0: safeScreen = contentRect
safeDesign = {
  x = (safeScreen.x - contentX) / scale,
  y = (safeScreen.y - contentY) / scale,
  w = safeScreen.width  / scale,
  h = safeScreen.height / scale
}
clamp(safeDesign, 0, 1280/720)
```

- 指针逆映射：`design = ((screen.x - contentX) / scale, (screen.y - contentY) / scale)`；必须命中 `safeDesign` 才算可点击；屏幕坐标与 Canvas 坐标均按左下原点处理，若平台事件为上原点，先翻转 y。
- `SafeAreaRoot` 只应用 `safeDesign` 的 anchors/offset；最小内缩 24 设计单位；所有可点击元素必须在 `safeDesign` 内。
- 触控目标：设计基线 `88×88`；同时满足 44dp 下限：

```text
minDesignTarget = max(88, 44 * Screen.dpi / 160 / scale)   // Screen.dpi > 0
minDesignTarget = 88                                      // Screen.dpi <= 0
```

  88 设计单位不等于固定 44dp；dp 口径按上式单独计算。示例：1080p/约 400dpi、scale=1.5 时，88×1.5px≈48dp，直接采用 88 设计单位即可。
- 正文字号 ≥28 设计单位、按钮 ≥30、标题 ≥56；字号是设计单位，不声明等于固定 dp；真实设备可读性用截图/人工矩阵验证。
- 横屏策略 **P4.2 设计冻结为 AutoRotation 且只允许左右横屏**：目标 `defaultScreenOrientation=5`，`allowedAutorotateToPortrait=0`、`allowedAutorotateToPortraitUpsideDown=0`、`allowedAutorotateToLandscapeLeft=1`、`allowedAutorotateToLandscapeRight=1`。当前 `4` + 四个 `1` 是待修正的现状，不是目标。
- `androidRenderOutsideSafeArea=1` 保留画到刘海区域的能力，但所有交互内容按 `safeDesign` 内缩；不把“画到边缘”当成“内容可在 cutout 下”。`androidPredictiveBackSupport=0` 保留传统返回；P4.2 不依赖预测返回动画，真机验证实际事件。

### 6.3 输入模型

**`MahjongUi` 动作集是唯一权威 schema**（`InputSystem_Actions.inputactions` 实施时按此改名；本次不创建资产）：

| Action | type / controlType | 精确 bindings | interaction | 触发阶段 | 唯一消费者 |
|---|---|---|---|---|---|
| `Navigate` | `Value` / `Vector2` | 2DVector：`<Keyboard>/upArrow`、`downArrow`、`leftArrow`、`rightArrow`；`<Gamepad>/leftStick`、`<Gamepad>/dpad` | none（连续 Value） | `performed`（UGUI 自行 repeat） | `InputSystemUIInputModule.move` |
| `FocusNext` | `Button` / `Button` | `<Keyboard>/tab` | `Press` | `performed` | `FocusRouter` |
| `FocusPrevious` | `Button` / `Button` | `OneModifier#1(<Keyboard>/leftShift + <Keyboard>/tab)`；`OneModifier#2(<Keyboard>/rightShift + <Keyboard>/tab)` | `Press` | `performed` | `FocusRouter` |
| `Submit` | `Button` / `Button` | `<Keyboard>/enter`、`<Keyboard>/space`、`<Gamepad>/buttonSouth` | `Press` | `performed` | `InputSystemUIInputModule.submit` |
| `Cancel` | `Button` / `Button` | `<Keyboard>/escape`（仅桌面；Android 启动时 `Disable()`） | `Press` | `performed` | **只给 `BackRouter`**；`InputSystemUIInputModule.cancel = None` |
| `Point` | `PassThrough` / `Vector2` | `<Pointer>/position` | none | `performed` | `InputSystemUIInputModule.point` |
| `LeftClick` | `PassThrough` / `Button` | `<Mouse>/leftButton`、`<Touchscreen>/primaryTouch/press` | `Press` | `performed` | `InputSystemUIInputModule.leftClick` → `Button.onClick` |
| `ScrollWheel` | `PassThrough` / `Vector2` | `<Mouse>/scroll` | none | `performed` | `InputSystemUIInputModule.scrollWheel` |
| `Back` | **不是 InputAction** | 无 | 无 | 平台事件 | `IBackRequestSource` → `BackRouter` |

冻结规则：

1. `Submit` 不绑定鼠标/触控；指针激活只走 `LeftClick` → `Button.onClick`。一个物理点击最多一次 `onClick`；`Submit` 不进入指针路径。
2. `Cancel` 只接桌面 Esc，且**不接** `InputSystemUIInputModule.cancel`；只由 `BackRouter` 用 `WasPerformedThisFrame` 消费。Android 上禁用 `Cancel` action，只由 `IBackRequestSource` 产生 `Back`，不允许两者同时订阅。
3. `BackRouter` 是唯一返回消费者，优先级固定：`Modal > Transition > Paused > 当前场景返回 > Menu 退出确认`。每次物理事件只消费一次；未消费才向下传递。`Paused` 状态的返回事件只消费，不改变已暂停的会话。
4. 指针去重：按下后移动超过 **8 设计单位**（`EventSystem.pixelDragThreshold = max(1, round(8 * scale))`）视为拖动，不触发点击；触摸只取主触点，额外手指不激活按钮；双击是两次独立按下/抬起，不允许同帧重复派发。
5. 键盘去重：`Submit`/`Cancel`/`FocusNext`/`FocusPrevious` 只在 `WasPerformedThisFrame` 消费一次；按住不重复；`Back` 只由平台源产生一次。
6. `Pause` 不是 InputAction；应用暂停/恢复由 `AppLifecycle` 处理。暂停期间不产生 `Submit`/`LeftClick`；恢复后先重算 `safeDesign`/命中，再开放输入。
7. 当前模板的 `Player` 动作（Move/Look/Attack...）不属于 P4.2 UI；`MahjongUi` 不保留这些动作。`activeInputHandler=1` 表示仅新 Input System，不能依赖旧 `Input.GetKeyDown`。
8. `FocusRouter` 的归属文件为 `Assets/Scripts/UI/FocusRouter.cs`（见 §10.4）。`FocusNext`/`FocusPrevious` 只在当前画面内按固定 Selectable 列表循环；`Tab` 走 next，`Shift+Tab` 走 previous；焦点不进入隐藏/禁用/非安全区元素。`Navigate` 不接管 Tab。
9. 指针点击生命周期：按下只 arm，不计数；主触点释放且仍在同一 Selectable 内、累计移动 ≤8 设计单位才产生一次 `onClick`；按住不产生点击；移动 >8、`PointerCancel` 取消 arm。`UiInputLifecycle.OnPause`/`OnTransition`/`OnFocusLost` 必须进入**同一个** `CancelArm()`：`arm=false`、`primary=null`、`pressGeneration++`、`accept=false`；`OnResume`/`TransitionEnd` 只恢复 `accept=true`，不恢复旧 arm。释放时还必须匹配 `pressGeneration`，因此 down→pause/transition/focus-lost→resume/transition-end→up 仍不点击。额外手指/第二 pointer 不 arm、不激活；同帧按下+释放仍只允许一次。
10. 平台源去重：桌面 `Cancel` 只接受 `Keyboard.escape`；Android `Back` 只接受 `IBackRequestSource`。`BackRouter.Handle(source)` 遇到不匹配的 source 返回 `REJECTED_WRONG_SOURCE`，不得静默忽略后继续消费；同一物理事件只产生一次路由。
11. `BackRouter` 的归属文件为 `Assets/Scripts/UI/BackRouter.cs`（见 §10.4），不是 App/Platform 内的隐藏组件。
