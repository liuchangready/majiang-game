## 2. 数据源与字段语义

### 2.1 只读数据源

| 投影字段 | 来源 |
|---|---|
| 四席公开手牌数/河/副露/立直 | `PlayerSnapshot.PublicView.Board.Players`（或匹配绑定 session 的 `PublicSnapshot.View.Board.Players`） |
| 场地/场况/宝牌/分数/最后舍牌/暂停/整场摘要 | `PublicMatchView.Board`、`.Session`、`.Paused`、`.SettlementRoundId` |
| 本席手牌/摸牌/袖牌/owner melds/振听/舍牌历史 | `PlayerSnapshot.PrivateView` |
| 本席决策/候选/control epoch/剩余 deadline | `PlayerPrivateView.Decision`、`.LegalActions` |
| 三绝技/准备 | `PrivateCheatView.TileMark/SleeveBloom/OffTurnSleeveBloom/SleeveBloomReservation/BeamSwap/Preparation/WindowId` |
| 时钟 | `PublicMatchView.Clocks` |
| 身份/绑定/generation | `SessionViewState.Generation/State/Binding/RoomSnapshot/PendingCommands` |

### 2.2 合同语义（本模型严格遵守）

1. `PlayerPrivateView.ClosedTiles` **不包含**摸牌；`DrawnTileId` 是独立字段。Wire 已校验两者不重复；本模型再次校验并保持两个独立字段，`PhysicalHandTileCount = ClosedTiles.Count + (Drawn != null ? 1 : 0)`。
2. `PlayerPublicView.HandCount` 是公开计数，包含本席摸牌；它是数量，不是 tile id 列表。模型不把计数展开为虚构实体。
3. 对手暗杠在公开流只有 `ConcealedMeldView{type=CLOSED_KAN,tile_count=4,from_seat=-1}`；模型映射为 `PlayerMeldState{IsPlaceholder=true, TileIds=[]}`。绝不生成四张 id。
4. 本席 `PrivateView.OwnerMelds` 含暗杠四张实体；`PlayerTableViewState.OwnMelds` 与 `PlayerSeatState.Melds` 是同一个不可变列表，公开侧的同一组 open meld 不再二次渲染。`MeldsAreOwnerOnly=true` 明确标记。
5. 同一 136 实体在本席可见集合内去重：`ClosedTiles`、`DrawnTileId`、`SleeveTiles`、`OwnerMelds[].TileIds` 任一重复即 fail-closed，`Own=null`，并记录 `PRIVATE_TILE_DUPLICATED`。
6. 公开副露类型未知时跳过并记录 `PUBLIC_MELD_TYPE_UNKNOWN`；不把未知枚举当作事实。
7. 本席公开 `HandCount` 与实际私有实体数不一致时记录 `OWN_HAND_COUNT_MISMATCH`，不修补任一侧。
8. `player_snapshot`、`public_snapshot` 同时存在但 `round_id` 不一致时 fail-closed，清除私有与公开数据并记录 `PUBLIC_ROUND_MISMATCH`。

### 2.3 身份/同步校验

以下任一条件不满足时，`Own=null`，私有候选/三绝技/袖牌/控制不出现：

- `SessionViewState.State == Ready`；
- `Binding != null`、`Role == Player`、`Seat ∈ 0..3`；
- `PlayerSnapshot.SessionId == Binding.SessionId`；
- `PrivateView.Seat == Binding.SeatId`；
- `RoomSnapshot`（若存在）的 `room_id/session_id` 与绑定一致；
- `PlayerSnapshot` 与 `PublicSnapshot`（若同时存在）round 一致。

观战绑定：即使误带 `PlayerSnapshot`，也只记录 `SPECTATOR_PLAYER_SNAPSHOT_IGNORED`，不映射 `Own`/候选/袖牌/账本/费用，并返回 `CanSubmit=false`。不实现另一套观战产品。

### 2.4 不可表示字段（明确缺口）

`PlayerTableViewState.Gaps` 固定包含以下结构性缺口（稳定码；不冒充字段）：

- `DEAD_WALL_IDENTITY_NOT_PUBLIC`：公开流只有 `wall_remaining`，没有死山身份/顺序。
- `SEAT_CONTROL_VIEW_NOT_REPRESENTABLE`：Wire 没有独立座位控制者视图；`DecisionView.control_epoch` 只在存在决策时可见。
- `LEGAL_ACTION_MELD_TYPE_NOT_REPRESENTABLE`：`LegalActionView` 只有 `action_type/option_id/tile_ids`，没有 meld type/kan type。
- `ABSOLUTE_DEADLINE_NOT_REPRESENTABLE`：Wire 只有服务端剩余毫秒，没有绝对 deadline。
- `VISIBLE_EVENTS_NOT_EXPOSED_BY_SESSION_VIEW`：`ISessionView`/`TableSnapshotChangedEventArgs` 目前不暴露 `visible_events`。
- `SHUFFLE_TARGET_CANDIDATES_NOT_REPRESENTABLE`：`ShufflePreparationView` 只有当前 `target`，没有可选 target 列表。
- `BEAM_SLOT_KIND_NOT_IN_COMMAND`：命令只有 `targetSlot`，没有 `slot_kind/slot_index` 字段。

条件性缺口：`OWNER_MELDS_MISSING_FOR_PUBLIC_MELDS`、`PUBLIC_SEAT_MISSING`、`OWN_HAND_COUNT_MISMATCH`、`PRIVATE_TILE_DUPLICATED`、`PUBLIC_MELD_TYPE_UNKNOWN` 等。

## 3. 命令意图与交互状态

### 3.1 命令矩阵

所有 `ProtocolCommand` 的 `request_id`、`request_scope_id` 由现有 owner/caller 通过 `TableCommandOwnerContext` 提供；本范围不生成替代 id。`expected_state_version` 默认取最新确认快照的 `state_version`，`owner_epoch` 默认取绑定 `OwnerEpoch`。`roundId/decisionId/controlEpoch` 仅在该命令合同适用时填入。

| Intent | CommandKind | canonical payload 字段 | 元数据/门控 |
|---|---|---|---|
| `SubmitAction` | `SubmitAction` | 1 roundId, 2 decisionId, 3 controlEpoch, 4 actionType, 5 optionId?, 6 tileIds? | 必须来自当前 `DecisionView.actions[Index]`；旧 decision/epoch/round 拒绝；不推导役种/费用 |
| `SubmitTileMark` | `SubmitTileMark` | 1 roundId, 2 decisionId, 3 controlEpoch, 4 四个互异 tileIds | 必须从 `TileMark.selectable_tile_ids` 选满 4 个；无 decision 则不可提交 |
| `SubmitSleeveBloom` | `SubmitSleeveBloom` | 1 roundId, 2 decisionId, 3 controlEpoch | 需当前 decision；已存在 immediate offer 时拒绝重复激活 |
| `SubmitSleeveBloomChoice` | `SubmitSleeveBloomChoice` | 1 offerId, 2 choice | 只接受 immediate offer；不写 roundId；`ProtocolCommand.RoundId=null` |
| `SubmitSleeveBloomOffTurn` | `SubmitSleeveBloomOffTurn` | 1 roundId, 2 decisionId, 3 controlEpoch, 4 windowId | 需 `PrivateCheatView.window_id`；已有 off-turn offer/reservation 时拒绝 |
| `SubmitSleeveBloomOffTurnChoice` | `SubmitSleeveBloomOffTurnChoice` | 1 offerId, 2 choice | 只接受 off-turn offer；不写 roundId |
| `SubmitBeamSwap` | `SubmitBeamSwap` | 1 roundId, 2 decisionId, 3 controlEpoch | 需当前 decision；已有 beam offer 时拒绝重复激活 |
| `SubmitBeamSwapChoice` | `SubmitBeamSwapChoice` | 1 offerId, 2 choice, 3 handTileId?, 4 targetSlot? | `SWAP` 必须从 `selectable_hand_tile_ids` 与当前候选 slot 选择；`KEEP_ORIGINAL` 省略 3/4；不写 roundId |
| `SubmitShufflePlan` | `SubmitShufflePlan` | 1 roundId, 2 target, 3 seeThrough | `target` 只取确认 `Preparation.Target`；`seeThrough=true` 仅当确认 `see_through_enabled`；不计算费用 |
| `NextRound` | `NextRound` | 1 roundId | 仅 `phase == ROUND_END` 且未 finished |
| `ClaimControl/ReleaseControl` | — | 合同缺陷，见 §5.1 | 不生成非法/替代 payload；fail-closed |

`LegalActionView` 没有 meld type/kan type，故 `SubmitAction` 不填 `meldType`（字段 7）；`option_id` 保持服务端原值，供服务端解释。不同命令的 canonical 字段 1 含义不同（roundId 或 offerId）；工厂按 CommandKind 写对应字段，不把 `offerId` 当 `roundId`，选择类命令的 `ProtocolCommand.RoundId` 为 `null`。

### 3.2 选择与 pending

- `TableInteractionState` 只接受最新 `PlayerTableViewState` 的候选/offer/slot；选择时再次校验 `DecisionId/ControlEpoch/RoundId`。
- 同一逻辑意图（kind + round/decision/offer/window + action/choice/tile 集合）有相同 `TableIntentKey`；重复点击返回 `ALREADY_PENDING`，不会创建第二个 pending。
- pending 存在时不同意图返回 `PENDING_CONFLICT`；不会生成第二个 request。
- `MarkDeliveryUnknown`/`ApplyClientOutcome(Unknown)` 保留 pending 并令 `NeedsReconciliation=true`。只有 `Applied/Recorded/Rejected/Abandoned` 或显式基线/身份重置清除 pending；动画消费、队列出队、倒计时归零都不会清除或替代 Client 回执。
- 新 decision/offer/slot/tile-mark 候选/准备状态变化清除旧选择，但不清除仍在 Client 对账中的 pending；新身份/基线重置清除 pending。
- 失焦、暂停、`OnBaselineReset`、身份切换清除旧选择；过期选择在下次选择/构建时立即失效。
- 截止显示：`PlayerCountdown` 保存服务端剩余毫秒与本地单调观测时刻；`RemainingMilliseconds(now)` 只做展示倒计时，不修改权威 deadline，不锁提交/刷新。决策/offer/准备在动画仍排队时到期，`BuildIntent` 立即返回过期码。

### 3.3 API 调用例

```csharp
var mapper = new PlayerTableProjectionMapper(clock);          // ITableClientClock
var view = mapper.Project(sessionView);                       // SessionViewState
Assert.True(view.Identity.IsPrivateAuthorized);

var factory = new TableCommandIntentFactory(clock);
var interaction = new TableInteractionState(factory);
interaction.ApplyConfirmedView(view);

interaction.SelectAction(view.Own!.Decision!.Candidates[0]);
// 或 SelectDiscardTile(tileId) / SelectTileMark(ids) / SelectSleeveBloom(...) /
//    SelectBeamSwap(...) / SelectPreparation(seeThrough)

var owner = new TableCommandOwnerContext(
    new RequestId("existing-request-id"),
    new RequestScopeId(view.Identity.ScopeId));
TableInteractionOutcome result = interaction.BuildIntent(TableIntentKind.SubmitAction, owner);
if (result.Accepted && result.Intent != null)
{
    // 现 owner 交给 TableSessionOperationQueue；本模型不发送。
    await queue.EnqueueSubmit(result.Intent.Command, cancellationToken).Completion;
}

// 真实 Client 回执/对账后：
interaction.ApplyClientOutcome(TablePendingOutcome.Applied);
```

## 4. 确认动画队列

`ConfirmedAnimationQueue` 只接受：

- `AcceptConfirmedBaseline(PlayerTableViewState current)`：确认全量基线；清除旧动画/去重键，记录确认上下文。
- `AcceptConfirmedDifference(previous, current, isFullBaseline)`：两个已确认投影之间的差异；不解析网络包、不重建同步引擎。
- `AcceptConfirmedEvents(ConfirmedAnimationContext, IReadOnlyList<ConfirmedVisibleEvent>, TableAnimationAudience)`：owner 已确认的 typed 可见事件；本范围不解析原始事件 bytes。

身份字段分离：

- `state_version` 只用于快照差异/重复判断；
- `event_seq + event_ordinal` 只用于事件顺序/去重；
- `stream_version` 与 `projection_seq` 只保存在上下文，允许滞后/重复，不作为 fence；
- `generation/session/room/round/binding_epoch` 是确认上下文身份。

行为：

- 默认容量 64（1..4096），超出丢弃最旧项并累计 `DroppedCount`；重复键不重播。
- 非基线差异旧 generation/binding/session/round 拒绝；新 binding/session 只允许通过新的全量基线建立。
- 全量基线清除动画/去重键；同一 generation 下旧 binding 或旧 state_version 的基线拒绝；更高 binding 或更高 generation 允许重连重置。
- 快照差异只比较已确认前/后事实：河牌凭 `called_tile_id/from_seat` 进入新副露、Pon→AddedKan 等同席超集升级属于合法迁移；无确认去向的移除仍 `NON_MONOTONIC_SNAPSHOT` 并清空可视项，不做乐观位置回滚。
- `previous` 必须是当前已确认视图（相同 generation/session/room/round/binding/state/event/stream/projection）；旧 previous 拒绝。快照 event 上界与“已播放事件”游标分离，快照不吞掉尚未播放的 typed 事件；同一 `discard/<seat>/<tile>` 在快照与事件两条路径共享语义去重键。
- 私有事件只允许本席 player audience，且 audience 必须匹配确认基线的 role/seat/private-authorized；`OwnerSeat` 必须显式 0..3 且等于 audience；观战/他席/缺 owner 全部拒绝。本席暗杠动画 `IsPrivate=true, OwnerSeat=seat`；公开暗杠仍是 identity-free 占位。`PublicEventEnvelope` 不含的私有事件类型若标 Public 也被拒绝（`EVENT_VISIBILITY_MISMATCH`）。
- 动画项只是可视流水线数据；确认状态、交互门控、deadline 和提交都不等待动画。

## 5. 合同缺陷与不可表示项

以下为**合同/上游问题**，本子范围不私改 Contracts/Wire；已 fail-closed 或明列，不得冒充已解决。

### 5.1 BLOCKER：ClaimControl/ReleaseControl canonical 字段冲突

- 位置：`dotnet/src/Mahjong.Contracts/ProtocolCommand.cs` 的 `CommandPayloadFields.ExpectedControlEpoch` 与 `RoundIdField` 均为 `1`；`CommandPayloadValidator.Validate` 对 `ClaimControl/ReleaseControl` 同时 `RequireUInt64(field 1)` 与 `RequireString(field 1)`。
- 实际：`CanonicalPayloadWriter` 要求字段号严格递增/唯一，无法同时写入 uint64 与 string 到字段 1；任何控制命令都无法通过验证。
- 本范围行为：`TableCommandIntentFactory.CreateClaimControl/CreateReleaseControl` 与 `TableInteractionState` 返回 `CONTROL_PAYLOAD_FIELD_COLLISION`，不生成非法/替代 payload，不创建 pending。
- 复现：`TableCommandIntentFactoryTests.ControlCommandsFailClosedOnFrozenPayloadFieldCollision`。
- 修复要求：合同 owner 为 `expectedControlEpoch` 分配独立字段号并重新冻结/回归；本任务不改 Wire。修复前 P4.3-B 不得展示可用控制按钮。

### 5.2 BLOCKER：Contracts canonical string 读取保留长度前缀

- 位置：`dotnet/src/Mahjong.Contracts/CanonicalPayloadDigest.cs` 的 `CanonicalFieldValue.AsString`。
- 实际：官方 writer 写入 4 字节 little-endian 长度前缀，`AsString` 返回“长度前缀 + 文本”；例如 `roundId="round-p43"` 读取为 `"\t\0\0\0round-p43"`。`CommandPayloadValidator` 只校验非空，因此当前不会在该 C# 校验器处失败。
- 本范围行为：生产 payload 仍使用官方 `CommandPayloadFactory/CanonicalPayloadWriter` 的原始字节，不重写、不补丁；测试用 `TestPayload` 仅做逻辑字段比对并显式保留该缺陷探针 `KnownContractDefect_OfficialCanonicalStringReaderKeepsLengthPrefix`。真实 owner/服务端端到端验收前必须由合同 owner 修复/确认。
- 复现：上述测试；以及 `TestPayload` 头部注释。
- 修复要求：读取端去掉 writer 的 4 字节长度前缀并与 Kotlin canonical 解析对齐；本任务不改 Contracts。修复前不得宣称命令 payload 已被真实服务端逐字段接受。

### 5.3 MAJOR：ISessionView 不暴露 visible events

`ISessionView.Current`/`TableSnapshotChangedEventArgs` 只有快照，没有 `visible_events`。`ConfirmedAnimationQueue.AcceptConfirmedEvents` 需要 owner 提供 typed 已确认事件，P4.3-B 接线时必须在现有 owner（App/SessionCoordinator）内建立该 typed 输入，禁止在 Table 程序集解析原始 envelope。当前快照差异路径可用，事件路径在 P4.3-B 前为 owner 供给缺口。

### 5.4 MAJOR：LegalActionView 无 meld/kan 类型

`LegalActionView` 只有 `action_type/option_id/tile_ids`；`SubmitAction.meldType` 无来源，故不填。若服务端要求 meldType 而不能由 optionId 解释，需合同补充；本范围不推导。

### 5.5 MAJOR：BeamSwap slot kind 不在命令中
