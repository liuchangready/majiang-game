## 2. 批次契约与生命周期

### 2.1 类型

`TableVisibleEventBatch`：

| 字段 | 语义 |
| --- | --- |
| `Kind` / `IsFullBaseline` | `Baseline` 或 `Incremental`；与产生它的已接受帧一致 |
| `SessionId` / `RoomId` / `TableId` / `RoundId` | 从同一 binding 与已接受快照复制 |
| `ScopeId` / `Role` / `Seat` | 当前服务器签发 scope、已确认角色与座位；观战 `Seat=-1` |
| `BindingEpoch` / `ConnectionEpoch` / `OwnerEpoch` | 完整代次身份 |
| `StateVersion` / `EventSeq` | 已接受快照的权威高水位 |
| `Cursor` / `StreamVersion` / `ProjectionSeq` | 与快照同一批次的流游标 |
| `Events` | 该帧实际携带、已确认的 typed 事件 |
| `PlayableEvents` | 仅 `Incremental` 返回事件；baseline/legacy empty 恒为空 |
| `Count` / `HasEvents` | 只读计数 |

`TableVisibleEvent`：

- `EventSchemaVersion`、`EventSeq`、`CommandVersion`、`EventOrdinal`。
- `Type`（复用 `ProtocolEventType`）、`Visibility`（复用 `ProtocolEventVisibility`）、`OwnerSeat`、`Seat`、`TileIds`、`TileId`、`TurnNumber`。
- `Payload` 为现有 `Contracts.ProjectedEventPayload` 的不可变 typed body；消费者可直接读 `Payload.Meld`、`Payload.Yaku`、`Payload.Score` 等，不存在 `object`/字符串/JSON/raw Envelope 旁路。
- `OwnerSeat`：私有事件为事件自身 owner，且必须等于当前 binding seat；公开事件为 `-1`。
- 集合和 tile id 均为 `ReadOnlyCollection`，订阅者不能添加、替换或改写已确认数据。

### 2.2 与冻结协议一致的 baseline 规则

对照 `V5-0-PROTOCOL-DECISIONS.md` §8.1/§8.3：

1. `SYNC_RESPONSE` 是基线，wire 上没有 `visible_events` 字段，因此 SYNC 基线批次事件数为 0。
2. `isFullSnapshot=true` 的 PUSH 是“基线/重置”，可携带本次发布产生的可见事件。客户端把这种批次标为 `Baseline`，`Events` 保留该接受帧的原事件供对账/去重，`PlayableEvents` 为空。
3. 不会把旧历史重新当新动作播放：
   - 同一 binding 内维护 `(event_seq, event_ordinal)` 交付栅栏，已交付/更旧的事件被过滤，不因 refresh 或 baseline 重新变为新动作。
   - Ready 状态下相同 cursor 的 full-snapshot 帧直接丢弃，不重复通知其快照或事件。
   - 新 WELCOME/新 binding/Open 重置栅栏并清空早期缓冲；旧 binding 帧不进入新私有缓存。
   - gap/溢出只走原 `ResyncRequired` + full baseline，不先发未接受帧事件。
4. 因此 B2b 的硬规则是：只有 `Incremental` 批次的 `PlayableEvents` 可进入确认动画；`Baseline` 的 `Events` 只能用于对账/去重/基线内已确认状态，不可当作新动作回放。客户端不改变服务端基线语义。

### 2.3 最小 Unity B2b 消费示例

```csharp
session.SnapshotChanged += (_, e) =>
{
    TableVisibleEventBatch batch = e.VisibleEventBatch;

    if (batch.Kind == TableVisibleEventBatchKind.Incremental)
    {
        foreach (TableVisibleEvent ev in batch.PlayableEvents)
        {
            // ev.Type / ev.Seat / ev.TileId / ev.OwnerSeat / ev.EventSeq /
            // ev.EventOrdinal / ev.Payload.Meld 等均为本批次已确认事实。
            // 只在 ev.OwnerSeat == e.VisibleEventBatch.Seat 时消费私有内容。
        }
    }
    else if (batch.IsFullBaseline)
    {
        // 替换视图、清理旧动画/选择；batch.Events 仅用于对账与去重。
        // 不把 baseline 事件重新加入动画队列。
    }
};
```

批次生命周期：

1. `OpenAsync`/新 `WELCOME`：新 binding，清空早期缓冲与事件栅栏；旧帧不得进入新私有缓存。
2. `SYNC_RESPONSE` 基线：安装快照/游标/版本后发布 `Baseline` 批次（通常 0 事件）并进入 Ready。
3. 增量 PUSH：先校验 binding/scope/cursor/版本/audience/事件 owner，再投影 typed 事件；只有全部通过才原子提交快照、游标和批次。
4. full-snapshot PUSH：发布 `Baseline` 批次；同 cursor 重复帧不重复通知。
5. gap：帧进入早期缓冲并触发 resync；基线安装后按序 drain，只有实际应用时才交付该帧 typed 事件。
6. 早期缓冲 item/byte 超限：清空缓冲、计数并请求 full baseline；不会先发缓冲事件。
7. 新 binding/重连/round reset：不夹带旧私有事件；旧 binding 帧忽略。

## 3. 实现要点与拒绝矩阵

### 3.1 原子对应

- `ApplyPush` 在修改 `_playerSnapshot/_publicSnapshot/_confirmedCursor/_confirmedStateVersion/_confirmedEventSeq` 之前先完成事件投影与校验；失败调用 `Fault`，不发布 `SnapshotChanged`。
- 成功后事件栅栏才推进，随后用同一 `cursor`、同一快照、同一 binding 构造并发布 `TableSnapshotChangedEventArgs`。
- `ApplyPush` 现在同时接收原 `Envelope`，因此早期缓冲 drain 可从原帧取事件；不是直接调用通知伪造。
- SYNC 基线发布 `TableVisibleEventBatch.Baseline(...)`，其 `cursor`/`stateVersion`/`eventSeq`/`roundId` 来自本次接受结果。

### 3.2 事件校验与拒绝

| 场景 | 行为 |
| --- | --- |
| 未知 event type/schema、未知 oneof、body/type 不一致 | 整帧 Fault，不发布快照/事件 |
| `event_seq=0`、`command_version=0`、event seq 超过快照高水位、command version 超过 state version | 整帧 Fault |
| 事件在同一帧内 `event_seq` 回退，或同 seq 的 ordinal 回退 | 整帧 Fault |
| 同帧完全重复的 `(event_seq, ordinal)` | 去重，不重复交付 |
| 已交付 `(event_seq, ordinal)` 在 refresh/baseline 中重复 | 过滤，不重复通知 |
| 私有事件 visibility 非 PRIVATE，或 owner 与 binding seat 不符 | Fault（隐私错误） |
| 公开事件 visibility 非 PUBLIC/SETTLEMENT_PUBLIC；win 非 SETTLEMENT_PUBLIC | Fault |
| 观战批次出现私有事件类型/私有可见性 | Fault |
| 闭杠 identity 事件发给非 owner seat | Fault |
| 旧 binding/room/session/seat/错误 role/audience | 静默忽略或在进入应用前拒绝；不发布事件 |
| PUSH 携带 scope 且 scope id/room/account/role 与 binding 不符 | 忽略；不进入早期缓冲、不发布事件 |
| 回退/重复 cursor、同 cursor 重复 full baseline | 忽略；不重复通知 |
| gap / item 溢出 / byte 溢出 | 原安全 resync；不提前发布缓冲事件 |

### 3.3 早期缓冲与并发/串行语义

- `EarlyPushBuffer` 仍只保存原 `Envelope` 与编码字节数；事件投影发生在 drain 的实际应用点。
- 原 outbox、receipt、pump、`TableSessionOperationQueue` 路径未改；全量 Client 回归 153 项原用例保持通过。
- `MatchesPushScope` 只对 PUSH 生效；没有 scope 的现行帧不受影响，带外部 scope 的帧被拒绝。
- 没有新增异步、线程或 timer；仍在调用方单线程 pump 边界内完成。
