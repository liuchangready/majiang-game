## 2. 实现与拒绝语义

### 2.1 原子传递

- `TableSnapshotChangedEventArgs.VisibleEventBatch` 直接进入
  `SessionViewState.VisibleEventBatch`；batch 本身不可变，不 clone，也不从
  后续 `_session.Binding`/`_operationQueue.Binding` 重造身份。
- `SessionCoordinator` 在**接受事件的同步点**克隆 `PlayerSnapshot`/
  `PublicSnapshot`/`RoomUpdate`，再异步 `CaptureAsync` 取 pending commands。
  捕获完成后用 typed batch 的 session/room/role/seat/scope/binding/
  connection/owner epoch 与当时 binding 及 snapshot 的 stateVersion/eventSeq/
  round 做交叉校验；不匹配则丢弃该延迟快照，不把旧事件换到新 binding。
- `TablePresenter` 只使用 `SessionViewState` 携带的 batch；事件映射上下文由
  batch 身份和同一 `SessionViewState.Generation` 构造，不从主线程此刻的
  live session 再读身份。

### 2.2 纯 `ClientVisibleEventMapper`

只接收 `TableVisibleEventBatch` + `PlayerTableViewState`，不读 raw
`Envelope`、JSON、`TableRuntime`、Domain 或服务端。处理规则：

- batch 的 session/room/round/scope/role/seat/binding/connection/owner/
  stateVersion/eventSeq/streamVersion/projectionSeq 必须与投影视图逐项相等；
  Ready/授权状态也必须匹配，否则拒绝，不产生任何动画项。
- private 类型只允许 `Private` 可见性且 owner/seat 等于本 binding seat；
  spectator 或 private 撤权拒绝；`SettlementPublic` 的和牌/结算按公开处理，
  不误判为 private。
- 映射覆盖：发牌、摸牌、弃牌、吃、碰、杠、岭上摸牌、立直、自摸/荣和、
  宝牌、出千余额、流局、结算、单局结束、半庄结束、袖里藏花、偷梁换柱。
- 对手公开暗杠若 body 已脱敏（无 meld/无 tile）或不是本席的 closed kan，
  归入 state-only，绝不用 snapshot/占位/随机牌伪造实体；本席带完整身份的
  暗杠才映射。
- `StackingStarted`/`WallBuilt`/`DealingComplete` 是合法状态事件，显式归入
  `StateOnlyEvents`（`STATE_ONLY_NO_ANIMATION`），不伪造动画。

### 2.3 唯一事件源

- `TablePresenter`：
  - `state.IsFullBaseline` 或 batch `Baseline`，或 generation/binding/round/
    authorization 变化 → baseline：清队列、重绘；batch `Events` 只对账。
  - incremental 且 `PlayableEvents.Count > 0` → 只用 typed 事件；不调用
    snapshot 差分，从而同一动作不会双重动画。
  - legacy fake/session 的 `TableVisibleEventBatch.Empty` 或 incremental 空
    batch → 保留既有 snapshot 差分 fallback；没有靠禁用动画或删除 fallback
    蒙混。
- `ConfirmedAnimationQueue.AcceptConfirmedIncremental` 在一次调用中完成
  快照/身份/版本/monotonic/授权/audience/事件全量校验，之后才提交 context +
  queue，避免半套事件。
- baseline 水位等于/高于旧事件时不重播；同 command 多 ordinal、合法稀疏
  `eventSeq`、重复批/重复实体去重均由 Client batch 栅栏与 queue 双层保持。

### 2.4 既有防线

snapshot/input/control/receipt/cheat 交互未改；`TableInteractionState`、
`TableCommandIntentFactory`、outbox/receipt、operation queue、B1 场景与 P4.4
观战/结算路径均保持原测例。唯一投影断言变化是
`VISIBLE_EVENTS_NOT_EXPOSED_BY_SESSION_VIEW` 从 true 改为 false（缺口已关闭），
不是放宽。
