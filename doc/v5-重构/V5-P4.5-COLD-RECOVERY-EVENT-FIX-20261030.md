- 不能从 31 断言“权威未提交”或“用户 UI 丢事件”；同样不能仅凭 `Applied` 推断 UI 事件正确。

### 3.2 第 1 轮的误报必须撤回

第 1 轮在真实 Player 中观察到：

### 3.3 产品缺口（范围外，未修改）

`dotnet/src/Mahjong.TableRuntime/TableEventProjection.cs` 的 `FromRoundEvent` 映射了 `TileDiscarded`、`TileDrawn`、`KanDeclared`、`TsumoWin`、`RonWin` 等，但**没有** `RoundEventType.PonDeclared`、`RoundEventType.ChiDeclared`、`RoundEventType.RiichiDeclared` 分支。

## 4. 第 2 轮最小修复

### 4.1 显式动作语义策略

新增 `SmokeActionEventPolicy`，明确列出每个动作的可见事件要求：

| 动作 | 空 publication 是否允许 | 要求 |
|---|---|---|
| `Pass` | **是**（唯一 allowlist） | 响应放弃，无自身协议事件；仍需后续真实动作确认 |
| `DiscardTile` | 否 | `TileDiscarded` |
| `DrawTile` | 否 | `TileDrawn` |
| `DeclareChi` | 否 | `ChiDeclared` |
| `DeclarePon` | 否 | `PonDeclared` |
| `DeclareKan` | 否 | `KanDeclared` |
| `DeclareRiichi` | 否 | `RiichiDeclared` / `TileDiscarded` |
| `DeclareTsumo` | 否 | `TsumoWin` |
| `DeclareRon` | 否 | `RonWin` |
| `DeclareAbortiveDraw` | 否 | `DrawGame` |
| `DeclareAgariYame` | 否 | 不按合法不可见动作处理 |

空 batch 本身不再有“合法”含义；只有策略显式允许的动作才能继续。

### 4.2 GameBootstrapper

- 提交前订阅独立 observer，`finally` 退订/释放。
- 用 `Applied receipt.command_version` 与已接受发布的 `stateVersion`、事件的 `commandVersion` 关联。
- 已 Applied 且动作发布存在：
  - `AllowsEmptyPublication(action)` 为真（仅 Pass）：继续下一个真实决策，仍必须由后续本请求的真实事件确认；
  - 否则：**立即 native 31**，日志输出 `action`、`requirement`、`publicationStateVersion`、`publicationEventSeq`、receipt 和完整 batch 链。
- 动作发布不存在：失败（缺失发布，不当 state-only）。
- 发布有事件但没有匹配 commandVersion：失败（关联异常）。
- 不修改 snapshot/phase/authority，不修改 Client/Coordinator，不强行给 Pon 造动画。

### 4.3 保留的 observer 修复

`ConfirmedVisibleEventObserver` 仍在提交前订阅并保留所有已接受发布，解决 `Current` 轮询被同状态空刷新覆盖的问题。该修复本身正确，但**不能**把产品缺失投影误判成 state-only。
