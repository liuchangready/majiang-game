## 4. 第 3 轮修复

### 4.1 动作语义：类型 + 座位

`SmokeActionEventPolicy.IsRequiredEvent(action, seat, ev)` 只接受该动作自己的必需事件：

| 动作 | 必需事件 | 座位规则 |
|---|---|---|
| `DiscardTile` | `TileDiscarded` | `ev.Seat == seat` |
| `DrawTile` | `TileDrawn` | `ev.Seat == seat` |
| `DeclareChi` | `ChiDeclared` | `ev.Seat == seat` |
| `DeclarePon` | `PonDeclared` | `ev.Seat == seat` |
| `DeclareKan` | `KanDeclared` | `ev.Seat == seat` |
| `DeclareRiichi` | `RiichiDeclared` 或带 `RiichiDiscard` 的 `TileDiscarded` | `ev.Seat == seat` |
| `DeclareTsumo` | `TsumoWin` | `ev.Seat == seat` |
| `DeclareRon` | `RonWin` | `ev.Seat == seat` |
| `DeclareAbortiveDraw` | `DrawGame` | `ev.Seat == seat` 或 table sentinel `NoSeat` |
| `Pass` | 无自身可播放事件 | 永不接受其他事件作为确认 |
| `DeclareAgariYame`/Unknown/Setup | 不视为合法不可见动作 | 不接受 |

多事件/结算命令：只要同一 `command_version` 的 publication 中**至少一个**事件满足上述类型与座位，即可确认；其他 `ScoreSettled`/`RoundEnded` 等事件不导致拒绝。没有匹配事件时，即使 publication 非空也 fail-closed。

### 4.2 Observer

- `BeginAction` 现在保存 `PlayerActionKind`，不再只保存字符串。
- `ObservedVisibleEvent` 暴露不可变 `Payload`，用于 Riichi 的 `RiichiDiscard` 判定。
- `TryGetConfirmation` 先排除 Pass（永不返回确认），再要求：
  - `Event.CommandVersion == receipt.CommandVersion`；
  - `SmokeActionEventPolicy.IsRequiredEvent(action, binding.Seat, ev)`；
  - 既有 binding/scope/round/stateVersion/Incremental 栅栏。
- 任何同版本但错误类型、其他座位、窗口结算事件都不会返回确认。

### 4.3 GameBootstrapper

- `Pass`：即使 publication 带窗口/结算事件，也不当作自身确认；若 `Pass` 是唯一 allowlist 的空动作，继续到下一真实请求，仍由下一请求自己的事件确认。
- 其他动作：
  - publication 为空 → native 31，`requirement=requires: ...`；
  - publication 非空但没有类型/座位匹配 → native 31，“携带事件但无一匹配所需类型/行动座位”；
  - 有匹配 → 成功。
- 不修改 snapshot/phase/authority；不修改 Client/Coordinator；不强行造 Pon/Chi 动画。
