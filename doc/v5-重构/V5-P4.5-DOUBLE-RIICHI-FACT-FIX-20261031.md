## Change

`TableCommittedCallFacts.RequireDoubleRiichi` previously required `RequireTurnNumber(round, record) == 1`. That counter advances after any discard and incorrectly rejects a non-dealer's first-draw riichi after the dealer's opening discard, even when the riichi seat has not discarded and no call/kan interrupted the opening.

The method now derives this flag only from the committed history before the exact RiichiDeclared event: it is true when the declaring seat has no earlier TileDiscarded event and there has been no earlier PonDeclared, ChiDeclared, or KanDeclared event. The global display turn number is not used as a rules condition. LocalHost and TableService both call this shared facts method; neither host needed a separate rules change.

## Domain-action coverage

All rule cases use legal Domain transitions and the committed event history:

- First-discard Riichi is true for seats 0, 1, 2, and 3. Seats 1, 2, and 3 each do so after the dealer's opening discard; their projection turn number is 2, exercising the original bug.
- A real earlier discard by the same seat makes the later Riichi false.
- A real Pon before another seat's first discard makes that seat's Riichi false.
- A real Closed Kan before another seat's first discard makes that seat's Riichi false.
- The non-dealer case traverses TableActor, strict Wire encoding/decoding, and TableSession. Player Wire, spectator Wire, and Client event each carry `doubleRiichi=true` and the exact seat/discard tile.
- LocalHost `LocalSnapshotFacts` and TableService `TableProjectionContextSource` both capture the real non-dealer first-turn facts with `turnNumber=2`, the committed discard ID, and `doubleRiichi=true`.

No Domain rules, DTO/schema, observer, smoke policy, or publication state was changed.
