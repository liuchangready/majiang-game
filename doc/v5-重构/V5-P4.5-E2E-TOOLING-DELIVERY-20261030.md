## 2. 工具设计

### 2.1 命令与语义

所有命令使用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/unity/run-p45-e2e.ps1 ...`。路径、参数逐项传给 `ProcessStartInfo`/`Start-Process`，没有 `Invoke-Expression`、`cmd /c` 拼接或 shell 字符串求值。

| 命令 | 作用 | 关键参数 |
|---|---|---|
| `Prepare` | 新建全新 run；创建 `local/client/outbox/log/screenshots/evidence/attempts/observations/control`；写 ownership marker；记录 source/player/build/platform/time；所有场景初始化为 `NOT_RUN` | `-RunDir`（可选）、`-PlayerPath`、`-EvidenceClass`、`-Mode`、`-BuildProvenance`、`-BuildCommit`、`-BuildLog`、`-ExpectedPlayerSha256` |
| `Launch` | 后台启动指定 Player；记录 PID/start/path/hash/args；可以 `-Wait` 并设置超时 | `-RunDir`、`-Mode LocalSmoke|Manual|ToolSelfTest`、`-Visible`、`-Wait`、`-TimeoutSeconds`、`-SelfTestMode` |
| `Stop` | 只停止本 run 当前记录且身份/命令绑定再次匹配的进程；默认先请求优雅退出，`-Force` 立即强杀 | `-GraceSeconds`、`-Force` |
| `Restart` | 先停当前进程（若在运行），再新建 launch；复用同一 run/save/outbox | `-Wait`、`-TimeoutSeconds`、`-Force` |
| `Collect` | 非破坏性复制 attempts/log/screenshots/save/observations；原始日志/存档进 private；生成 manifest 和 sidecar hash | `-RunDir` |
| `Verify` | 独立校验 manifest 自身/条目/字节/SHA；拒绝自引用、重复、逃逸路径 | `-ManifestPath` 或 `-RunDir` |
| `Import` | 校验并复制真实/自测 observation 到 `observations/`；拒绝覆盖 | `-ObservationPath`、`-Phase Before|After` |
| `Compare` | 严格校验两个 observation；比较 roundId、state/event version、confirmed request/receipt、ledger、physical；reconnect session/cursor 只记录不比较 | `-BeforeObservationPath`、`-AfterObservationPath`（省略时用最新导入） |

`-EvidenceClass TOOL_SELF_TEST` 只能配 `-Mode ToolSelfTest`；`GAME` 不能使用 `ToolSelfTest`。`Manual` 必须显式 `-Visible`。默认 `LocalSmoke` 为后台隐藏模式。

### 2.2 Prepare 记录

`run.json` 记录：

- `runId`、`toolVersion`、`createdAt`、`time`（`Asia/Shanghai`，显式 `+08:00`；若系统时区不可用则使用本地时区并带 offset）
- `platform`：OS、64 位、PowerShell 版本/edition、culture、processor count
- `source`：HEAD、branch、`dirty/dirtyKnown`、`statusPorcelain` 全文、status SHA-256、diff stat SHA-256
- `player`：完整路径、字节数、SHA-256、LastWriteUtc、FileVersion/ProductVersion、`_Data` 目录、`app.info`/`boot.config`、`buildProvenance`、`buildCommit`、`buildLog` hash、`buildCommitMatchesSourceHead`
- `paths`：`root`（`-smoke-data` 持久化根）、`save`=`<run>/local`、`outbox`=`<run>/client/outbox`、`log`、`screenshots`、`evidence`、`attempts`、`observations`、`control`
- `ownership`：marker 路径和 marker SHA-256
- 17 个功能场景全部 `NOT_RUN`，不会因 Prepare 或 smoke 自动变成 PASS

`-BuildCommit` 只有在 `USER_DECLARED` 或 `BUILD_LOG_ATTACHED` 时允许；未提供时固定 `UNKNOWN`。仅“文件存在”不会产生“此提交构建”的结论；`buildCommitMatchesSourceHead` 只是一个相等事实，`buildProvenance` 仍按调用者声明记录。

### 2.3 进程所有权与防止 PID 复用

启动时记录并再次校验：

- 本 run 的 `ownerRunId`、attempt、PID、**process StartTimeUtc**、完整 exe 路径、exe SHA-256；
- 真实 Player 的命令行必须含本 run 的唯一 `-smoke-data <run root>`；self-test helper 的命令行必须含本 run 的 `--data-dir <run>/local`。这层 command-line binding 由 `Win32_Process.CommandLine` 读取，失败即 fail-closed。
- Stop/Restart/超时终止前都重新校验上述身份和绑定；路径/启动时间/hash/命令绑定任一不符即 exit 4，不终止。
- 进程自然消失但无 exit record 时记 `EXITED_UNOBSERVED`，不伪造 native exit code。

### 2.4 隐藏/可见模式

- `LocalSmoke`：默认 `hidden=true`、`visible=false`，传现有 Unity 参数 `-screen-width 1280 -screen-height 720 -screen-fullscreen 0 -logfile <abs> -smoke-data <run root> -smoke-localhost <screenshots/attempt-N>`；启动后 best-effort 隐藏主窗口。**隐藏窗口可能产生黑帧截图**，本工具不把截图存在当成视觉通过。
- `Manual`：必须 `-Visible`，不传 smoke 序列，供人工从真实菜单操作；这是正式 P4.5 人工执行使用的模式。
- `ToolSelfTest`：只用于本任务辅助 `.exe`；所有产物有 `TOOL_SELF_TEST` 标识，不能冒充麻将 Player。

### 2.5 退出/处置语义

| 记录 | 含义 |
|---|---|
| `EXITED_OK` | 原生进程 exit 0；不表示整场/恢复 PASS |
| `EXITED_NONZERO` | 原生进程非 0；工具 exit 10 |
| `TIMED_OUT` | 工具等待超时并强杀自己启动的进程；工具 exit 11；`killReason=TOOL_TIMEOUT` |
| `FORCE_KILLED` | 调用者 `Stop -Force`，身份/绑定复验通过后强杀；`killReason=TOOL_FORCE` |
| `GRACEFUL_STOPPED` | 调用者请求优雅停止，进程在 grace 内退出 |
| `EXITED_UNOBSERVED` | 进程在两次工具命令之间自然消失，无法取得 native exit code |
| `START_FAILED` | 启动失败；工具 exit 12 |
| `STOP_FAILED` | 优雅停止超时且未给 `-Force`；工具 exit 13 |

`nativeExitCode` 与 `toolExitCode` 分开记录；`P45_RESULT.exitCode` 是工具自身退出码。`LocalSmoke` exit 0 只代表现有 smoke 序列完成，不代表完整整场。

### 2.6 证据收集与 manifest

- attempts 的 `launch.json/exit.json/stdout.log/stderr.log/helper-args.txt` 逐文件归档；`stdout/stderr` 标记 private。
- 日志原始件**始终**复制到 `private/logs/`，标记 `private-do-not-publish`。
- 只有 fail-closed 评估为 `Safe` 的日志才生成 `logs/` 公开 redacted 件：
  - 处理 quoted/unquoted JSON、`key=value`、HTTP header、URL query 中的 `ticket(s)/token/accessToken/refreshToken/authorization/bearer/opaque/secret/password/apiKey/cookie/set-cookie/credential/signature` 等；
  - 对 quoted 值保留引号并写 `<REDACTED>`；对无引号值/header 遮盖整行剩余值；
  - 再检查残留敏感键、未遮盖 Bearer、嵌套对象/数组、不可解析的 JSON-like 行、NUL/二进制内容；
  - 任一检查失败即**不生成 public copy**，只在 manifest notes 记录 withheld，原始件仍只在 private。不得仅以正则替换就标记 public。
  - manifest 记录 `redactionPolicy=P45-LOG-REDACTION/2-FAIL-CLOSED`。
- 截图复制到 `screenshots/`；若多个截图 SHA 相同，manifest 增加“不得作为视觉 UI 证据”的 note。
- `*.save`/`*.save.prev` 原始件复制到 `private/save/`；同时只解析安全的 header 字段生成 `normalized/*.observation.json`（source=`SAVE_HEADER_EXTRACT`）。原始存档明确 `private-do-not-publish`。
- manifest 只列已复制 artifact；不含 `manifest.json`、`manifest.sha256.txt`、`*.tmp.*`、`*.lock`。先写临时文件再替换，写完后计算 manifest SHA-256 写入独立 sidecar。
- `Collect` 在 run 仍有 active process 时拒绝；无 attempt 且无 observation 时 exit 14，不写空 PASS manifest；不覆盖旧 collection。

### 2.7 Compare/observation 规则

`p45-e2e-evidence.schema.json` 定义 observation 必需字段。`Import`/`Compare` 校验：

- `kind`、`schemaVersion`、`source`、`phase`、`runId`、`playerSha256`、`sourceHead`、`buildCommit`、`buildProvenance`、`rulesetVersion`、`observationId`；
- `phase` 必须精确等于 `BEFORE_RECOVERY`/`AFTER_RECOVERY`；`UNKNOWN` 仅允许用于独立 save-header 提取，Import/Compare 一律拒绝（exit 18），不允许“未知阶段”进入 PASS；
- observation 的 `buildCommit` 和 `buildProvenance` 必须与 Prepare 记录的 `Run.player` **逐项一致**；不一致是 `OBSERVATION_IDENTITY`（exit 19）。`TOOL_SELF_TEST` run 只能有 `TOOL_SELF_TEST` observation，伪称 `PLAYER_STRUCTURED_EXPORT` 直接无效（exit 18）；
- `integrity.algorithm=SHA-256` 与 `canonicalSha256` 必须匹配由规范化字段重算的摘要；摘要**包含全部 availability 布尔值**，因此只改 availability 不重算 checksum 会 exit 18；坏 JSON/坏 checksum exit 18，run/player/source/build 身份不符 exit 19；
- roundId、stateVersion、eventSeq、requests（requestId/receiptId/confirmed/payloadSha256）的集合、ledger（points/entryCount/entriesSha256）、physical（tileCount/tilesSha256）为必需比较项；physical.tileCount 必须为 136；
- `controlEpoch`、`reconnect.sessionId`、`reconnect.cursor`、capturedAt 不作为必需相等项，只记录到 `mutableFields`；
- 缺字段/availability false → `BLOCKED`（exit 17），不得 PASS；required 不相等 → `FAIL`（exit 16）；
- 任一来源为 `TOOL_SELF_TEST`，或 Prepare 的 `evidenceClass=TOOL_SELF_TEST`，只能得到 `TOOL_SELF_TEST_ONLY`（exit 30）或更早的拒绝，`pass=false`；
- **真实 `PASS` 在当前版本不可达**：即使 source=`PLAYER_STRUCTURED_EXPORT`、字段完整、build identity 与 Prepare 一致、phase 精确，工具仍以 `realPassGate=NO_VERIFIED_PLAYER_STRUCTURED_EXPORTER_IN_THIS_TOOL_VERSION` 返回 BLOCKED。原因是没有产品导出 hook、签名/信任根或可核对的导出 artifact；自声明 source 和可自行重算的普通 SHA-256 不是 provenance。未来接入真实导出器时必须改工具并增加可验证信任，而不是改 observation 字段。

当前真实能获取的 save header 字段只有：roomId、origin、rulesetVersion、stateVersion、lastEventSeq、stateFingerprint、stateHash、controlVersion、controlEpoch、timingVersion、cheatVersion、cheatFingerprint、cheatBound。**没有 roundId、已确认 request/receipt、ledger、physical tile digest、签名导出**；这五项在 normalized observation 中 `availability=false`，Compare 必须 BLOCKED。
