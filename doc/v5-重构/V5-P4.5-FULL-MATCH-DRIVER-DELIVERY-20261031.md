## 2. D-1-05(b) — 部分：scope 契约阻断，timeout 仍缺

`LocalMatchChannelProgressionTests` 新增实际断言：

- 终局后关闭 session channel，再 `OpenRoundAsync` 恢复同一 durable round；恢复 session 的 Client scope 是新 scope。
- 用原 Ron 请求（原 requestId/scope/canonical payload）向恢复 session 提交，实际抛出：
  `ArgumentException: The command scope id does not match the current server-issued scope.`
- 断言：
  - 恢复前后 `StateVersion`/`EventSeq` 不变；
  - 旧 scope 与新 session scope 不同；
  - 同一 terminal round 重复 `RecordRoundCompletionAsync` 抛错，`Records` 仍为 1，结算不重复；
  - 原请求没有被替换为新 requestId 的正常请求。
- 结论：同 scope/request **对账重放目前不可实现**；这是 `LocalTableRuntime`/`TableSession` 的恢复 scope 契约缺口（新连接发新 scope，Client 拒绝旧 scope），不是本任务可在授权文件内修复的行为。没有编造 threadId；需调用方/该契约 owner 决定是否提供 resume-scope。
