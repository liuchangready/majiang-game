## 3. 实现要点

### 3.1 Round/整场装配

- 默认应用：`LocalTableChannelFactory.CreateAsync` 仍创建单局 `LocalTableHost`，不改行为。
- 仅当驱动在 `AppRoot` 初始化前调用 `EnableMatchMode()`：工厂打开/复用 `LocalMatchCoordinator`，每次 session open 取当前 round 的 `LocalTableRound.Channel/Ticket`。
- Round 结束：驱动先调用 `ILocalMatchControl.RecordRoundCompletionAsync`，由 coordinator 用 Domain `RoundResult` 持久化 match（分数、立直棒、本场、下一 round/终局），**不**由客户端计算；然后关闭现有 session，再 `OpenLocalSessionAsync` 打开下一 round。新 round 使用新的 durable actor/store/roundId，不复用终局。
- `RecordRoundCompletionAsync` 与既有 `CompleteRoundAsync` 共用同一核心；后者仍负责关闭 channel。
- 恢复：同一 round channel 被 session owner 关闭后，`OpenRoundAsync` 不返回已关闭对象，而是从同一 durable round 冷恢复新 channel（不换 round、不换 match、不撤账）。

### 3.2 驱动语义

- 只从真实 `Menu`/`Lobby` 的 `PlayButton`/`StartLocalGameButton` 点击进入，和 smoke 一样通过真实 Button/EventSystem；不新增 UI 技术文案。
- 动作只使用 `PlayerTableViewState.Own.Decision.Candidates`；`TableCommandIntentFactory` 创建 canonical 命令，经 `SessionCoordinator`（`ITableCommandSink`）提交。
- `requestId = fm-<SHA256(round|decision|action|option|tiles)>`；同一逻辑动作重规划仍是同一 ID。未知结果只记录 unresolved，不换 ID 重发。
- 可见确认复用**未修改**的 `SmokeActionEventPolicy`/`ConfirmedVisibleEventObserver`；另以 `IsOwnActionEvent` 要求同一 session/room/table/scope/seat/binding/connection/owner/round 和 Applied command version。Pass 只接受 Applied、不接受别座位/别类型事件。
- 已知 definite Rejected（stale state/decision、not-your-turn、seat-not-eligible 等）是零副作用；驱动把该 decision 视为不可重提，等待下一 confirmed decision，不把拒绝当 Applied。未知/无回执仍有界失败。
- 强制 Draw 没有服务端 decision；驱动使用 canonical `SubmitAction(DrawTile)`，并用两种**同一 binding/round/seat**的确认兜底：自己的 `TileDrawn` 可见事件，或 post-state（新 stateVersion + 本座位 drawn tile + CheatWindow/Discard）。不读宿主隐藏牌。
- 卡住：25 s 无 state 变化且 session Ready 时，关闭/重开同一 round 的 Client session（最多 3 次/round）；超过则 `ROUND_STALLED`。整场 90 min、round 20 min 有界。
- 终局：只接受有 `RoundEnded` + Tsumo/Ron/Draw 的真实结算事件、4 行 final scores、136 守恒（分数+立直棒=100000）、`SettlementRoundId==roundId`；整场完成由 coordinator `Finished` + records/rankings/final scores 交叉核对，客户端不自算排名。
- 证据只写 ignored `build/.../driver/full-match.jsonl` 与 `summary.json`；未写 token/ticket、隐藏牌或私有存档内容到报告。

### 3.3 关键事实：真实 NextRound 门面链路仍缺失

核实结果：`TableCommandIntentFactory.CreateNextRound` 和 UI 有 `NextRound` intent；`TableService.TableCommandMapper` 有 NextRound 分支；但 `LocalTableRuntime.HandleCommandAsync` 没有 `CommandKind.NextRound` 分支，Unity 默认 factory 也未接 coordinator。因此**当前生产 UI 的 NextRound 按钮在 LocalHost 上不会完成下一局**。本任务没有改这些任务 1 所属文件；驱动改用已验收 `LocalMatchCoordinator` 的 round 边界（服务端 facade），每个 round 内部仍全部走真实 Client 命令。该缺口是 G2 的明确 BLOCKED 项（见 §7）。

## 7. 已知缺陷 / BLOCKED（一次性列全，不逐轮保留）

1. **BLOCKER：LocalHost 流/回执停顿。** 真实 Player 多次在同一 run 内约 25–30 s 无任何 state 推进，Client `State=Ready`、`lastError=<none>`，save 停更；恢复重开同一 round 后继续。run-06/07/08/09/10 均出现。驱动只能以有界恢复/失败兜底，不能证明整场。
