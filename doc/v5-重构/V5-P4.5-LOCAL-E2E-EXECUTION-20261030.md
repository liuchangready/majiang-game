## 3. 工具快速开始

变量示例（按实际路径替换）：

```powershell
$Tool = 'D:/majiang-wt/p45-e2e-tooling-20261030/tools/unity/run-p45-e2e.ps1'
$Run  = 'D:/majiang-wt/p45-e2e-tooling-20261030/build/p45-e2e-tooling/runs/formal-p45-01'
$Player = 'D:/path/to/clean-build/Mahjong.exe'
$BuildLog = 'D:/path/to/player-build.log'
$Commit = '<40-hex-clean-build-commit>'
```

### 3.1 Prepare（正式人工模式）

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Tool Prepare `
  -RunDir $Run `
  -PlayerPath $Player `
  -EvidenceClass GAME `
  -Mode Manual `
  -Visible `
  -BuildProvenance BUILD_LOG_ATTACHED `
  -BuildCommit $Commit `
  -BuildLog $BuildLog `
  -BuildSourceNote 'P4.5 formal Windows Player; clean commit + attached build log'
```

Prepare 后立即读取并保存：

```powershell
Get-Content (Join-Path $Run 'run.json') -Raw -Encoding UTF8
Get-FileHash (Join-Path $Run 'ownership.json') -Algorithm SHA256
```

确认 `run.json` 中的 `source.head/dirty`、`player.sha256`、`time.label`、`paths.localSave`、`paths.clientOutbox`、17 个场景均为 `NOT_RUN`。若 `dirty=true` 或 `buildCommitMatchesSourceHead=false`，恢复 Compare 只能 BLOCKED；不得手改 run.json 变成干净。

### 3.2 Launch（真实操作，后台等待）

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Tool Launch `
  -RunDir $Run -Mode Manual -Visible -Wait -TimeoutSeconds 3600
```

- 该命令会启动一个可见 Player，并等待它退出；期间在另一个 PowerShell 窗口执行 Stop/Collect。
- 默认 `LocalSmoke` 模式是隐藏后台，不得用它声称视觉/完整整场证据。
- 记录 `attempts/NNNN/launch.json` 中的 PID、StartTimeUtc、exe 路径/hash、完整参数。
- 若 Player 自行退出，记录 native exit code；如果工具没有观察到（两次命令之间退出），记 `EXITED_UNOBSERVED`，不编造 exit code。

### 3.3 Stop / Force / Restart

```powershell
# 请求优雅退出（真实 Player 可能弹退出确认；超时则不会盲杀）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Tool Stop -RunDir $Run -GraceSeconds 20

# 仅在本 run 进程身份/命令行绑定复验通过后强杀
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Tool Stop -RunDir $Run -Force

# 复用同一个 local/ 和 client/outbox/，新建 launch 证据
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Tool Restart `
  -RunDir $Run -Mode Manual -Visible -Wait -TimeoutSeconds 3600
```

Stop 只接受 `state.json` 中 `ownerRunId` 属于本 run、PID/启动时间/路径/SHA/命令行绑定再次匹配的进程。路径或启动时间不符、PID 被复用、命令绑定不含本 run 路径时 exit 4，**不 kill**。不要用任务管理器强杀后把未观测到的状态写成工具强杀。

### 3.4 Collect / Verify

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Tool Collect -RunDir $Run
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Tool Verify `
  -ManifestPath (Join-Path $Run 'evidence/collections/0001/manifest.json')
```

Collect 会新建 `evidence/collections/NNNN/`；不覆盖旧 collection。若 run 仍有活动进程，Collect 拒绝；先 Stop。无 attempt 且无 observation 的 run，Collect exit 14，不生成空 PASS manifest。

## 4. 正式 P4.5 操作步骤

以下步骤需要真实人工操作、截图/日志和结构化证据；工具负责 run/process/evidence，不替代判断。

### 4.1 菜单 → 本地房间

1. 启动真实 Player；检查窗口、分辨率、键盘/鼠标或触屏输入。
2. 从菜单进入本地对局入口（现有入口包括 `PlayButton` → Lobby → `StartLocalGameButton`；以构建实际 UI 为准）。
3. 确认真实 LocalHost 已打开：日志出现 `SCENE_LOAD_COMPLETED:Table`、`SMOKE_STEP:LOCAL_SNAPSHOT` 或等价生产日志；`<run>/local/local-main.save` 和 `<run>/client/outbox/` 出现。
4. 记录 roomId、seat、sessionId、初始 stateVersion、手牌数、玩家可见基线。
5. 断开外部网络（仍保持本地进程），确认本地房间仍可开始；这不是“公网不可用=通过”，只证明本路径。

### 4.2 码牌 → 发牌

1. 在真实码牌准备面板完成码牌/确认；不修改快照或注入候选。
2. 核对四席、手牌、牌山、死山、宝牌指示牌与可见计数。
3. 用真实权威摘要/结构化字段核对 136 张物理守恒；截图数量不能替代权威检查。
4. 记录 `roundId`、stateVersion、eventSeq、player seat、起始手牌。

### 4.3 完整一局

按真实 UI 完成并分别记录：

- 摸牌、打牌、吃/碰/杠（明杠/暗杠/加杠）、立直、振听/解除、自摸/荣和；
- 响应窗口、超时、错误 deadline；旧 decision/controlEpoch 被拒绝；
- 流局（荒牌/九种九牌等）与和牌至少各一次；
- 每次动作的 requestId、receiptId、confirmed 状态；不把“画面变化”当回执；
- 三绝技在真实合法候选窗口出现时：
  - 落汗（TileMark）：标记真实实体牌，记录费用/账本变动/可见范围；
  - 袖里藏花（SleeveBloom）：真实手牌交换，记录候选/确认/费用/结果；
  - 偷梁换柱（BeamSwap）：手牌与牌山/死山等额互换，记录物理守恒；
  - 无法自然触发时明确标 `BLOCKED`，不要注入假状态或伪造候选。
- AI 接管/收回：制造真实断线/控制丢失，等待策略窗口；记录 controlEpoch 变化、旧决策失效、显式 `claimControl` 收回；不把客户端标签当权威。
- 观战/隐私：切到观战只读流，确认无暗牌、种子、袖牌、私有费用/账本；观战不能提交玩家命令；切回玩家必须重建会话/基线，不复用旧身份/游标。

### 4.4 连庄 / 下一局 / 整场终局

1. 完成一局结算，核对役种代码、番/符、点数、立直棒、本场数、供托、排名来自结构化字段/权威数据，不从中文文案反算。
2. 连庄或下一局：确认新 `roundId`、新的状态机实例；不复用旧局终态。
3. 继续至整场终局；记录最终排名、点棒、账本、LOCAL 结果。
4. 如果产品流程没有可用的“下一局/终局”入口，明确 `BLOCKED`，不要通过改存档/注入状态推进。

### 4.5 正常退出 / 强杀 / 重启

**正常退出：**

1. 通过真实菜单退出，等待 clean shutdown；确认日志 `QUIT_SHUTDOWN_RESULT: Outcome=Completed` 或等价。
2. 记录 native exit code（`-Wait` 模式下由 launch/exit 记录）。
3. `Stop` 只做对账；若已退出，记 `ALREADY_EXITED`/`EXITED_UNOBSERVED`，不补写 0。

**强制终止 + 冷恢复：**

1. 在已确认一次提交后，记录 before 状态（见 §5）。
2. `Stop -RunDir $Run -Force`，记录 `FORCE_KILLED`、killReason、PID。
3. 保留 `local/local-main.save`、`.save.prev` 和日志。
4. `Restart` 同一 run，确认复用同一 `local/`，新建 attempt；等待恢复到 Ready。
5. 记录 after 状态；验证未重复扣费、未重复出牌、已确认回执未丢失；执行 §5 的 Compare。
6. 如果重启后进入新局、静默开新档或无法恢复，标 `BLOCKED`/`FAIL`，不得继续宣称 PASS。

### 4.6 损坏副本 / 旧版备份

此步骤必须在**独立副本**上做；不要拿正式已确认存档做破坏性试验。

1. Stop 后复制整个 run 到新的隔离目录，或 Prepare 一个新 run 并把已有 save 复制到它的 `local/`。
2. 分别制作：
   - 截断文件（保留前 N 字节）；
   - 坏 envelope/file magic；
   - 坏 payload SHA-256；
   - 旧 `saveVersion`/`rulesetVersion`（如果当前格式可识别）；
   - 只保留 `.save.prev` 的备份回退。
3. 启动新 run，记录：
   - 明确拒绝并保留字节；或
   - 按合同恢复到上一份可用存档；
   - 不得静默开新局、不得删除损坏件、不得覆盖原证据。
4. 工具不会自动修改 save；没有专用注入 runner，因此该步骤是人工/后续独立 fixture 流程。当前不能声称“损坏存档与旧版回退已自动验证”。

## 5. 恢复一致性对比（当前真实边界）

### 5.1 当前 Player 能提供什么

`LocalSave` 的真实 header 可由工具解析，当前得到：

- roomId、origin、rulesetVersion；
- stateVersion、lastEventSeq、stateFingerprint、stateHash；
- controlVersion、controlEpoch、timingVersion；
- cheatVersion、cheatFingerprint、cheatBound。

**不包含：**

- roundId；
- 已确认 request/receipt 集合；
- 账本明细/账本摘要；
- 物理 136 张摘要；
- 签名/受信任结构化导出。

因此当前真实恢复只能：

- 记录 save header（`SAVE_HEADER_EXTRACT`）；
- 做人工日志/版本核对；
- **Compare 必须 BLOCKED**，不得用截图、中文日志、文件存在或退出码补字段。

**本工具版本对真实 PASS 设了显式闸门**：即使有人把 observation 的 `source` 改成 `PLAYER_STRUCTURED_EXPORT`、把 `buildCommit` 改成 Prepare 的 sourceHead、把 `buildProvenance` 改成 `USER_DECLARED`，并重算普通 SHA-256，Compare 仍必须是 `OBSERVATION_IDENTITY` 或 `BLOCKED`，不能 PASS。原因是：

- observation 的 buildCommit/provenance 必须与 Prepare 的 `player` 记录逐项一致；
- `TOOL_SELF_TEST` run 只能使用 `TOOL_SELF_TEST` observation；
- phase 必须是精确的 `BEFORE_RECOVERY`/`AFTER_RECOVERY`，`UNKNOWN` 只用于 save header；
- 当前没有可验证的 Player 结构化导出器/签名/信任根，因此 `realPassGate=NO_VERIFIED_PLAYER_STRUCTURED_EXPORTER_IN_THIS_TOOL_VERSION`，真实 source 一律 BLOCKED。普通 SHA-256 只防篡改，不是 provenance。

`integrity.canonicalSha256` 的规范化字段顺序见 `tools/unity/p45-e2e-common.ps1` 的 `Get-P45ObservationDigest`。摘要包含：

```text
schemaVersion,kind,observationId,source,phase,
runId,playerSha256,sourceHead,buildCommit,buildProvenance,rulesetVersion,
availability.roundId,availability.stateVersion,availability.eventSeq,availability.controlEpoch,
availability.requests,availability.ledger,availability.physical,availability.structuredPlayerExport,

physical.tileCount,physical.tilesSha256,
按 requestId 排序的 request=requestId|receiptId|confirmed|payloadSha256
```

不包含 `capturedAt` 和 `reconnect.sessionId/cursor`；它们是可变/观测元数据。摘要算法为 UTF-8 文本、LF 换行、SHA-256、大写十六进制。**availability 必须纳入摘要**；只改 availability 不重算 checksum 会 exit 18，重算后缺字段仍 BLOCKED。

### 5.3 Import / Compare 命令

`Import -Phase Before` 只接受 `phase=BEFORE_RECOVERY`，`-Phase After` 只接受 `AFTER_RECOVERY`；`UNKNOWN` 的 save header 不能伪装成恢复前后观测。Import 还会强制 observation 的 buildCommit/provenance 与 Prepare 的 Player 记录一致，并拒绝 `TOOL_SELF_TEST` run 里的真实 source。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Tool Import `
  -RunDir $Run -Phase Before `
  -ObservationPath 'D:/evidence/before-recovery.json'

powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Tool Import `
  -RunDir $Run -Phase After `
  -ObservationPath 'D:/evidence/after-recovery.json'

powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Tool Compare `
  -RunDir $Run `
  -BeforeObservationPath 'D:/evidence/before-recovery.json' `
  -AfterObservationPath 'D:/evidence/after-recovery.json'
```

结果含义：

| 结果 | exit | 含义 |
|---|---:|---|
| `PASS` | 0 | **本工具版本不可达（真实 source 被闸门 BLOCKED）**；未来接入可验证导出器后才可能 |
| `FAIL` | 16 | 必需字段不相等（如 roundId/版本/回执/账本/物理摘要） |
| `BLOCKED` | 17 | 缺字段/availability false/source 非真实导出/build 身份 UNKNOWN/source dirty/无可验证导出器 |
| `OBSERVATION_INVALID` | 18 | JSON、schema、checksum、phase=UNKNOWN、TOOL run 伪称真实 source 等非法 |
| `OBSERVATION_IDENTITY` | 19 | run/player/source/build/provenance 身份不匹配 |
| `TOOL_SELF_TEST_ONLY` | 30 | 自测 fixture 逻辑相等，但不是真实恢复；`pass=false` |

reconnect 的 session/cursor、capturedAt、controlEpoch 不作为必需相等项；controlEpoch 变化通常与重连/接管有关，但工具不会因此把账本/物理差异放行。

## 6. 观战隐私与 LOCAL 结果隔离

### 6.1 观战

- 从真实观战入口进入，确认使用独立公共流/会话，不复用玩家身份、基线或游标。
- 观战画面不得出现：暗牌、种子、袖牌、私有绝技候选、私有费用明细、玩家私有账本。
- 观战不得提交玩家命令；如果 UI 出现按钮，记录为缺陷，不点击。
- 切回玩家必须重建真实会话；旧 controlEpoch/游标不得复用。
- 截图只能作辅助；结构化公共白名单/字段才是证据。P4.4 的 test-channel 证据不等于真实网络/真实观战通过。

### 6.2 LOCAL 结果

- 确认 `origin=LOCAL`，没有线上 token、钱包、排位/资产结果。
- 检查客户端/服务端合同测试，确认假线上结算/资产入口被拒绝；仅靠 UI 标签 `[本地局]` 不算服务端证明。
- 本工具只隔离本地目录，不证明所有上传/资产入口；该结论属于 P4.1/P4.4/G2 的合同测试与独立复核范围。

| 三绝技/AI/流局/和牌/连庄/终局 | **NOT_RUN** | 人工操作；无完整自动操作 hook |
| 正常退出/强杀/重启 | **PARTIAL** | 工具已验证进程层；真实 Player 的强杀恢复和回执一致未执行 |
| 损坏/旧版存档回退 | **NOT_RUN / BLOCKED** | 无专用注入 runner；需独立副本和人工/后续 fixture |
| 真实恢复 Compare | **BLOCKED** | 缺 Player 结构化导出 hook；save header 不够 |
| 观战隐私 | **NOT_RUN** | 人工检查；P4.4 test-channel 不等于真机/真实网络 |
| LOCAL 结果隔离 | **NOT_RUN** | 需合同/服务端证据；工具只隔离目录 |
| Android | **NOT_RUN / BLOCKED** | 单独构建/设备/输入矩阵；不从 Windows 推导 |

| IL2CPP | **NOT_RUN** | 未做 IL2CPP 构建/运行 |
| 真机/跨物理网络 | **NOT_RUN** | 不在本任务范围 |

## 8. 证据归档规则

1. 每次正式执行只写新 run；Prepare 拒绝旧目录。
2. Player 正常退出或 Stop 后再 Collect；Collect 拒绝活动进程。
3. 原始日志/存档在 `evidence/collections/NNNN/private/`，标记 `private-do-not-publish`；不要提交、不要公开、不要粘贴 ticket/opaque token。
4. 公开日志只有在 `P45-LOG-REDACTION/2-FAIL-CLOSED` 评估为 `Safe` 时才生成。JSON/header/query 的 ticket、token、Authorization/Bearer、opaque 等会被替换；**带日志前缀或嵌入文本的 JSON、`\u0074icket` 这类 Unicode 转义键、以及 JSON 字符串值内再次编码的 JSON（如 `{"message":"{\"\u0074icket\":\"...\"}"}`）都会递归解码识别**。敏感标量 JSON（含包住它的整个外层 JSON）替换为 `<REDACTED-JSON>`；嵌套 JSON、未闭合/不可解析的 JSON-like 值、超过深度上限、残留敏感键或 NUL 内容一律**不生成 public copy**，只保留 private 原件，并在 manifest notes 记录 withheld。不得只看“正则跑过”或“行首不是 JSON”就发布。
5. manifest 不包含自身或 sidecar，记录 `redactionPolicy`；用 `Verify` 逐字节/逐 SHA 复核。public 产物和 manifest 不得含样本秘密。
6. 截图若有重复 hash，manifest 会提示可能是黑帧/非视觉证据；不得用截图存在代替结构化字段。
7. 所有临时辅助进程/日志/XML/截图/样本都在 ignored `build/p45-e2e-tooling/`；不新增 tracked 文件。
8. 记录首次失败和原始日志；不要删除失败件或改成通过。

## 9. 退出码与失败处理

工具退出码（`P45_RESULT.exitCode`）：

| 码 | 含义 |
|---:|---|
| 0 | 当前命令成功（不代表整场/恢复 PASS） |
| 2 | 参数/用法错误 |
| 3 | 拒绝覆盖旧 run/旧证据 |
| 4 | ownership/身份/命令绑定不匹配，或不可安全终止 |
| 5 | 文件/run/manifest 不存在 |
| 10 | Player 原生非 0 |
| 11 | 等待超时，工具已强杀自己启动的进程 |
| 12 | 启动失败 |
| 13 | 停止失败/仍在运行，未给 Force |
| 14 | 证据为空/非法，Collect 拒绝 |
| 15 | manifest/artifact 校验失败 |
| 16 | Compare 必需字段不相等 |
| 17 | Compare 缺字段/不可得/不可判定 |
| 18 | observation JSON/schema/checksum 非法 |
| 19 | observation run/player/source 身份不符 |
| 30 | TOOL_SELF_TEST_ONLY（不是真实 PASS） |
| 99 | 未分类内部错误 |

失败时不要：

- 把 exit 0 或截图存在写成 PASS；
- 删除/覆盖失败 run；
- 用旧 run 的 manifest 代替新 run；
- 把 fixture、save header、中文日志或单次 smoke 当真实恢复；
- 修改权威存档/状态来“修绿”。

## 10. 收尾检查

- `run.json` 的 source/Player/build/time、`ownership.json` hash 已保存；
- 每次 launch 有 `launch.json`，退出/停止有 `exit.json`，native 与 tool exit 分开；
- 已确认操作前后的真实 observation（若有 hook）已 Import/Compare；无 hook 时明确 BLOCKED；
- 四席、136 张、账本、回执、物理摘要来自权威/结构化字段，不是截图推断；
- 观战无私有内容、不能提交命令；LOCAL 无线上资产结果；
- Collect/Verify 通过，manifest hash 已记录；private 文件未提交；
- Android/iOS/IL2CPP/真机仍 NOT_RUN/BLOCKED；
- V4 仍是生产基线，PR20/P4.5/G2–G5 未整体接受。

本指南本身不是通过证明。正式结果必须记录真实版本、硬件、命令、native exit、测试计数、证据路径和 SHA；任何未执行项保持 `NOT_RUN` 或 `BLOCKED`。
