## Implementation

- `TableEventProjection.FromRoundEvent` maps PonDeclared, ChiDeclared, and RiichiDeclared to their actual protocol event types and preserves source event sequence, command version, ordinal, and actor seat. Since Domain Pon/Chi records carry only the called physical tile, the intermediate input carries that tile; the final contract mapper still requires the exact three distinct meld entities, matching meld type, called tile membership, and matching `fromSeat`.
- `TableCommittedCallFacts` associates facts with the unique committed event in the captured Round history and matching seat/fromSeat/called tile. It does not substitute the latest meld for an older event. It reconstructs a historical Pon before a later AddedKan by excluding the exact later-added entity recorded in history. Missing or inconsistent facts fail closed.
- Riichi facts use the committed discard entity and derive double-riichi from that Round history. LocalHost creates the three facts, including rebuilding these newly introduced facts when restoring a matching older cached fact set while preserving unrelated cached facts. TableService uses the same shared call association rules.
- Public exposure remains governed by the existing projection policy. No private hand, sleeve tile, seed, or private fee is added to public facts. Existing concealed-kan identity handling and internal-event behavior remain unchanged.
