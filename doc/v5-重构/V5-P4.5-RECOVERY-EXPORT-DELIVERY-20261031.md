## 2. D-1-01 至 D-1-06 修复映射

### D-1-01（BLOCKER）受控采集全字段绑定

**根因**：Chain 只校验 challenge/phase/package 等少数字段；raw export 的 pid/runId/processPath/capturedAt/exporterVersion 与 observation/launch/run 未交叉比较；Collect 自身可重算 manifest，不能作为真实性来源。

**修复**：

1. `Test-P45RecoveryExportChain` 对 raw `export.json` 与 observation/launch/run/package 做逐字段交叉：
   `exporterVersion`（精确 allowlist）、`runId`、`attempt`、`phase`、`challenge`、`pid`、`processStartUtc`、`processPath`、`playerSha256`、`packageManifestSha256`、`packageFileCount`、`sourceHead`、`buildCommit`、`buildProvenance`、`rulesetVersion`、`capturedAt`、`authoritySha256/Bytes`、`cheatStateSha256/Bytes`。
2. `processPath` 必须同时等于 launch.player.path、launch.command.executable、run.player.path；`run.paths.root/save` 必须等于当前 run 目录；launch 的 `-smoke-data` 必须等于 run root。
3. `export.done` 必须逐字节绑定 `export.json` SHA；`launch.json/exit.json` 的 runId/attempt/PID/start/path/hash 必须一致。
4. 外部 **collector HMAC key**：`Prepare` 在 run 之外的 `build/p45-recovery-export/collector/<runId>.json` 生成随机 32 字节 key，并绑定 **原始 run root**；每次 `New-P45Collection` 对 `runId|root|collection|manifestSha` 计算 HMAC-SHA256，写 `collector-attestation.json`。复制 run 到新 root 再 Collect 会 exit 4，不能重建可信采集记录。Compare 只用外部 key 验证 attestation。
5. 仍明确限制：该 key 是本机受控文件，不是硬件根，不能抵御本机管理员；不把它说成生产签名。

**验证**：Codex `repro-bindings.ps1` 在修复后复制 run 到 scratch 并改变 root，`New-P45Collection` 实际 exit **4**（`The external collector key is bound to a different run root`），不再出现五个 PASS。20 项负例覆盖 raw/observation 篡改、重算 SHA、缺字段/availability、错 phase/run/build/challenge/package。

### D-1-02（BLOCKER）当前 cheat aggregate/账本

**根因**：Reader 从 base checkpoint 取 ledger，而 current row 的 cheat version/fingerprint 来自后续 operations；base v1 vs current v4，导致不同时点字段拼接。

**修复**：

1. `LocalTableRuntime.CaptureRecoveryAsync` 在同一个已提交 actor 上读取当前 `_cheat`（诊断只读反射），编码为 `cheat-state.bin`；同时读取同一 primary envelope，要求 current cheat version/fingerprint 与 save row 完全一致。
2. `LocalTableRecoveryFactsReader.ReadPersistedFacts(bytes, currentCheatPayload)`：
   - current cheat payload 必须与 `CurrentState.CheatVersion/Fingerprint` 一致（未 bound 的新局要求与初始 checkpoint 一致）；
   - 缺失 current aggregate 且 base checkpoint 已陈旧 → `InvalidDataException`，拒绝拼接；
   - round/control 取最新 checkpoint/operation 的单一时点；
   - 账本从 current aggregate 构建，source=`CURRENT_COMMITTED_ACTOR`，checkpointVersion=current total version。
3. Probe 原子写 `authority.save` + `cheat-state.bin` + `export.json` + `export.done`；Import/Chain/Verifier 都校验 cheat-state 字节/SHA。
4. 非空账本测试：在独占内存夹具中加入真实 `CheatLedgerEntry` 扣点，重编码 save/current cheat；reader 导出 1 entry、balance 110、digest；旧 aggregate 配新 binding 被拒绝。另有真实公开通道 `SubmitTileMark` 定向用例：提交 4 张实体牌并等待 Applied/Recorded 回执后 capture，导出 ledger entryCount>0、seat0 balance<120、source=`CURRENT_COMMITTED_ACTOR`。

**边界**：current cheat aggregate 由宿主内部读取，不是离线重放所有 cheat operation；不声称全量绝技账本回放。当前 v3 sample 为 0 entries。

### D-1-03（MAJOR）控制/权威事实比较
