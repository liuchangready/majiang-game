## 2. 设计与信任链

### 2.1 为什么不能只改 Compare 闸门

旧工具把“`source=PLAYER_STRUCTURED_EXPORT` + 可自行重算的普通 SHA-256”当成唯一输入，真实 Player 没有结构化导出，因此真实 PASS 被显式闸门固定为 BLOCKED。直接删闸门会把自写 JSON 当成真实导出。本任务改为：

1. **真实 runtime 内读取**：只在真实 `LocalTableRuntime` 已打开、已恢复/已提交的同一个 authority 上捕获；不创建第二个可变 host，不接管 lease，不写存档。
2. **单点版本 fence**：capture 读取 primary envelope 后，要求解码的 roundId/stateVersion/eventSeq/stateFingerprint/controlVersion/controlEpoch 与 actor 的同一快照一致；不一致就重试并在超时后 fail closed，绝不拼接多个时点。
3. **Before 在终止前落地**：Probe 在 runtime 打开时先写 `authority.save` + `export.json` + `export.done`，随后才允许正常退出或由本任务强杀。
4. **After 是首个恢复基线**：opt-in 预捕获在 `LocalTableRuntime.OpenAsync` 内、autoplay driver 启动前完成；Probe 读取该预捕获。这样 AFTER 不是采样到 AI 已行动后的版本。该分支只在 `-p45-recovery-export` Probe 中启用，生产路径不启用。
5. **独立进程校验**：`P45RecoveryVerifier` 在独立 .NET 进程读取被导出的 `authority.save`，重新解码 envelope/checkpoint/operation/round/control/cheat，重新计算账本/136 实体摘要；Compare 不信任 observation 自声明字段。
6. **封存链**：Compare 只接受在已 `Verify` 的 collection 中同时存在 `observation.json`、`export.json`、`authority.save`、`run-snapshot.json`、`ownership.json`、`player-package.json`、`attempts/<n>/launch.json`、`exit.json`、build log/source diff 的 observation；并核对 PID/start/path/hash、一次性 challenge、phase、整包清单、构建 commit/日志、run ownership。
7. **显式信任边界**：仍不把普通 SHA 说成签名。`realPassGate=PLAYER_EXPORT_CHAIN_VERIFIED_LOCAL_CONTROLLED` 明确表示本机受控测试，不是生产 provenance。

### 2.2 导出字段

`authority.save` 为只读复制。`export.json` 记录：

- phase、runId、attempt、一次性 challenge、PID、进程 start UTC、进程路径、Player exe SHA-256；
- 整包清单 SHA/文件数、sourceHead、buildCommit、buildProvenance、rulesetVersion、capturedAt；
- authority 文件字节/SHA；
- facts：roomId、roundId、stateVersion、eventSeq、stateFingerprint、stateHash、controlVersion、controlEpochs[4]、cheatVersion/Fingerprint；
- requests：accountId + scopeId + requestId + receiptId + confirmed + status + `payloadSha256`（`TablePayloadSha256.ToHex()` 真值）+ evaluated/command/event 版本；
- ledger：points、initialPoints、balances[4]、entryCount、entriesSha256、balancesSha256、totalVersion、checkpointVersion、source=`LATEST_PERSISTED_CHECKPOINT`；
- physical：tileCount=136、uniqueCount=136、wallCount、deadWallCount、tilesSha256。

`sessionId`、`cursor`、`ownerEpoch` 明确列入 `excludedMutableFields`；重连游标变化不参与必需相等。

### 2.3 账本边界

本导出只使用持久化 envelope 中的最新完整 checkpoint 账本，不重放 cheat operation。`ledger.source=LATEST_PERSISTED_CHECKPOINT` 和 `checkpointVersion` 随事实一起导出/比较。本次 baseline 无三绝技动作，账本 0 entries、四席 120 点；本报告不声称“全量绝技账本回放”。

## 7. 明确缺口（不得被本交付掩盖）

1. **本机受控边界**：导出链的信任来自同一台机器上的 run ownership、进程身份、一次性 challenge、整包清单、构建日志和封存 collection。它不抵御本机管理员/调试器/内核级伪造，不是生产签名信任根，也不证明远端 CI 或发布 provenance。
2. **Probe 为 opt-in 诊断路径**：`-p45-recovery-export` 存在时才启用；该分支在捕获后暂不启动 autoplay，避免 AFTER/BEFORE 之间产生新 AI 动作。生产默认路径不受影响。该行为必须被视为受控测试 seam，不是产品玩法验收。
3. **完整 P4.5 未执行**：没有完成整场、连庄/终局、三绝技、AI 托管/收回、流局/和牌、观战隐私、LOCAL 资产隔离的正式执行；本次只验证恢复导出/Compare。
4. **账本只读最新 checkpoint**：没有 cheat operation replay；本次 baseline 0 entries，不能外推三绝技账本恢复。
5. **Before/After 是同一 v3 基线**：没有在恢复后提交新动作；这证明恢复一致性，不证明恢复后继续游戏的完整路径。
6. **Android/iOS/IL2CPP/真机/跨物理网络**：NOT_RUN；Windows 结果不能推导其他平台。
7. **视觉证据**：本任务未采集/使用可见截图；没有视觉布局/动画通过声明。
8. **G2–G5/PR20**：未通过、未接受；V4 仍是生产架构。
9. **公开日志脱敏**：沿用原有 fail-closed 策略；Player 日志中的不可解析 JSON-like 片段仍可能使 public copy withheld，原始件只在 private。
