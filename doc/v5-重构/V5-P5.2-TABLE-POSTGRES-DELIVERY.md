| `LoadCheckpointAsync` | 最新 `state_version` checkpoint | 解密 + 校验 hash，损坏抛错 |
| `LoadTimingAsync` | 最新 `table_timing_journal` | 解密 + codec 解码 |

### 3.3 `CommitAsync` 事务顺序

所有路径先在事务内取：

```text
pg_advisory_xact_lock(hashtextextended(room_id, 0))
```

之后严格按冻结顺序：

1. 房间存在性检查；
2. 回执查重 `FOR UPDATE`：
   - 同 API + 同 payload SHA-256 → `Replayed`，不重执行；
   - 异 API/异 payload → `Conflict`；
3. scope `FOR SHARE`：
   - 不存在/账户/角色/房间不符 → `ScopeRejected`；
   - revoked/expired → `ScopeRejected`；
4. lease `FOR UPDATE` + owner/epoch/expiry；
5. `table_state FOR UPDATE` + stateVersion CAS；
6. accepted 时：
   - timingVersion 必须 `state.timing_version+1`；
   - 事件非空、ordinal 从 0 连续、seq 连续、commandVersion 全等于 `expected+1`；
   - command journal 版本一致；
   - checkpoint 与 state/control/timing/ruleset 一致，并通过 `TableCheckpointValidator`；
   - committed facts hash 校验；
   - 事件、command journal、timing journal、checkpoint、facts、outbox 全部写入；
   - `UPDATE table_state ... WHERE state_version=expected`，行数必须为 1；
7. rejected（非 forced-state）只写回执，不写事件、不推进 state/version；
8. 写 receipt；
9. 写 outbox（同 key 同 hash 幂等；异 hash 冲突并整事务回滚）；
10. 提交边界再次 `FOR SHARE` 读 scope，用 `clock_timestamp()` 判定 revocation/expiry；
11. `tx.Commit()` 成功后才返回；actor 只在返回后发布。

返回码：

| disposition | 触发 |
|---|---|
| `Committed` | COMMIT 成功 |
| `Replayed` | 已存在同 key 同 API/同 payload |
| `Conflict` | 同 key 异 API/异 payload |
| `StaleOwner` | owner/epoch 不符或 lease 过期 |
| `StaleState` | expected stateVersion 不符，或 accepted timing 不是下一版 |
| `ScopeRejected` | scope 不存在/账户/角色/房间/revoked/expired |
| `Failed` | 提交前 SQL/约束/编码/outbox 冲突等失败 |
| `OutcomeUnknown` | COMMIT 已发出后连接/响应异常，或 commit 后测试故障 |
| `Cancelled` | commit 前取消 |

REJECTED、forced-state rejection、internal command 的区分：

- 普通 REJECTED：回执 `REJECTED`，`command_version=NULL`、`event_seq=NULL`，state_version 不变；
- P1.4 forced-state rejection（`RejectedWithState`）：回执仍 `REJECTED`，但私有 state/events/journal 同事务持久化；这是既有 P3.4 合同语义，不是普通拒绝；
- internal tick/AI：无回执，仍有 event/journal/state，必须有事件。

## 4. Scope、租约与恢复

### 4.1 scope

`PostgresTableStore` 同时实现：

- `IRequestScopeAuthority.LookupAsync`；
- `ITableTransactionalScopeReader.BeginScopeForCommit`（独立事务实现，供合同测试使用；生产 commit 在自身事务内重读 scope，不依赖预检查）。

host 辅助方法 `IssueScopeAsync` / `RevokeScopeAsync` 用真实 `request_scope` 行。

已有回执优先于 scope 检查：scope 后续撤销/过期，原回执仍可查、可 replay；无回执的旧/撤销 scope 零副作用。

### 4.2 租约

- 每房间一行 `table_lease`；
- `ownerEpoch` 每次成功 acquire/recover 后递增；
- 同一事务内 lease fence 与 `state_version` CAS 独立，任一失败整事务回滚；
- 旧 owner 即使进程还活着，第一次写就 `StaleOwner`；
- 续租失败后 actor 停止/发布 lease-lost，不再写权威状态。

### 4.3 冷恢复

`TableRecoveryService` 使用真实 PG store/lease/outbox：

- 取最新 checkpoint；
- 读 `table_event.command_version > checkpoint.state_version`；
- 读 command journal；
- 用真实 Domain `RoundRecoveryCodec` / `RoundRecovery.Restore` 重放；
- 校验 state hash、state fingerprint、136 张物理守恒、event seq/ordinal 连续、command version 连续、账本/控制时钟、outbox；
- bad checkpoint hash、坏 event blob、缺 event、缺 command、state fingerprint 篡改、重复 tile id 均 `Failed`，没有 skip；
- 恢复期间不接命令由 `TableActor`/`TableRecoveryService` 既有生命周期保证；本任务未改其规则。

### 4.4 结算 outbox

- 只有在 `TableDurableCommitRequest.Terminal=true` 时才允许 outbox；构造器拒绝非终局 outbox；
- outbox 与 event/receipt/state 同事务；
- 同 `(matchId,resultVersion)` 同 payload 幂等跳过；异 payload 返回 `OUTBOX_CONFLICT` 并整事务回滚；
- 消费合同：`TryGet` / `ListUnpublished` / `MarkPublished`；
- 未实现钱包/余额/入账；未开放任何资产功能。

## 5. Payload 加密与安全

- 所有 sensitive durable payload（state/control/timing/cheat/facts/history/bindings/event/command/outbox/receipt response）使用 **AES-256-GCM**；
- 外部 key：`MAHJONG_TABLE_PG_PAYLOAD_KEY`，32 字节 base64；也支持调用方从 secret store 传入；
- AAD 绑定 `schema|format|purpose|room|version/seq`，把密文复制到其他行会解密失败；
- 密文格式：`MJP1` + 12B nonce + 16B tag + ciphertext；
- 数据库只保存 ciphertext + 独立 SHA-256；不写 key、连接密码、明文 payload；
- key 缺失/非 base64/长度不符 → `PostgresTableConfigurationException`，fail closed；
- 日志/异常只输出 SQLSTATE/类型，不回显连接串/key；
- 未实现密钥轮换：当前一个 key/版本绑定所有 sealed payload；轮换需要受控重加密迁移，明确 **NOT_RUN**，不静默 fallback。

测试已验证：missing key 抛错；runtime 角色 DDL 被拒；DB 的 facts/outbox 字节中不含明文 marker；解密后值正确。
