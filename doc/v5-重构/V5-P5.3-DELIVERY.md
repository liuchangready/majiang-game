## 1. 审查阻断项与返修

### R1 游客身份接管（已修复）

原实现按调用者提供的 `deviceId` 查找账号并直接签发新 bearer，`deviceId` 实际成为认证凭据。现改为：

- `deviceId` 只是公开去重/显示提示；`POST /v1/auth/session` 必须携带客户端 CSPRNG 生成并本地保存的 `bootstrapSecret`（32–128 个 URL-safe 字符）。
- 服务端只存 `bootstrap_hash = SHA-256(bootstrapSecret)`；账号键为 `(device_digest, bootstrap_hash)`。
- 幂等回执 principal 为 `"bootstrap:" + canonical(device_digest, bootstrap_hash)`；仅知道 `deviceId + requestId` 不能回放 Victim 的 session token。
- 同 `(deviceId, bootstrap)` 的不同 requestId 是合法双开（同账号、不同 session）；不同 bootstrap 是不同账号；丢失 bootstrap 则无法恢复，只能新身份。
- 缺失/弱格式 bootstrap 返回 `400 BOOTSTRAP_SECRET_REQUIRED` / `BOOTSTRAP_SECRET_INVALID`，不回退到 deviceId 登录。
- OIDC 仍未实现；没有把本机制扩展成账户体系。

- `GuestSessionTests.SameRequestIdWithDifferentBootstrapCannotReplayTheVictimToken`
- `GuestSessionTests.SameDeviceAndBootstrapIsLegitimateDoubleOpenAndIdempotentReplay`
- `HttpRouteTests.HttpDeviceReuseWithoutBootstrapCannotObtainVictimSessionOrTicket`（真实 Kestrel loopback HTTP）

### R2 跨房双席位（已修复）

原实现只检查当前房间 active assignment，数据库唯一索引也是 `(room_id, account_id)`。现改为：

- 同一账号全局最多一个 active lobby assignment（`RESERVED|CONFIRMED`），跨房间、跨玩家/观战角色一致。
- 建房、加房、观战、匹配入口统一用 `FindAnyActiveAssignmentForAccountAsync`；账号级 advisory lock（PostgreSQL）与全局事务序列化（内存）保证 create-vs-join / match-vs-join 不双写。
- 存储最终约束：`uq_assignment_active_account ON lobby.assignment (account_id) WHERE status IN ('RESERVED','CONFIRMED')`；内存 `EnsureAssignmentUnique` 同样全局拒绝。应用预检不是唯一栅栏。
- 签发/消费票据前检查该账号所有 active assignment；历史遗留双预订以 `409 ACCOUNT_ALREADY_SEATED` 拒绝继续消费，不能继续产生双席位。
- 取消/过期释放 assignment 后，唯一约束释放，可重新加入。

### R4 已关闭房间仍可分配/签票/消费（已修复）

原实现只用 `lobby.room.state`（始终 Open）做准入；`GetRoom`/目录虽按投影显示/隐藏 CLOSED，但 Join/Issue/Consume 不读取终态。

现改为：

- 同 `rulesetVersion` 的公开投影 `CLOSED`/`FINISHED` 在独立存储事务中单调落入 `lobby.room.state=CLOSED`、写 `closed_at`，并取消该房所有 `RESERVED|CONFIRMED` assignment；该事务提交后，准入/票据事务再以 `409 ROOM_CLOSED` 拒绝。
- `JoinRoomAsync`、`SpectateRoomAsync`、`IssueTableTicketAsync`、`ConsumeTableTicketAsync` 全部在应用端口执行终态对账与持久化房间检查；不是只隐藏目录或只挡 HTTP。
- 已签发旧票据在关闭后消费被拒绝，且不写 `table_ticket_consumption`、不写 `table_confirmed_at`；关闭后新签发也拒绝。
- 新增 `POST /v1/rooms/{id}/reconcile`（`ReconcileRoomAsync`）：显式观察公共投影并落入终态/释放 placement；重复同键对账幂等回放。
- 终态单调：关闭后缺失/失败/旧 `OPEN|PLAYING` 投影不会重开房间；不同 `rulesetVersion` 的 CLOSED 投影不当成同一房间终态。
- 终态释放后账号全局 placement 解除，可加入其他房间；匹配 reservation 也会转 `CANCELLED`，避免 `ALREADY_QUEUED` 继续占用账号。
- 缺失/读取失败投影仍是明确降级：不关闭、不伪造；`projectionStale=true`，准入按 lobby 自有状态继续。该边界是最终一致，不是 TableService 强一致。

### R5 对账幂等摘要被服务端状态污染（已修复）

原 `ReconcileRoomAsync` digest 含事务外推导的 `terminal` 值，属于可变服务端观察而非客户端请求语义。首次成功对账后只要 snapshot/投影变化，同账号/同 roomId/同 requestId 的合法重试就变成 `REQUEST_ID_CONFLICT`；可控并发场景下首次响应已 CLOSED，重试仍 409。

现改为：

- digest 只由稳定请求语义 `("room.reconcile.v1", roomId)` 决定；不包含 snapshot、投影、terminal、生命周期或时间。
- 同账号/同 roomId/同 requestId 的重试在 receipt 层直接回放首次已提交响应，不重新执行关闭/释放等副作用；即使期间另一请求已关闭房间。
- 同 key 换 roomId 或换操作仍因 digest 不同返回 `409 REQUEST_ID_CONFLICT`；新的对账观察使用新 requestId。
- 终态单调、并发旧读不重开、旧票据不复活、关闭/释放与回执事务一致性不变。

回归：

- `RoomTerminalTests.ConcurrentTerminalObservationDoesNotChangeReconcileReceiptDigest`（可控投影等待，非概率 Task.WhenAll）
- `RoomTerminalTests.NonTerminalReconcileThenTerminalSameKeyReplaysTheOriginalResponse`（先 NON_TERMINAL，后终态同 key 回放；新 key 才关闭）
- `RoomTerminalTests.SameReconcileKeyForDifferentRoomIsARealConflict`
- `RoomTerminalTests.SameReconcileKeyForDifferentOperationIsARealConflict`
- 审查方 R5 探针：`RECONCILE_FIRST: status=200, state=CLOSED, replayed=False`；`RECONCILE_RETRY: status=200, replayed=True, sameBody=True`

### R6 已完成回执被终态预检截断（已修复）

原 Join/Spectate/Issue 在 `ExecuteIdempotentAsync` 之前读取房间/投影并在终态时抛错；已提交 receipt 没有机会查询，导致同 key 同 payload 的成功请求在房间关闭后变成 `409 ROOM_CLOSED`。

现改为：

- 所有 receipt 型副作用入口先执行 `TryReplayAsync(key, stablePayloadDigest)`：已提交回执在读取房间/assignment/投影之前直接回放原 status/body，并标记 `Replayed`。
- Join/Spectate/Issue 的可变状态检查与终态关闭移入首次执行的事务；回放路径完全不读取、不修改房间/assignment/投影，也不重做副作用。
- 首次执行遇终态时，在 receipt 事务内关闭房间、取消 assignment/匹配 reservation，并写入 409 回执后提交；应用层在提交之后抛出 `ROOM_CLOSED`，不会回滚关闭。新 key 首次执行仍拒绝 CLOSED/FINISHED。
- 同 key 换 room/换操作/换有效 payload 仍由 digest 差异产生 `REQUEST_ID_CONFLICT`。
- `CreateRoom/CreateGuest/CreateMatch/Cancel/Reconcile` 同样先查回执再执行可变/策略检查（Reconcile 的稳定 digest 见 R5）。
- 旧票据 Consume 不属于 receipt 回放；终态后仍拒绝 `ROOM_CLOSED`，不因历史回放复活资源。

回归：

- `RoomTerminalTests.CompletedJoinSpectateAndIssueReceiptsReplayAfterTerminal`（CLOSED/FINISHED；同 key 201/body/Replayed，新 key 拒绝，回放不重建 assignment/不签新 jti，旧票据仍拒绝）

- `RoomTerminalTests.UsedIssueKeyForDifferentAssignmentConflictsBeforeStateChecks`

## 5. 未覆盖与集成缺口

- PostgreSQL 仍是 **NOT_RUN**：没有真实实例，迁移未执行；部分唯一索引、advisory/row lock、事务回滚、重启后回执/票据对账、冷恢复未验证。内存测试不能称为持久化通过。
- `001_lobby.sql` 按 greenfield 方式修改（account bootstrap 列/全局 assignment 唯一索引）；从未有 DB 应用旧版，因此未提供旧 001→新 001 的升级迁移。真实 DB 验收前必须确认部署库是空库，或另立升级迁移。
- 无真实 HTTPS/TLS、证书、反向代理、公网入口；仅 loopback HTTP 测试。
- 无真实 TableService 联调：票据消费只有 `ConsumeTableTicketAsync` 应用端口，没有 WSS 握手/租约/ownerEpoch/顶号链路。
- 无 WSS 大厅推送/观战延迟；目录与匹配靠轮询。观战延迟非 0 会拒绝启动，不伪造。
- 房间终态依赖调用准入/票据/对账时“观察到的”公共投影；投影落后或读取失败时，准入仍可能按 lobby 自有 Open 状态短暂发生，随后对账关闭并释放。未实现 TableService outbox 主动推送终态，也不把缺失投影当 CLOSED。
- 未实现会话刷新/登出/删号、离开房间/角色切换、OIDC/账户/资产、数据保留清理/导出、限流、生产部署/压测。
- `bootstrapSecret` 丢失后的恢复/迁移未实现；以新 secret 创建新游客身份，不把 deviceId 当恢复凭据。
- 产品未决项仍以显式临时配置限制：游客排位默认关闭、观战延迟为 0、匹配规则固定 FIFO、数据保留为临时值。
