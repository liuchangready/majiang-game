## 1. 审查阻断项与返修

### R1 游客身份接管（已修复）

原实现按调用者提供的 `deviceId` 查找账号并直接签发新 bearer，`deviceId` 实际成为认证凭据。现改为：

- `deviceId` 只是公开去重/显示提示；`POST /v1/auth/session` 必须携带客户端 CSPRNG 生成并本地保存的 `bootstrapSecret`（32–128 个 URL-safe 字符）。
- 服务端只存 `bootstrap_hash = SHA-256(bootstrapSecret)`；账号键为 `(device_digest, bootstrap_hash)`。
- 幂等回执 principal 为 `"bootstrap:" + canonical(device_digest, bootstrap_hash)`；仅知道 `deviceId + requestId` 不能回放 Victim 的 session token。
- 同 `(deviceId, bootstrap)` 的不同 requestId 是合法双开（同账号、不同 session）；不同 bootstrap 是不同账号；丢失 bootstrap 则无法恢复，只能新身份。
- 缺失/弱格式 bootstrap 返回 `400 BOOTSTRAP_SECRET_REQUIRED` / `BOOTSTRAP_SECRET_INVALID`，不回退到 deviceId 登录。
- OIDC 仍未实现；没有把本机制扩展成账户体系。

回归：

- `GuestSessionTests.SameDeviceWithoutTheBootstrapSecretCannotTakeOverAVictimAccount`
- `GuestSessionTests.SameRequestIdWithDifferentBootstrapCannotReplayTheVictimToken`
- `GuestSessionTests.SameDeviceAndBootstrapIsLegitimateDoubleOpenAndIdempotentReplay`
- `HttpRouteTests.HttpDeviceReuseWithoutBootstrapCannotObtainVictimSessionOrTicket`（真实 Kestrel loopback HTTP）
- 独立探针：`R1_FIXED: sameVictimAccount=False, freshToken=True, victimSeatConsumed=False, denial=ASSIGNMENT_NOT_FOUND`

### R2 跨房双席位（已修复）

原实现只检查当前房间 active assignment，数据库唯一索引也是 `(room_id, account_id)`。现改为：

- 同一账号全局最多一个 active lobby assignment（`RESERVED|CONFIRMED`），跨房间、跨玩家/观战角色一致。
- 建房、加房、观战、匹配入口统一用 `FindAnyActiveAssignmentForAccountAsync`；账号级 advisory lock（PostgreSQL）与全局事务序列化（内存）保证 create-vs-join / match-vs-join 不双写。
- 存储最终约束：`uq_assignment_active_account ON lobby.assignment (account_id) WHERE status IN ('RESERVED','CONFIRMED')`；内存 `EnsureAssignmentUnique` 同样全局拒绝。应用预检不是唯一栅栏。
- 签发/消费票据前检查该账号所有 active assignment；历史遗留双预订以 `409 ACCOUNT_ALREADY_SEATED` 拒绝继续消费，不能继续产生双席位。
- 取消/过期释放 assignment 后，唯一约束释放，可重新加入。

## 5. 未覆盖与集成缺口

- PostgreSQL 仍是 **NOT_RUN**：没有真实实例，迁移未执行；部分唯一索引、advisory/row lock、事务回滚、重启后回执/票据对账、冷恢复未验证。内存测试不能称为持久化通过。
- `001_lobby.sql` 按 greenfield 方式修改（account bootstrap 列/全局 assignment 唯一索引）；从未有 DB 应用旧版，因此未提供旧 001→新 001 的升级迁移。真实 DB 验收前必须确认部署库是空库，或另立升级迁移。
- 无真实 HTTPS/TLS、证书、反向代理、公网入口；仅 loopback HTTP 测试。
- 无真实 TableService 联调：票据消费只有 `ConsumeTableTicketAsync` 应用端口，没有 WSS 握手/租约/ownerEpoch/顶号链路。
- 无 WSS 大厅推送/观战延迟；目录与匹配靠轮询。观战延迟非 0 会拒绝启动，不伪造。
- 未实现会话刷新/登出/删号、离开房间/角色切换、OIDC/账户/资产、数据保留清理/导出、限流、生产部署/压测。
- `bootstrapSecret` 丢失后的恢复/迁移未实现；以新 secret 创建新游客身份，不把 deviceId 当恢复凭据。
- 产品未决项仍以显式临时配置限制：游客排位默认关闭、观战延迟为 0、匹配规则固定 FIFO、数据保留为临时值。
