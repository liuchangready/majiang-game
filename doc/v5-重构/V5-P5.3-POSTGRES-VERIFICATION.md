## 8. 验证过程中发现并修复的问题

这些问题都在**本次新增的验证脚手架**中，不涉及已验收的 Lobby 业务合同：

1. 重启写阶段原先把同一账号 Join 两次（第二次必然 `ALREADY_ASSIGNED`）。
   改为只 Join 一次并保存该次 receipt。
2. `pg_ctl start` 的 postgres 子进程继承调用方输出管道，导致脚本在部分宿主
   中挂起。改为隐藏窗口 + 文件重定向，并以 `pg_isready` 作为兜底判据。
3. Windows PowerShell 将 psql 的无害 `NOTICE` 当作终止错误。改为捕获
   native stderr 文本后按退出码判断。
4. `dotnet test` 的本地化/两种 summary 格式导致计数解析失败。解析器同时支持
   `Total/Errors/Failed/Skipped`、`Failed/Passed/Skipped/Total` 与中文格式。
5. 字符串中 `$var:` 的 PowerShell 作用域歧义（migrate/cleanup）已改为 `${var}:`。
6. 证据 summary 原先在 cleanup 前写入，未记录 cleanup；已改为 cleanup 后写。

未发现需要修改 `PostgresLobbyStore` 或 `001_lobby.sql` 的实测缺陷。
