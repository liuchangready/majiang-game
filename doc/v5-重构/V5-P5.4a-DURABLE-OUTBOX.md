## 1. 第 1 轮缺陷与修复

### 1.1 写读字段上限不对称（P1）

**缺陷**：`WriteResolution` 使用 1024 字节通用上限写入 reason，`ReadResolution` 却按 512 字节读取。`OutboxResolution.FromReceipt(Rejected, new string('r', 513), ...)` 可成功 `ResolveAsync`，但新的 store 实例重开会抛 `OutboxStoreCorruptException`，即一次“成功”的原子提交把可读数据库替换成自身不可读的文件。

**修复**：

- 所有字符串字段改为**同一个写入/读取校验器**：`FileOutboxFormat.WriteString` 与 `ReadString` 使用相同的每字段上限。
- `MaxIdBytes = 512`、`MaxReasonBytes = 512`、`MaxDigestBytes = 64`；不再存在 1024 与 512 的字段差异。
- `ValidateResolutionForWrite` 与 `ValidateEntryForWrite` 都在原子提交前检查 UTF-8 字节长度；reason 512 ASCII 字节可往返，513 字节在任何临时文件创建前被拒绝，旧快照字节与未决记录保持不变。
- `WriteSnapshot` 在创建临时文件前对编码结果执行一次 `FileOutboxFormat.Decode(bytes, ...)` 回读自检；任何编码/解码不对称都会在替换前失败，而不是落盘后才发现。

### 1.2 `ValidateResolution` 语义校验不完整（P1）

**缺陷**：旧实现只校验 `Unspecified` 与 digest 形状。以下输入能成功 resolve，但重开即损坏：

- `Applied` + `committedAtMs: 0`；
- `new OutboxResolution(Applied, Rejected, "REJECTED", ...)`（disposition/status 不一致）。

**修复**：`FileOutboxFormat.ValidateResolutionForWrite` 成为写入、读取与提交前自检的唯一语义入口，覆盖：

- `OutboxDisposition` / `ReceiptStatus` 必须为已定义值且非 `Unspecified`；
- `Applied` / `Recorded`：status 一致，`commandVersion == evaluatedStateVersion + 1`（含 `ulong.MaxValue` 溢出边界），`eventSeq` 存在且 > 0；
- `Rejected`：status 必须为 `Rejected`，reason 非空，禁止 `commandVersion` / `eventSeq`；
- `Conflict`：status 必须为 `Unknown`，evaluated=0，禁止 commandVersion/eventSeq/committedAt，`FromReceiptLookup` 必须为 false；
- `committedAt` 若存在必须 > 0；
- reason 的 UTF-8 字节上限、digest 必须为空或 64 位十六进制、非配对 surrogate 拒绝；
- 读取路径用 `new OutboxResolution(...)` 重建后调用同一个 validator；任何不一致都转为 `OutboxStoreCorruptException`，不会把坏文件当空库。

## 2. 回归测试

新增/调整的回归测试覆盖三类原始复现及其邻接边界：

### 2.1 原始三类复现

1. `ReasonAt513AsciiBytesIsRejectedBeforeCommitAndSnapshotIsUnchanged`：513 ASCII reason 在 `ResolveAsync` 抛 `ArgumentException`；文件字节完全不变；重开仍读到原未决记录。
2. `AppliedWithZeroCommittedAtIsRejectedBeforeCommit`：`Applied` + `committedAtMs: 0` 在提交前失败，旧快照不变。
3. `DispositionAndReceiptStatusMismatchIsRejectedBeforeCommit`：`Applied` + `Rejected` status 在提交前失败，旧快照不变。

### 2.2 边界与邻接

- ASCII reason 512 字节成功并可由新实例读取；513 字节拒绝。
- UTF-8 双字节：256×`é`=512 成功；257×`é`=514 拒绝。
- UTF-8 三字节：170×`中`=510 成功；171×`中`=513 拒绝。
- UTF-8 四字节：128×emoji=512 成功；129×emoji=516 拒绝。
- `Applied` 缺失/错误 `commandVersion`、0/缺失 `eventSeq`、`ulong.MaxValue` evaluated 边界。
- `Rejected` 空 reason、携带 commandVersion。
- `Conflict` 非零 evaluated、携带 commandVersion/committedAt、`FromReceiptLookup=true`、status 非 Unknown。
- 未定义 disposition/status 枚举、63 字符或非十六进制 digest、非配对 surrogate。
- 合法的 `Applied`、`Rejected`（含正 committedAt）与静态 `Conflict` 均可往返读取。

## 3. 持久性、恢复与安全边界

### 3.1 已实现

- 版本化快照 `MJOUTBX1`，保存 account/scope/request、原业务字节与 digest、kind、schema、expectedStateVersion、round/decision/control/owner epoch、session/room、完整 scope 生命周期。
- 同键同字节且同元数据幂等；异字节/异元数据冲突；已解析键禁止再次保存。
- resolve 写 tombstone；重启不复活；重复同解析幂等；不同解析拒绝。
- 临时文件 → `Flush(true)` → `File.Replace` 原子替换；进程内信号量 + 跨进程 `.lock` 文件。
- 取消/提交失败/半写临时文件/重复打开/并发写/容量上限/损坏检测。
- 未知结果重启后由既有 `TableSession` 先发 `RECEIPT_QUERY`，不重发 `COMMAND`、不改 requestId。
- 传输 ticket 不写入；带 `ResumeToken` 的恢复命令被明文文件 store 显式拒绝，要求平台安全存储。

### 3.2 未验证/边界

- Windows 10 19045 + NTFS 临时目录，.NET SDK 8.0.426，x64；进程终止使用 Windows `TerminateProcess` 语义。
- 未验证真实断电、磁盘缓存丢失、硬件坏道、目录项独立 fsync、ACL 最小权限、Unix/macOS、Android/iOS app sandbox 与 fsync、IL2CPP/Mono。
- 文件为明文、未加密；调用方必须使用 app-private 目录。token-bearing 恢复命令的持久化应走平台安全存储，本任务未实现该适配器。
- 不支持原子 replace 的文件系统不会被静默降级为“删除再改名”。
- 真实 WSS、PostgreSQL、票据服务与端到端远端对账未运行。
