## 2. 实现内容

### 2.1 可信 settlement facts port

新增 `TableServiceSettlementFactsPort : ITableSettlementFactsPort`
（`dotnet/src/Mahjong.TableService/TableSettlementAuthority.cs`）：

- `Resolve` 只使用 actor 的 exact committed round + actor committed
  `TableFuritenSnapshot`；校验 roundId、round version、source fingerprint 与
  furiten roundId。缺失/异源抛 `InvalidOperationException`，actor 转
  `SETTLEMENT_FACTS_UNAVAILABLE`，**不默认 false**。
- 四个座位固定生成记录；ippatsu 从 committed event chain 重放（riichi 声明、无真实
  call/kan、至多一次自摸、只允许宣言打牌），不是配置默认值。
- 临时/立直振听从 actor committed snapshot 进入 host facts；
  `TableProjectionContextSource` 把两个 bit 持久化到 checkpoint 的 private facts，
  `TableActor` 恢复时再读回。恢复链有真实来源；无 PG 终局可做端到端重启验证。
- 不复制 calculator：Tsumo/Ron/Exhaustive/Abortive 全部由 actor 调
  `RoundSettlementCalculator`；客户端不发送役/符/分/支付/最终点数。

### 2.2 Client 动作映射

`TableCommandMapper`：

- `DeclareTsumo` / `DeclareRon` → `TableCommandRoute.Settlement` →
  `host.Actor.SubmitSettlementAsync`；保留 scope/role/seat/requestId/payloadDigest/
  round/decision/controlEpoch/deadline/state/owner/recoveryGeneration 门控。
- `DeclareAbortiveDraw`：只有 composition root 能从 committed round 证明
  NineTerminals/FourRiichi/FourKans/FourWinds 之一时才映射；否则 pre-actor 返回
  `SETTLEMENT_ABORTIVE_REASON_UNAVAILABLE`，零副作用；actor/calculator 仍二次校验。
- `DeclareAgariYame`：保持 `MATCH_AUTHORITY_UNAVAILABLE` fail closed；需要 match
  层 facts，下一依赖是 B2-R1-BLOCKER-03，不在本任务伪造 match。
- 观战在 mapper 前被 `SCOPE_ROLE_NOT_AUTHORIZED` 拒绝；错误 seat 为
  `ProtocolViolation`；raw settlement-bearing `SubmitAsync` 仍由 actor 的
  `SETTLEMENT_RAW_ENTRY_REJECTED` 拒绝；客户端伪造非和牌手牌被 calculator 拒绝。
- 候选：`TableDecisionRuntime` 用 frozen evaluator 的 `CanTsumo`/`CanRon` 推导
  Tsumo/Ron 候选；Ron 受 committed furiten 约束；actor 仍复算。Abortive 的 frozen
  `LegalActionKind` 没有对应值，**无法广告**（§7 MAJOR-01），但协议动作可直接映射。

### 2.3 可信 exhaustive-draw

`TableDecisionRuntime.AutoExhaustiveDrawAsync`：

- 只在 `RoundPhase.Draw && WallRemaining == 0` 触发；`wall > 0` 继续原
  `AutoAdvanceDrawAsync`。
- 通过 `TableActor.SubmitSettlementAsync` 的 durable 事务路径提交
  `TableSettlementAction.ExhaustiveDraw`；request identity 由
  round/stateVersion/seat 确定性构造（`svc-exhaustive-...`），同一 committed state
  只提交一次。
- 仅在拿到 control/seat/request 后、submit 前标记 attempt；并发 tick 在锁内复查，
  不会产生第二个 terminal request；异常/失败只记录，不发布、不直接改 round、不写 DB。
- decisionId 为 null（Draw 没有 open decision）；owner/control/state/version 仍由
  actor 校验；scope 使用房间自己的 service scope。
- 结果日志带 `status/reason/detail`，本任务的失败证据即由此得到。

### 2.4 终局投影

`TableProjectionContextSource`：

- Tsumo/Ron 事件的 yaku/han/fu/score 来自 `actor.LastSettlementCalculation`，并校验
  `SourceRoundId` 与 `ResultId`；不匹配 fail closed，不发布空/猜测役。
- ExhaustiveDraw/AbortiveDraw 事件补 tenpai + finalScores；RoundEnded 补
  finalScores（frozen contract 必需，checkpoint validator 会重建该投影）。
- 该处只读 actor 已接受的计算；客户端仍无结算字段。
