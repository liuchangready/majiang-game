### B2-R1-03 / MAJOR / abortive 原请求重放

**位置**：`TableSessionHandler.cs` `TryBuildAbortiveReplayAsync` 与
`DispatchCommandAsync` 的 `PreActorRejection` 分支；`TableCommandMapper.cs` 的
abortive reason 映射。

**实际（修复前）**：流局成功后 round 已 terminal，live abortive reason resolver 返回
null，mapper 在 actor 前返回 `SETTLEMENT_ABORTIVE_REASON_UNAVAILABLE`；原 envelope
原 scope/requestId/payload 重发无法到达回执账本。

**修复**：
- 当 mapper 返回 abortive reason unavailable 时，先按原身份/可选历史 scope 查询
  `Actor.QueryReceiptAsync`；只有 Found 才构造 replay 探测 intent（非当前 round +
  placeholder reason）交给 `SubmitSettlementAsync`。
- actor 的 receipt-first 路径按 account/scope/requestId/API/digest 返回 Replayed；
  digest/API 不同返回 Conflict；若 receipt 在查询后消失，placeholder round 会在
  core 前被拒绝，不会创建新终局。
- 保留原 requestId、API `SUBMIT_ACTION`、payload digest、scope、round/decision/
  control 等 fencing；不按当前终局原因伪造新请求。

**新证据**：
- `AbortiveDraw_OriginalRequestReplaysFromReceiptAfterRoundEnd`：真实 Kestrel/wire；
  首次 Applied → RoundEnd；原 envelope 原样重发 → Applied + Replayed=true，版本/
  事件/outbox 不增。
- 同 requestId 不同 payload digest → `REQUEST_ID_CONFLICT`，outbox 仍 1。
- 未证明原因的新流局请求仍 pre-actor fail closed（既有
  `AbortiveDraw_WithoutProvableReason...`）。

**未跑**：新连接/重绑定历史 scope 的 replay 测试尝试未稳定通过，已移除该测试；
实现保留 `envelope.Scope` 的历史 scope 授权路径，但标记 **NOT_RUN**，不声称已验证。

### B2-R1-04 / MAJOR / 短暂失败锁死耗墙终局

**位置**：`TableDecisionRuntime.cs` `AutoExhaustiveDrawAsync`（原 372–400）。

**实际（修复前）**：提交前设置 `_exhaustiveAttemptedRoundId/version`；一次
fail-before-commit 后永久不再提交，即使 actor 未 paused、state version 未前进。

**修复**：
- 以 `(round, stateVersion)` 为单位维护 `_exhaustiveInFlight`、`_exhaustiveAttempts`、
  `_exhaustiveStopped`、`_exhaustiveFailure`；in-flight 时并发 tick 不重复提交。
- 已知未提交可恢复 `Failed`（如 `COMMIT_TEST_TRANSIENT`/`COMMIT_FAILED`）按同一
  request identity 有界重试（上限 3），不做新 id。
- `CommitOutcomeUnknown` 先查询原 request 回执；Found 则记录
  `UNKNOWN_REPLAYED_ORIGINAL_RECEIPT` 并停止，未找到则
  `UNKNOWN_ORIGINAL_RECEIPT_NOT_FOUND`，绝不换 id 重做。
- `CheckpointInvalid`、stale owner/state、lease lost、cancelled 等确定性失败停止
  并在日志留下 reason；持久失败最多 3 次后停止，不每 tick 无限重打。
- 成功/Replayed 后停止；失败期间不发布、不直接改 round、不写 DB。

**新证据**：
- `TransientExhaustiveCommitFailure_RetriesSameIdentityAndSettlesOnce`：真实
  `ITableCommitPort` seam fail 一次，4 次 DriveAsync 后 finished，commitCalls=2。
- `ConcurrentExhaustiveTicks_SubmitOnlyOneInFlightRequest`：首 commit 阻塞时并发
  tick 不产生第二次 commit；释放后唯一终局。
- `PersistentExhaustiveCommitFailure_StopsAfterBoundedAttempts...`：8 次 DriveAsync，
  commitCalls 1–3，不无限重打。
- `CHECKPOINT_INVALID` 仍为 deterministic 外部阻塞；本轮未改 Runtime。

**未跑**：unknown-but-committed 的版本一致 durable harness。原因：`TableActor`
以 `_stateVersion=0` 构造，而真实耗尽局 round version 已 >0；要用真实
`InMemoryTableStore` 跑 unknown 需先重放到同版本，或伪造 receipt store。后者会违反
“不 fake receipts”，故只做源码路径审查并在 §6.3 标 NOT_RUN；不以 fake 回执冒充。
