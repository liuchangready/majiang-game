2. 拆分目标（移走什么、留下什么）
----------------------------------------------------------------
2.1 父层 MenuScreen 保留（唯一所有者，不下放）：
  - activeLobby / lobbyStateSub / roomUpdateSub 订阅的建立与注销
    （attachLobby/detachLobby 原语义不变）；
  - ClientRole / myViewerSeat / hasNavigatedToTable 角色与一次性导航守卫；
  - requestGeneration 代次守卫、runOnUi、isDisposed；
  - statusMessage / errorMessage 文案状态；
  - currentState 状态机与 show/hide/dispose 生命周期；
  - 全部异步业务流：单机启动链、openRemoteLobby 连接链、refreshRoomList、
    createRoom/joinRoom/joinSpectator/setReady/start/leaveRoom 的 whenComplete
    回调与状态写回、fetchRoomInfo、onRoomInfoUpdated；
  - 导航调用（navigation.showPlayerTable() 等）只发生在父层；
  - 背景/粒子渲染（renderBackground、FloatingParticle、animTimer）；
  - 秘籍/设置弹窗（SECRETS_MODAL/SETTINGS_MODAL 的渲染与点击，
    renderSecretsModal/renderSettingsModal/handleTouchModal 本任务不拆，
    原样留在父层）。
2.2 提取为同包新文件（类名可按此建议）：
  - MainMenuView：主菜单六按钮的渲染与命中上报（含标题文案）；
  - LobbyListView：大厅视图（左列按钮、房间列表 8 行、选中高亮、
    加入/观战按钮、连接状态文案）的渲染与命中上报；
  - RoomPreparationView：房间等待视图（四席位面板、准备/开局/离开按钮）
    的渲染与命中上报；
  - ConnectDialogView：TCP 连接弹窗（含 HOST/PORT 输入框、光标闪烁、
    keyTyped 字符过滤、键盘输入状态）；
  - CreateRoomDialogView：建房规则配置弹窗（半庄/码牌开关的本地翻转状态
    cfgIsHanchan/cfgShuffleCheating 归它所有，确认时把结果上报父层）；
  - JoinRoomDialogView：输码加入弹窗（含 ROOM_ID 输入状态）。
  允许把 ConnectDialogView/JoinRoomDialogView 的输入框逻辑抽一个包内
  共享的小助手（如 DialogTextInput），但不强制。
2.3 交互契约：子组件不持有 LobbySession、不持有 navigation、不发网络请求、
  不读写 requestGeneration。子组件接收"展示状态"（纯数据参数或自带展示
  字段），通过明确的意图回调上报，例如：
  - LobbyListView 回调：onCreateRoom / onJoinById / onRefresh / onBack /
    onRoomRowSelected(index) / onJoinSelected / onSpectateSelected；
  - RoomPreparationView 回调：onToggleReady / onStart / onLeave；
  - MainMenuView 回调：onPlaySingle / onOpenLobby / onToggleSkin /
    onSecrets / onSettings / onExit；
  - ConnectDialogView 回调：onConnect(host, port) / onCancel；
  - CreateRoomDialogView 回调：onConfirm(isHanchan, shuffleEnabled) / onCancel；
  - JoinRoomDialogView 回调：onConfirm(roomId) / onCancel，输入为空时按现行为
    置错误文案（错误文案所有权见 2.4）。
  禁止：子组件相互持有引用、持有父对象、新增万能 Context 参数对象、
  把一批字段改成 public 完成搬家。
2.4 状态所有权细则：
  - roomList / selectedRoom：大厅列表数据由父层持有（refreshRoomList 写入），
    LobbyListView 每帧接收参数绘制；行点击上报 index，父层写 selectedRoom。
  - currentRoomInfo / isMyReady / isHost：父层持有，作为参数传给
    RoomPreparationView 绘制。
  - inputHost/inputPort/inputRoomId 与 ActiveInput：归各对话框所有
    （ConnectDialogView 持有 HOST/PORT 两框状态；JoinRoomDialogView 持有
    ROOM_ID）。父层 keyTyped 按 currentState 转发给当前对话框。
    注意：现行行为是输入内容在弹窗关闭再打开后保留（字段在 Screen 级存活
    期限）——拆分后对话框实例由父层长期持有（随 MenuScreen 创建），保持
    "同一 MenuScreen 生命周期内输入保留"的现状，不得改成每次打开清空
    （现行唯一清空点：点击"输入房号加入"时 inputRoomId = ""，保留该语义）。
  - cfgIsHanchan/cfgShuffleCheating：CreateRoomDialogView 自有；确认时经
    onConfirm 上报，父层用它构造 MatchConfig。
  - statusMessage/errorMessage：父层唯一持有，绘制时传给需要的子视图。
2.5 渲染辅助：drawButton/drawInputBox/drawCenteredText/glyphLayout 移到
  包内共享助手（如 MenuViewDraw），各子视图与父层共用；UiAssets、字体、
  皮肤继续从 assets 借用，子组件不得自建/释放字体或纹理。

3. 布局与行为不变量（验收红线，逐项自查）
----------------------------------------------------------------
3.1 像素级布局不变：所有 Rectangle 常量与绘制坐标、字号 setScale、颜色、
  文案字符串必须与基线完全一致。MenuScreenTest 用固定坐标点击，举例
  （不完整清单，以基线源码为准）：
  - (640,495)=btnSecrets、(640,560)=btnSettings、(640,365)=btnOpenLobby、
    (640,425)=btnPlaySingle 附近区域；
  - (190,290)=btnLobbyRefresh、(190,160)=btnLobbyCreateRoom、(190,577)=
    btnLobbyBack、(780,530)=btnCreateCancel、(520,478)=btnTcpConnect、
    (760,500)=btnTcpCancel、(500,330)=rectHostInput。
  任何坐标/尺寸漂移都会打爆既有测试。
3.2 行为不变量：
  - 准备/开局跳转只发生一次：hasNavigatedToTable 置位逻辑原样保留
    （单机链、start 链、onRoomInfoUpdated 的 PLAYING 分支三处）。
  - 连接取消后迟到完成必须关闭迟到会话且不进大厅：CONNECTING 态 ESC/
    取消走 requestGeneration++ 分支（handleTouchTcpDialog 的 btnTcpCancel
    与 keyDown 的 CONNECTING 分支都保留 ++ 语义）。
  - 刷新后选中保留：refreshRoomList 成功后 selectedRoom = roomList.firstOrNull()
    的现行语义不变（列表刷新会重置到首行，这是现状，不要"改进"）。
  - 大厅返回：detachLobby + lobbyToClose.close() + navigation.leaveToMenu()
    顺序与 runOnUi 回主菜单语义不变。
  - keyDown 的 ESC 分支表、keyTyped 的字符过滤规则（HOST 允许 a-z A-Z 0-9
    . -；PORT 仅数字限 5 位；ROOM_ID 字母数字限 12 位；\b 退格）逐字保留。
  - show() 里 Gdx.input.inputProcessor = this；dispose() 幂等（isDisposed、
    requestGeneration++、detachLobby）；hide() 空实现保持。
  - runOnUi 的 expectedGen 判空语义与 Gdx.app 判空兜底逐字保留。
3.3 订阅不重复：attachLobby 先 close 旧订阅再建新订阅；init 块对
  initialLobby 的 attachLobby 调用保留；拆分后订阅仍只在父层创建/注销一次，
  子组件绝不自己订阅 LobbySession。
