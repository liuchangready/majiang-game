2. 任务 A：定义 TableBoardRenderModel（common/render/TableBoardRenderModel.kt）
----------------------------------------------------------------
纯公开数据快照，字段仅限（全部不可变 defensively-copied，风格对照
OpponentHandRow）：
  viewerSeat: Int
  isSpectator: Boolean
  roundWind/roundNumber/honbaSticks/riichiSticks/wallRemaining: Int
  doraIndicators: List<TileView>
  markedDoraIndicatorIds: Set<Int>          // 落汗 EXPOSED_INDICATOR 的 tileId
  scores: List<Int>
  riichiStatus: List<Boolean>
  currentTurnPlayer: Int
  discards: List<List<TileView>>
  riverMarkedTileKeys: Set<RiverMarkedTile> // data class RiverMarkedTile(seat, discardIndex, tileId)
  melds: List<List<MeldView>>
  markedMeldTileIds: Set<Int>               // 落汗 EXPOSED_MELD 的 tileId
  opponentHandRows: List<OpponentHandRow>   // 复用既有类型；观战映射时槽位全 null
  viewerHandBackCount: Int                  // 玩家模式恒 0；观战=handTileCounts[viewerSeat]
  clocks: List<ClockInfo>
配两个工厂（放同文件或 TableBoardRenderMapper.kt）：
  fromPlayerSnapshot(snapshot: GameSnapshotView): TableBoardRenderModel
    —— viewerSeat=snapshot.viewerSeat、isSpectator=false；落汗标记按现
    GameScreen 逻辑计算：riverMarks 用 TileMarkPresentation.riverMarks(snapshot)；
    markedDoraIndicatorIds 取 area==EXPOSED_INDICATOR 的 tileId；
    markedMeldTileIds 取 area==EXPOSED_MELD；opponentHandRows=
    OpponentHandPresentation.build(snapshot)；viewerHandBackCount=0。
  fromPublicSnapshot(snapshot: PublicSnapshotView): TableBoardRenderModel
    —— viewerSeat=0、isSpectator=true；全部标记集为空；
    opponentHandRows 用新加的 OpponentHandPresentation.rowsFromCounts(
    handTileCounts, phase)（见任务 B）；viewerHandBackCount=handTileCounts[0]；
    clocks=snapshot.clocks。
禁止把 PlayerView/GameSnapshotView/PublicBoardView 实例塞进模型或渲染器
（模型字段只允许 client.api 的原子视图类型 TileView/MeldView/ClockInfo
与基本类型）。phase 之外的私有字段（myClosedTiles/myDrawnTile/mySleeveTiles/
legalActions 等）绝不进入模型。

3. 任务 B：OpponentHandPresentation 增加纯计数行构造
----------------------------------------------------------------
新增 fun rowsFromCounts(handTileCounts: List<Int>, phase: GamePhaseView):
List<OpponentHandRow>：对 seat=(viewer+i)%4（这里固定 viewer=0，即 seat 1..3）
按 STACKING 阶段 0 张、其余 handTileCounts[seat] 张全 HandDisplaySlot(null)
构造，风格与 build() 一致。既有 build/buildSlotsForSeat 不改语义。

4. 任务 C：TableBoardRenderer（common/render/TableBoardRenderer.kt）
----------------------------------------------------------------
object 或无状态 class，五个渲染段，签名统一接收：
  (model, projectionMatrix: Matrix4, batch, shape, font, chineseFont?,
   tileSkin, tileDrawBuffer, options)
options data class TableBoardRenderOptions(
  isTileVisibleInRiver: (seat: Int, tile: TileView, index: Int) -> Boolean = { _, _, _ -> true },
  highlightTileId: Int? = null,          // 牌河提示选中高亮
  clockElapsedMillis: Long = 0L          // 调用方用 lastClockUpdateLocalMillis 算好传入
)
段与统一后的布局（这些是本任务拍板的统一值，玩家屏数值优先）：
  1) renderTableCenter：文案起点 x=540,y=400；isSpectator 时行首加
     "【观战】"前缀（拼进同一字符串）；dora 槽位 (640+i*32, 315) 28x38，
     alpha=在 markedDoraIndicatorIds 中则 0.55 否则 1.0；字体色/缩放与
     GameScreen L1206-1223 逐字一致（含 try/finally 恢复字色与缩放）。
  2) renderSeatsInfo：相对位置 0=(40,80) 1=(1150,400) 2=(320,675) 3=(40,400)；
     标签 "P$seat" + (!isSpectator && seat==viewerSeat 时 " [YOU]"")；
     ClockDisplay.format(clock, clockElapsedMillis)；urgent 红/普通绿、
     RIICHI 行、当前巡玩家泛黄，逐字对照 GameScreen L1252-1287。
     观战屏顶部标签将从 (640,670) 移到 (320,675)——这是有意统一，交付说明
     里注明。
  3) renderHandAreas：对手三行按 GameScreen L1322-1436 的布局与翻面规则
     （top 28x38 y=665 居中、left 34x24 x=245 逆时针 -90、right 34x24 x=990
     顺时针 90，翻面 alpha 0.55，highlight 命中收集后画青色描边框）；
     viewerHandBackCount>0 时按观战屏现行底部布局画牌背行
     （startX=260、y=40、44x62、步长 48 向右）——玩家模式传入 0 自然跳过。
  4) renderDiscards：槽位公式逐字取 GameScreen.getDiscardSlotPosition 的
     数值（等价 viewerSeat=0 时的观战公式）；isTileVisibleInRiver 为假跳过；
     riverMarkedTileKeys 命中 alpha 0.55；highlightTileId 命中收集描边框
     (x-2,y-2,42,56)。
  5) renderMelds：MeldDisplayLayout.layoutAll(model.melds, model.viewerSeat)
     （两参重载，勿用 PlayerView 重载）；MeldDisplayRenderer.append(...,
     markedTileIds = model.markedMeldTileIds)；highlightTileId 命中组内描边。
渲染器内不得 new Camera、不得持有可变状态、不得引用 GameSnapshotView/
PlayerView/PublicSnapshotView/SpectatorSession/GameSession（交付说明注明，
验收方会做源扫描）。每段末尾的 tileDrawBuffer.flush 与 projectionMatrix
赋值顺序对照两屏现状保持。
