2. 任务 A：新建 SerialDispatchChannel（共享池上的串行通道）
----------------------------------------------------------------
新建 server/src/main/kotlin/com/majiang/server/host/HostDispatch.kt，
包含通道与共享池两个类型（类名可微调）：
- class SerialDispatchChannel(
    name: String,
    executor: ExecutorService,      // 共享有界池或专属执行器
    maxQueuedItems: Int,            // 通道独立有界队列条目上限；Int.MAX_VALUE 表示无界（默认模式）
    maxQueuedBytes: Long,           // 通道字节上限（按条目估算大小计入）；同样可禁用
    drainBatchSize: Int             // 每轮限量 drain 条数，之后重新排队
  )
  * enqueue(item)：锁内判 closed/容量，入队；若 drainWip.compareAndSet(false,true)
    成功则向 executor 提交 drain 任务；executor 拒绝（RejectedExecutionException）
    时必须回退 drainWip=false 并递增可观测拒绝计数（下次 enqueue 会重触发，
    队列数据不丢）；随后返回 true/false。
  * drain 任务：单所有者（drainWip 保护），每轮最多 drainBatchSize 条，
    逐条调用构造时注册的消费者回调（回调异常逐条捕获，不中断本轮）；
    本轮结束若队列非空则重新提交自身继续（保持 wip）；重新提交被拒绝则
    回退 wip + 计数，等待下次 enqueue 重触发。
  * 溢出策略：队列满时丢弃"新"条目（不是丢最旧！），置 needsRecovery=true，
    递增溢出计数；消费者收到 isFullSnapshot=true 的基线条目处理后清除
    needsRecovery。KDoc 必须写明：完整快照基线不含历史事件，丢帧后依赖
    客户端 cursor 缺口检测触发全量恢复（既有 MR-01 契约）。
  * close()：标记 closed、清空队列（计数被丢条目）、后续 enqueue 返回 false；
    幂等；绝不阻塞等待在途 drain。
  * 指标暴露：queuedItems、queuedBytes、overflowCount、scheduleRejectCount、
    needsRecovery、closed（供测试与预算测量读取）。
- class HostDispatchPools(
    dispatchThreads: Int, dispatchQueueCapacity: Int,
    completionThreads: Int, completionQueueCapacity: Int,
    closeDeadlineMillis: Long
  )
  * dispatchExecutor：ThreadPoolExecutor 固定线程数 + 有界队列 +
    AbortPolicy（拒绝处理交给通道回退，禁止 CallerRuns），
    线程名 "TcpTableServer-Dispatch-N"。
  * completionExecutor：同构，线程名 "TcpTableServer-Completion-N"，
    仅用于 Future 完成（ServerTableHost 现有内联完成兜底保持不变）。
  * fun close(deadlineMillis)：shutdown + 有界 awaitTermination + shutdownNow，
    期限内必须返回；返回/暴露残留任务数（不可中断回调无法强杀，
    只报告不承诺零残留）。

3. 任务 B：ServerTableHost 接入通道（注入式，默认行为不变）
----------------------------------------------------------------
修改 ServerTableHost.kt：
- 构造新增可选参数（全部默认 null/0 表示"默认模式"）：
  sharedDispatch: ExecutorService? = null,
  sharedCompletion: ExecutorService? = null,
  seatChannelCapacityItems: Int = 0,   // 0 = 默认模式（无界）
  seatChannelCapacityBytes: Long = 0,
  publicChannelCapacityItems: Int = 0,
  publicChannelCapacityBytes: Long = 0,
  channelDrainBatchSize: Int = 16
- 默认模式（未注入 sharedDispatch）：行为与现状逐点等价——每席位与公开流
  各自持有专属单线程执行器（现状 5 个）、通道无界、无拒绝、无溢出；
  既有测试是裁判，零回归。
- 共享模式（注入）：席位/公开通道 = 共享池上的 SerialDispatchChannel，
  使用给定容量与 drainBatchSize。
- publishStateChanges / publishPublicChanges 改为"每更新一个通道条目"：
  条目在 drain 时扇出给全部 active 订阅者（替代现状的每订阅者一个任务）。
  席位流每订阅者的 deepCopy 移到 drain 线程执行（降低权威线程负担，
  保持每订阅者独立拷贝语义）；公开流共享同一只读 update 对象（现状语义）。
  每订阅者回调独立 try-catch。per-seat FIFO 顺序不得改变。
- subscribeSeat / subscribePublic 的初始基线仍经同一通道派发
  （isFullSnapshot=true，处理 needsRecovery 清除）。
- enqueueOperation 的 completionExecutor：注入 sharedCompletion 时用它，
  拒绝时的内联完成兜底逻辑逐字保留；未注入保持现状每桌 Cached 池。
- close()：通道一律 close（清队列、后续入队 false）；仅 shutdown 自己
  拥有的执行器（默认模式的 5 个派发执行器与 completion 池）；
  注入的共享池绝不 shutdown。pendingFutures 确定性异常完成语义不变。
- KDoc 更新：说明两模式、线程预算归属（共享部分与房间数无关）。

9. 陷阱清单（前几轮 MR 的教训，逐条自查）
----------------------------------------------------------------
1) 权威队列纪律：publishStateChanges 在 serialExecutor 上执行，通道
   enqueue 必须非阻塞、锁内只做判定与入队；严禁在权威线程等待 Future/
   锁/线程池；严禁在 drain 任务里等待自身通道或宿主关闭。
2) 所有权：注入的共享池一律不 shutdown；房间 close 只关自己的通道与
   订阅；只有池的拥有者（TcpTableServer / 默认模式的宿主）才 shutdown。
3) drainWip 回退是防死锁关键：executor.execute 抛 RejectedExecutionException
   的 catch 里必须把 wip 复位，否则通道永久卡死。注意 execute 抛出的
   异常类型在 Kotlin 中的捕获写法（RejectedExecutionException 是 RuntimeException）。
4) RoomSubscriber 拒绝分支修复后，注意 isRunning/wip 语义与既有
   "终态最终态、后续事件直接丢弃"语义的兼容，不要引入第三套状态机。
5) 席位流 deepCopy 移到 drain 线程后，每订阅者仍必须拿到独立拷贝，
   不得共享可变对象给外部监听器。
6) 饱和策略禁止 CallerRuns；任何丢弃路径必须有计数（溢出/调度拒绝/
   close 丢弃），禁止无观测静默丢弃。
7) 默认模式与现状线程语义逐点等价是硬约束：专属单线程、无界、无拒绝。
   既有 ServerTableHostTest / SharedRoomTest / 各 TCP 集成测试零回归。
8) 测试禁止用真实 sleep 驱动逻辑等待；用 CountDownLatch/注入执行器/
   轮询截止。可注入时钟沿用 ManualClock 既有写法。
9) 所有拟定默认值 KDoc 标注"拟定默认值，可通过服务端配置调整"。
10) 线程命名严格遵守给定前缀（预算测试按线程名统计）：
    TcpTableServer-Dispatch-N / TcpTableServer-Completion-N。
11) 你无法自证编译。交付前用读文件工具逐字回读你改过的每个文件，
    对照本简报逐条自查（import、构造参数名、作用域、括号配对），
