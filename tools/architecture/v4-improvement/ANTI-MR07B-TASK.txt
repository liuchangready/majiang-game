1. 现状与问题（已核实的代码事实，基线 fe5e359）
----------------------------------------------------------------
- server/tcp/TcpTableServer.kt bindSpectatorToRoom（约 1730-1760 行）：
  每个观战连接的订阅回调查询到达时各自执行
  `TcpMessageCodec.toPublicUpdateFrame(pubUpdate).toByteArray()` 再
  `conn.sendNormalFrame(...)`——同一房间的同一条公开更新被重复 JSON 编码 N 次
  （N=观战者数；T0 实测 PUBLIC_UPDATE 最大约 3.9KB，32 观战者=32 次编码）。
- TcpOutboundQueue.enqueueNormal（server/tcp/TcpOutboundQueue.kt）每次调用
  `ByteBuffer.wrap(frameBytes)`——各连接的 ByteBuffer position/limit 本就独立，
  共享同一不可变 ByteArray 是安全的（writeToChannel 只读写各自 buffer 的
  position/limit，不改字节数组内容）。
- 公开流内容按 V4 契约 4 不含任何私密数据（玩家私有流/暗牌/牌山/私人账本/
  未授权里宝牌均被 PublicProtocolMapper 过滤）——只有公开流允许进入共享编码，
  席位（私有）流更新绝不经过共享缓存。
- 房间关闭路径：TcpTableServer.onRoomRecycled（回收）、close()（停服）、
  registry 清扫——缓存需要在这些时机按会话释放。

2. 任务 A：新建 PublicUpdateFrameCache
----------------------------------------------------------------
新建 server/src/main/kotlin/com/majiang/server/tcp/PublicUpdateFrameCache.kt：
- class PublicUpdateFrameCache(
    maxEntries: Int,        // 拟定默认 64
    maxMaxBytes: Long       // 拟定默认 1 MiB
  )
- 缓存键 data class 含全部五元组：sessionId、syncEpoch、cursor、fromCursor、
  isFullSnapshot（来源：ProtocolPublicUpdate.snapshot.sessionId/syncEpoch/cursor
  与 update.fromCursor、update.isFullSnapshot——先读 protocol 的
  ProtocolModels.kt 核对真实字段名，禁止臆造字段）。
- fun frameBytesFor(update: ProtocolPublicUpdate): ByteArray：
  * 锁内查键：命中返回同一不可变 ByteArray（编码次数 0）；
  * 未命中：锁内编码一次（TcpMessageCodec.toPublicUpdateFrame(update)
    .toByteArray()，经 server.tcp 的 toByteArray 扩展），encodeCount++，
    计入字节容量，FIFO 淘汰最旧条目直至满足条目/字节双上限，返回。
  * 编码必须在锁内完成恰好一次（多房间并发查询同一更新也不得重复编码——
    注意：不同房间的更新天然不同键，并发主要来自同房间多次查询与淘汰竞争）。
- fun releaseSession(sessionId: String)：移除该会话全部条目（房间关闭时释放）。
- 指标：encodeCount、entryCount、cachedBytes、hitCount、missCount。
- KDoc：只缓存公开流帧；完整快照基线不含历史事件；字节数组编码后不可变，
  各连接以独立 ByteBuffer 视图引用；不保留 seq/ACK/重传索引（TCP 无重传语义）。

3. 任务 B：TcpTableServer 接线
----------------------------------------------------------------
- TcpServerConfig 新增：publicFrameCacheMaxEntries = 64、
  publicFrameCacheMaxBytes = 1 MiB（拟定默认值，init 校验 > 0）。
- TcpTableServer.start() 创建 publicFrameCache（服务器拥有）；
  暴露 internal fun getPublicUpdateFrameCache() 供测试读取指标。
- bindSpectatorToRoom 的公开更新订阅回调改为：
  val frameBytes = publicFrameCache.frameBytesFor(pubUpdate)
  conn.sendNormalFrame(frameBytes)
  （sendNormalFrame 内部按连接独立 wrap ByteBuffer，语义不变。）
- 释放时机（三处都要接）：
  1) onRoomRecycled(room) 追加 publicFrameCache.releaseSession(该房 sessionId)；
  2) TcpTableServer.close() 停服清理（直接清空或逐会话释放）；
  3) handleLeaveRoom 观战离房不需要释放（会话仍在），但房间从注册表注销的
     其它路径（如 close/registry.removeRoom 后房间 closed）若存在则同样释放——
     以"房间 closed 即释放"为原则排查所有路径并在交付说明列表。
  sessionId 获取方式：房间存活时经一次公开快照查询或 SharedRoom/tableHost
  暴露只读 sessionId（优先复用已有公开访问器，避免新增可变状态；若需在
  ServerTableHost 增加 internal val publicSessionId 只读透传，允许，
  但必须权威侧既有值，不得新建生成逻辑）。
