# 疯狂动物麻将 · 千术麻将 UI 原型

> **可点击界面原型（纯前端）** —— 用于评审「疯狂动物麻将」的方向：动物角色 + 日式麻将 + 千术心理战。
> 本目录是**独立的界面原型**：不包含游戏规则实现，也**不连接任何后端服务**。

原项目「千术麻将」是 libGDX 1.14.2 的 2D 横屏麻将工程（虚拟坐标 1280×720），核心玩法是
日式麻将牌局 + 三大出千绝技（落汗 / 袖里藏花 / 偷梁换柱）+ 独立出千点经济。
本原型把这条主线做成了**可以在浏览器里点着看**的界面稿，并按
[十二张视觉概念图](concepts/README.md) 的美术方向（深翡翠 / 朱红漆木 / 暖金描边 / 灯笼光 / 动物肖像）
重做了整套视觉。

## 1. 运行方式

### 方式 A：直接打开（最快）

双击 `ui_demo/index.html`，或把它拖进浏览器窗口即可。

* 无需构建、无需安装依赖、无需本地服务器，`file://` 直接可用。
* 建议使用 Chrome / Edge / Firefox 最新版。

### 方式 B：本地静态服务器（可选，便于移动端调试）

```bash
# 在仓库根目录执行任意一种
python -m http.server 8000
npx serve .
```

然后访问 <http://localhost:8000/ui_demo/index.html>。
移动端请用**横屏**浏览（设计基准 1280×720）。

### 依赖与约束

| 项目 | 状态 |
| --- | --- |
| 外部字体 / CDN / 网络请求 | **无**（不引用任何 CDN、字体服务、fetch/XHR/WebSocket） |
| 构建步骤 / 打包工具 | **无**（纯 HTML + CSS + 原生 JS，直接 `file://` 打开即可运行） |
| 第三方依赖 | **无** |
| 图片 | 仅使用本目录 `assets/` 下的 **3 张本地 PNG**（场景图 + 动物肖像精灵图），无外部图片 |
| 文本 / 牌面 / 状态 / 按钮 | **全部由 HTML + CSS + JS 绘制**，图片只作装饰层与角色肖像 |

### 浏览器支持

需要支持 CSS Grid、`aspect-ratio`、`:focus-visible`、CSS 变量、`inert` 的现代浏览器
（Chrome / Edge 102+、Firefox 112+、Safari 15.5+）。窄屏下会自动改为纵向堆叠布局并可滚动浏览。

## 3. 页面 / 交互目录

### 3.1 屏幕总览（9 个）

| # | 屏幕 | 入口 | 主要交互 |
| --- | --- | --- | --- |
| 1 | **主菜单** `menu` | 启动默认页 | **左右分层构图**（见 [主菜单分层方案](design/MAIN_MENU_LAYER_PLAN.md)）：左侧金色书法标题 + 一行玩法说明 + 3 张大入口卡（单机开局 / 联机大厅 / 动物图鉴）+ 3 枚次入口（选择模式 / 千术秘籍 / 设置），共 6 个入口均可点；右侧为当前角色主视觉（大金环 + 章鱼大幅立绘 / 其他动物肖像 + 角色信息牌）。上次进度「继续牌桌」 |
| 2 | **模式选择** `mode` | 主菜单「选择模式」 | 单机 / 联机两张漆木卡片，进入不同分支 |
| 3 | **动物角色选择** `characters` | 主菜单、结算页、单机流程 | 8 张肖像卡、锁定开关、绝技与特性详情、确认使用 |
| 4 | **联机大厅** `lobby` | 主菜单、模式选择 | 列房 / 刷新 / 建房 / 按房间号加入 / 观战（全部为演示模拟数据） |
| 5 | **房间准备** `room` | 大厅、单机流程 | 4 席位准备状态、房主开赛（未全部准备时禁用并说明原因）、码牌六选一 |
| 6 | **牌桌** `table` | 房间准备 | 见 3.3 |
| 7 | **秘籍 / 图鉴** `codex` | 主菜单 | 三个标签页：千术绝技秘籍 / 动物角色图鉴 / 原型边界说明 |
| 8 | **设置** `settings` | 主菜单、顶栏齿轮 | 牌面皮肤、动效强度、界面字号、章鱼演示开关、重置演示数据 |
| 9 | **局末结算** `settlement` | 牌桌「结算本局」 | 名次卡、役种（演示）、出千账本、角色特性结算摘要、再来一局 |

### 3.2 导航规则

* 顶部面包屑实时显示当前屏幕。
* 每个页面左上角都有 **← 返回** 按钮；`Esc` 等同于返回上一级（主菜单下 `Esc` 不退出，避免误关）。
* 弹层打开时 `Esc` **只关闭最上层弹层**，不会连带返回页面。
* 返回栈最多保留 12 级。
* **状态保持**：角色选择、锁定状态、皮肤 / 动效 / 字号设置、房间与牌局进度写入浏览器
  `localStorage`（键名 `mj-animal-demo/session-v2`），刷新页面后主菜单会出现「继续牌桌」。
* **重进**：
  * 结算页「再来一局（重进牌桌）」→ 保留角色与设置，重开新一局；
  * 牌桌「重开本局」→ 同桌重开；
  * 设置页「重置演示数据」→ 清空本地存档并回到初始状态。

### 3.3 牌桌交互（核心）

牌桌布局参考概念图 03：上 / 左 / 右三席肖像铭牌分布在牌桌边缘，**中央是方位罗盘锚点**（局次 / 圈风 /
牌山剩余 / 宝牌）与左右两侧的牌山立柱，中间是牌河，底边是本人手牌（摸牌单独隔开），
右侧自上而下为出千点、落汗、袖里藏花、偷梁换柱、理牌、托管。桌布由**朱红漆木外框 + 暖金回纹
导轨 + 四角描金**围合，桌面纹样与中央锚点均为 CSS 绘制，**不遮挡牌河与任何点击区**
（自动化检查确认锚点与牌河不重叠、桌布内容覆盖率 79.5%）。

| 元素 | 行为 |
| --- | --- |
| **手牌** | 可点击；点击选中（再次点击取消），选中牌抬起并高亮；`Enter` 可直接打出。出牌后恒为 **13 张**，摸牌后为 **14 张** |
| **出牌** | 打出选中牌 → 牌飞入牌河，日志记录；随即模拟三名对手依次出牌，然后轮到你 |
| **理牌** | 按 万 / 筒 / 条 / 字 排序手牌 |
| **托管** | 切换自动出牌（牌桌顶部显示「托管中」标签） |
| **落汗** `TileMark` | 打开选牌弹窗，从手牌选 **4 张** → 确认 → 手牌出现金色「汗」标记，追踪栏列出已标记牌 |
| **袖里藏花** `SleeveBloom` | 摸牌后可施术，候选牌（默认 2 张）二选一 / 三选一 → 保留 1 张 |
| **偷梁换柱** `BeamSwap` | 两步：先选手牌，再选牌山暗槽 → 一换一交换（箭头只表示双方各一张等额互换） |
| **补充演示点数（+50）** | 仅用于原型演示，随时补充出千点 |
| **结算本局** | 进入局末结算页 |

* 三个绝技弹窗里的候选牌 / 暗槽都**只是预览**：打开弹窗不会把实体移出牌山，
  点「确认」才发生归属转移。因此 **取消 / `Esc` / 关闭按钮 / 遮罩点击 / 导航**
  都不会丢牌，重复开关同一个弹窗也不会。
* 所有绝技按钮在不可用时**置灰并显示具体原因**（例如「出千点不足（需要 10 点，现有 4 点）」、
  「需在自己的回合施术」、「等待摸牌后才能施术」、「标记已达上限（12 张）」），不是只靠颜色区分。
* 顶栏常驻显示当前**出千点余额**，变化时有数值跳动动画。
* **费用条读数规则**：没有折扣时只显示一个金额（`本次费用 10 点`），
  只有费用真的变化时才显示 `原价 10 点 → 实付 7 点`（企鹅返还以附注给出）。

> **关于 136 张守恒**：原型把每张牌当作**唯一的物理实体**（带内部编号）来跟踪，所以同名牌不会互相串味，
> 落汗标记也只会跟着那一张具体的牌。
>
> * **候选只做预览**：袖里藏花的候选牌、偷梁换柱的暗槽都只是对牌山的**预览**，
>   打开弹窗时**不会把任何实体移出牌山**；只有点击「确认」时才发生归属转移，
>   且每张实体在任一时刻只归属一处。因此取消 / `Esc` / 关闭按钮 / 遮罩点击 / 导航
>   等任意退出路径都不会丢牌，重复开关也不会。
> * **手牌张数恒定**：出牌后手牌恒为 **13 张**（打出普通手牌时，刚摸的那张会自动并入手牌），
>   下一巡摸牌后为 **14 张**（13 + 摸牌 1）。
>
> 因此「手牌 + 摸牌 + 牌山 + 牌河 + 对手手牌」在任何时刻都恒等于 **136**。

### 3.4 动物角色（8 位）

角色是**可选皮肤 + 对三大绝技的加强或费用调整**，**没有任何独立的新技能**，也不会获得额外的回合操作。

| 角色 | 特性 | 影响 |
| --- | --- | --- |
| **章鱼** Octopus | 三腕藏花 | 袖里藏花 **20% 概率**看到三张候选，但**只保留一张**，手牌数量不变 |
| **喜鹊** Magpie | 第一滴汗 | 每局**首次落汗** -4 点（10 → 6） |
| **狐狸** Fox | 偷看一眼 | 偷梁换柱**额外预览一个合法候选**槽位（3 → 4） |
| **猴子** Monkey | 换手 | 同一局**第二种不同绝技** -3 点（每局仅一次；重复使用或第三种绝技不再减免） |
| **企鹅** Penguin | 留一手 | 袖里藏花**保留原摸牌**返还 3 点 |
| **熊猫** Panda | 一好一坏 | 当局**第一招半价**，**第二招 +3 点** |
| **老虎** Tiger | 额外一组 | 落汗标记上限 12 → 16 张 |
| **乌鸦** Crow | 折价 | 偷梁换柱 -2 点 |

角色卡上使用**本地 PNG 肖像**（`assets/animal-roster.png` / `animal-extra.png`），
卡面另有独立的**锁定**开关：锁定后卡片变灰、无法选用、确认按钮禁用并给出文字原因，解锁后恢复。

### 3.5 角色特性触发演示

* 触发时：牌桌左栏「角色特性」卡片脉冲 + 顶部横幅 + 右下角提示 + 日志一条「角色特性触发 · …」。
* **章鱼 20% 概率**有三种查看方式，正常概率文案始终显示「20% 概率」：
  1. 设置页「章鱼三候选强制演示」开关（全局）；
  2. 袖里藏花弹窗内的「演示：强制触发三候选 / 演示：回到二选一」按钮（单次双向切换）；
  3. 不做任何操作时，按 20% 概率自然触发。
* 触发后候选为 **3 张但仍只能保留 1 张**，界面明确标注「20% 触发」「手牌数量不变」「物理守恒」。
* 弹窗内的演示按钮是**双向开关**：三候选时文案变为「演示：回到二选一」，再点一次即回到二候选
  （无论三候选来自概率还是强制触发，回落逻辑一致）；界面显示的候选与待确认状态
  （`pendingBloom.candidates`）始终是**同一份数据**，不会出现「界面 3 张、待确认仍是 2 张」的不同步。

## 4. 演示数据与真实游戏的边界

**这一节是本原型最重要的部分，请勿把原型内容当作已实现功能对外描述。**

### 4.1 本原型**是**

* 一个**纯前端 UI 原型**：HTML + CSS + 原生 JS，没有构建步骤、没有依赖、没有网络请求。
* 一套**可点击、可演示**的交互稿，用来评审视觉方向、信息层级与操作手感。
* 一个**演示模拟器**：牌墙、对手出牌、结算分数、房间列表都由本地脚本即时生成。

### 4.2 本原型**不是**

| 项 | 说明 |
| --- | --- |
| 后端连接 | **完全没有**。不建立 TCP / UDP / WebSocket，不调用任何 `client` / `server` 代码 |
| 用户账户 | 未实现（原型中不存在登录、注册、账号体系） |
| 自动撮合匹配 | 未实现（大厅里的房间是本地脚本生成的演示数据） |
| TLS / 加密信道 | 未实现（原型里没有任何信道） |
| 真实房间与观战 | 未实现（联机大厅是界面示意流程） |
| 动物角色系统 | **尚未在真实游戏中落地**。角色表是原型提出的设计方案 |
| 真实规则判定 | 未实现。原型不做和牌判定、不做役种计算、不做番数结算 |
| 真实权威流程 | 未实现。没有「准备 → 码牌 → 开局 → 对局 → 结算」的服务端状态机 |

### 4.3 原型沿用了真实工程的哪些设定

这些是**为了让原型看起来合理**而沿用的数值，不代表生产实现：

* 三大绝技的基础费用各 **10 出千点**；原型初始出千点 **100**。
* 落汗每次选 **4 张**实体牌、单局最多维持 **12 张**标记。
* 单副牌 **136 张**、万 / 筒 / 条 / 字 四种牌面。
* 准备阶段「统一码牌」**六选一**、消耗 **30 点**；看破 10 点。
* 菜单结构（单机 / 联机 / 皮肤 / 秘籍 / 设置）、大厅（建房 / 加房 / 列房 / 观战）、
  房间准备（准备 / 开赛 / 码牌）→ 牌桌 → 结算 的主线流程。
* 「物理守恒」在原型里是**硬约束**：落汗只加标记、袖里藏花只换牌面、偷梁换柱严格一换一，
  任何操作都不增加也不减少牌的总数，手牌数量始终不变。

### 4.4 原型里被简化或改写的地方

* 真实游戏的**看破**与**统一码牌**在原型里只有说明与房间阶段的一次性选择，不做真实生效计算。
* 角色特性在原型里按「费用调整 / 候选数量 / 标记上限」三类实现，属于原型提案。
* 结算分数、役种名称、对手出牌均为随机或写死的演示数据。
* 计时器只做了静态展示，未实现「20 秒储备 + 3 秒思考缓冲」的权威倒计时。

### 4.5 真实工程的位置

真实实现仍然在原仓库中，本原型**不替代**它：

* 引擎 / 规则 / 物理守恒：`engine/`
* 协议契约：`protocol/`
* 权威房间与传输：`server/`
* 客户端门面：`client/`
* libGDX 展示层：`presentation/`
* 架构说明：`AGENTS.md`、`doc/FRAMEWORK_ARCHITECTURE.md`、`doc/RIICHI_RULES_DESIGN.md`

## 5. 视觉与动效

### 5.1 视觉

* **风格**：深翡翠牌桌 + 朱红漆木 + 暖金描边 + 灯笼光 + 动物剪纸肖像，对齐
  [概念图 12 张](concepts/README.md) 与 [交互设计 §2](design/INTERACTION_DESIGN.md)。
  实测色值：翡翠 `#153c2b`、朱红 `#83301d`、暖金 `#e5bf86`、象牙 `#fff3d8`。
* **场景层**：`assets/club-background.png` 作为固定底图，叠加翡翠/朱红渐变罩、两盏 CSS 灯笼光晕与细颗粒纹理；
  页面内容一律绘制在实色底板之上，**装饰不会盖住操作区**（装饰层均为 `pointer-events: none`）。
* **层次**：漆木面板 + 暖金顶边导轨 + **回纹金带（四边）+ 四角描金** + 云纹分隔线 + 内发光，
  避免平面渐变与简陋卡片；主菜单另有描金圆环、暖光晕、印章与漆木角色牌构成的**三层景深**。
* **主菜单构图**（改造后，依据 [主菜单分层方案](design/MAIN_MENU_LAYER_PLAN.md)）：
  左为金色书法标题 + 一行玩法说明，其下是 3 张大入口卡（单机开局 / 联机大厅 / 动物图鉴）与
  一行 3 枚次入口（选择模式 / 千术秘籍 / 设置）；右半屏为当前角色主视觉——
  描金圆环 + 暖光晕 + 章鱼大幅透明立绘（或所选动物的肖像）+ 底部角色信息牌
  （当前角色 / 特性 / 关联绝技）。章鱼立绘约 474×453 px，**与左侧入口互不重叠**；
  改选非章鱼角色时主视觉换成对应肖像，**不会出现「画面是章鱼、文字写别的角色」**。
* **牌桌构图**：朱红漆木外框 + 暖金回纹四边 + 四角描金围合翡翠桌布；
  桌布内有对家铭牌、牌山横条、左右牌山立柱、牌河与**中央方位罗盘**（局次 / 圈风 / 牌山剩余 / 宝牌）。
* **麻将牌全部由 CSS 绘制**：万（汉字数 + 万）、筒（圆形点数按传统布局排布）、条（竹节，5 条中心为红）、
  字（东南西北中发白，中为红、发为绿、白为蓝框）、1 条为手绘小鸟；牌背为翡翠底 + 金色斜纹。
* **动物肖像来自本地 PNG**：大尺寸（选角卡 / 详情 / 席位 / 结算名次）用整格立绘，
  小尺寸头像用逐角色验证过边界与取景的**头部特写**裁切（`--pz / --px / --py`）。
* **3 套牌面皮肤**：经典象牙（默认）、夜市霓虹、兽纹墨玉，在设置页切换。
* 布局以 **1280×720 横屏**为基准；主菜单为左（标题 + 入口）/ 右（角色主视觉）双栏，
  ≤1180px 收紧右栏，≤900px 改为「标题 → 角色 → 主入口 → 次入口」纵向流，
  ≤720px 再降一档；牌桌在 ≤1040px 改为纵向堆叠（牌桌与手牌在前、绝技与操作紧随其后），
  窄屏仍可完整浏览。

### 5.2 动效

页面转场（朱红扫光）、角色选择反馈、摸牌 / 出牌、落汗水滴标记、袖里藏花候选展开、
偷梁换柱一换一、角色特性触发（横幅 + 卡片脉冲）、结算名次依次入场 + 少量金纸片、提示条进出。

* **主菜单入场动效**（每次进入菜单，含从其他页面返回时重放）：

  | 元素 | 起始 | 时长 | 延迟 |
  | --- | --- | ---: | ---: |
  | 标题区 | 透明、上移 10px | 360ms | 0ms |
  | 右侧角色主视觉 | 透明、右移 32px、缩小 3% | 600ms | 100ms |
  | 主入口卡 1 / 2 / 3 | 透明、**右移 84px** | 520ms | 180 / 270 / 360ms |
  | 次入口 1 / 2 / 3 | 透明、**右移 48px** | 380ms | 450 / 510 / 570ms |

  * 曲线 `cubic-bezier(.16,1,.3,1)`，**只动画 `transform` / `opacity`**，不改布局。
  * 入场动画加在**入口容器**（`.menu-entry`）上，按钮的 hover 位移加在**按钮自身**，
    二者作用于不同元素，互不覆盖；动画进行中入口依然可命中、可点击。
  * 主视觉入场结束后只保留极慢、低幅度的轻呼吸；`prefers-reduced-motion: reduce`
    与设置页「关闭动画」时**立即显示终态**（动画被取消，不残留延迟等待）。

* **动效强度**：设置页提供「跟随系统 / 完整动效 / 减弱动效」三档。
  * 「跟随系统」（默认）实时响应系统 `prefers-reduced-motion: reduce`，系统偏好变化时立即生效。
  * 「减弱动效」与系统偏好一致：所有动画与过渡被压缩为瞬时，**界面状态与信息完全保留**。
  * 显式选择「完整动效」时以用户选择为准。
* 所有装饰性动画层（转场遮罩、特性横幅、提示条、结算纸片）均为 `pointer-events: none`，
  **不会遮挡或吞掉点击**；模态弹窗有焦点陷阱，`Esc` 关闭。

## 6. 无障碍

* 全部可交互元素使用原生 `<button>`（含 `type="button"`），焦点可见（`:focus-visible` 金色描边）。
* 屏幕切换后焦点自动落到该屏标题；弹窗打开时焦点进入弹窗并在内部循环，`Esc` 关闭并归还焦点。
* 禁用态同时提供**文字原因**，不依赖颜色单独传达信息。
* 选择态除颜色外还有 `✓`、位移、描边等非颜色线索。
* 状态变化通过 `aria-live` 区域播报（出千点、施术结果、角色特性、回合切换）。
* 页面结构使用 `header` / `main` / `footer` / `section` / `nav`，标题层级连续，并提供「跳到主要内容」跳转链接。
* 装饰层（场景图、灯笼、肖像、纸片）均 `aria-hidden`，角色名与能力由 DOM 文本提供。

### 7.1 视觉复核方法

本模型无法直接观看位图，因此视觉检查用**可复现的客观测量**完成（脚本同样在临时目录）：

1. **像素探针**：对每张截图按区域统计纹理能量（相邻像素亮度梯度）、色彩数量与暖色占比，
   用于确认「不是平面渐变 / 简陋卡片」（全图纹理能量 0.004–0.028，颜色数 62–880）。
2. **色系分布对比**：把 12 张概念图与 24 张实机截图按「墨 / 翡翠 / 朱红 / 暖金 / 象牙」分类统计，
   逐屏比对；据此修正了转场遮罩过暗、暖金与朱红占比偏低、牌桌缺少朱红漆木外框等问题。
3. **精灵图裁切校验**：对 8 个角色逐个解算 CSS `background-position`，把裁切结果反解回源图像素
   并打印轮廓，确认「头部在框内、且不越出图格、不串到相邻角色」。
4. **布局审计**：逐屏读取关键元素的外接矩形，检查越界、被裁切与过小点击目标。
5. **构图度量**（针对「角色成为主视觉 / 桌布不留大片空白 / 暖金层次」三项）：
   * 主菜单角色主视觉改为右侧大幅章鱼立绘（约 474×453 px，占主菜单右半屏约 19% 画布面积），
     改版前仅为 300×300 描金画框；
   * 牌桌桌布**内容覆盖率 79.5%**、空白 20.5%（改版前中央约半屏为空），
     且中央罗盘锚点与牌河**不重叠**；
   * 暖金像素占比（暖金定义：色相 20–62°、亮度 > 0.30，概念图与实机同一条规则）：
     概念图 21.5% / 24.1% / 28.5%，实机主菜单 7.5%、选角 11.5%、牌桌 8.8%。
     UI 形态无法达到绘画的暖金密度（概念图的暖金是大幅笔触与整体打光），
     这里的差距是**形态差异**，不是描金缺失：已落地的描金包括标题金渐变 + 金晕、
     四边回纹金带、四角描金、角色画框金边、卡面金边导轨、罗盘金环、金印与灯笼暖光。

> 上述测量**不能替代人工看图**：像素分布只说明「有纹理、有层次、色系方向一致」，
> 具体的构图观感仍建议人工打开 `ui_demo/index.html` 与 `ui_demo/concepts/index.html` 对照浏览。
