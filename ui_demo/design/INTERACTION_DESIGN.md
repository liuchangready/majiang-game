# 疯狂动物麻将 · UI 原型视觉与交互规范

本文件是 `ui_demo` 可点击原型的实现依据。十二张 [页面概念图](../concepts/README.md) 定义气氛、构图与信息层级；图像生成的文字、费用、手牌张数和算分可能出错，**本文件及真实演示状态优先**。原型是独立 HTML/CSS/JS 演示，不连接游戏权威或网络服务。

主菜单当前专项改造的图层、素材与从右移入动效见 [主菜单分层方案](MAIN_MENU_LAYER_PLAN.md)。

## 1. 范围与核心原则

- 原型基准为 1280×720 横屏，允许 960×540 和窄屏滚动浏览；保留牌桌、手牌、牌河、四席及权威倒计时的位置辨识度。
- 动物角色只加强落汗、袖里藏花、偷梁换柱，或改变这三招的费用。任何动物按钮都不是第四种独立绝技。
- 主交互由 HTML 元素承载；概念截图不能直接铺成背景再叠透明热区。所有中文标题、费用、禁用原因、牌面和数字必须是可读的真实 DOM 文本或原型数据。
- `assets/club-background.png` 可作非牌桌页的场景层。`assets/animal-roster.png` 是透明 3×2 六肖像图（章鱼、喜鹊、狐狸 / 猴子、企鹅、熊猫）；`assets/animal-extra.png` 是透明 2×1 图（老虎、乌鸦）。可用 CSS 定位裁切，保留人物完整脸部。
- 局域网/自建 TCP 房间在真实游戏已有，但此浏览器演示全部使用模拟数据。界面只能标为“演示房间”，不得暗示公网账户、自动匹配、实时联机、TLS 或游戏后端已接通。

## 2. 视觉系统

| 层级 | 建议 | 用途 |
| --- | --- | --- |
| 场景底层 | 深夜麻将馆与月色，`club-background.png` | 主菜单、模式、大厅、准备、图鉴、设置、结算 |
| 交互底板 | 深翡翠 `#082b29` 至 `#123c35`，约 92% 不透明 | 文字、表单、房间行、弹层 |
| 主动作 | 朱红 `#a72a24` 至 `#d4492c`，暖金描边 | 确认、开局、加入、施术 |
| 次动作 | 墨绿与浅金边框 | 返回、取消、观战、切换 |
| 信息强调 | 暖金 `#f5cb78`、象牙白 `#fff3d8` | 标题、选中、费用、点数 |
| 禁用与错误 | 深灰底 + 明确文字原因；错误用朱红文字与图标 | 不可用的千术/开赛条件 |

装饰边框、云纹、灯笼和角色肖像用于建立气氛，内容区应保留足够实色底。普通正文优先 16px 以上；可点击区域至少 44px 高。牌桌把视觉焦点留给 13/14 张手牌、牌河、回合和三绝技，不让大肖像或动效覆盖行动区。标题字体可有书法感，但正文、数字、牌名使用系统中文字体保证辨认。

| 08 [秘籍/图鉴](../concepts/08-codex.png) | `codex` | 标签为“三大绝技”“动物角色”“规则说明”；技能卡只讲现有三招，角色卡只讲加成和费用。 |

## 4. 牌桌与三种千术弹层

牌桌布局参考图 03。上/左/右席头像与点棒在边缘；中心为牌山、牌河、局次和剩余牌数；底边是本人手牌，摸牌单独隔开；右侧自上而下为出千点、落汗、袖里藏花、偷梁换柱、理牌、托管。行动区保留清楚的点击和键盘焦点形态。技能入口同时显示名称、当前费用、可用/禁用状态及禁用原因。只允许一个选择弹层占用交互焦点。

### 4.1 落汗 · [图 11](../concepts/11-tile-mark.png)

1. 点击可用入口 → 打开选择弹层，背景牌桌变暗并暂时停止本地牌桌输入。
2. 从允许的手牌实体中选足演示要求的张数，选中态为抬升 + 金色水滴标记 + 计数；再次点同张撤销。
3. “确认落汗”只在选牌数正确且点数足够时可用。显示当前费用与扣后余额；角色减价在这里以“原价 / 特性减免 / 实付”三行显示，避免只替换数字。
4. 确认后一次性扣点、标记显现、关闭弹层并显示回执；取消不扣点。断线/过期/超时演示态必须关闭或禁用提交并解释原因。

### 4.2 袖里藏花 · [图 04](../concepts/04-octopus-sleeve-bloom.png)

1. 打开后显示通常的两张候选。章鱼特性成功的演示态才显示三张，并写“20% 触发 · 三选一”。
2. 只允许选一张；选中有独立描边、抬升和“最终保留”标签。第三张候选并不增加手牌总数；未选牌返回合法位置。
3. 显示本次费用和剩余选择时间；确认后只保留所选的一张，点数按一次施术结算。取消/超时按原有规则演示，不能把取消做成本地清除却不处理权威语义。
4. 概率演示开关可以令章鱼必定触发，须标“仅供演示”；正常说明仍为 20%。同一个施术请求不能因点击/刷新重复抽概率。

### 4.3 偷梁换柱 · [图 12](../concepts/12-beam-swap.png)

1. 左侧选一张允许交换的手牌；右侧选一个合法候选槽位。候选槽位背面朝上，除角色明确提供预览外不泄露牌面。
2. 两侧都选定且点数足够时确认才可用。箭头只表示双方各一张等额互换；提交后手牌数和全桌实体牌数不变。
3. 狐狸的加成仅多一个合法候选，并保留“一进一出”；费用变化型角色只改变结算和费用预览。
4. 取消无副作用；收到过期/不合法反馈时保留可读的原因并让用户重新选择。

三种入口的忙碌、连接、余额、回合窗口和互斥条件，应由同一可用状态同时驱动按钮视觉和点击行为。禁用按钮仍能给出原因提示，不允许点击穿透到理牌或托管。

## 5. 动物选择与费用展示

首屏重点六角：章鱼（袖里藏花 20% 三选一）、喜鹊（本局首次落汗 -4）、狐狸（偷梁换柱多一个合法候选）、猴子（本局使用第二种不同绝技 -3）、企鹅（袖里藏花保留原摸牌返还 3）、熊猫（本局第一招半价，之后费用变化按原型明示）。原原型已有老虎、乌鸦，保留它们的角色卡与现有演示行为，但画面与肖像统一。每张角色卡显示名字、关联绝技图标、1 行特性、当前选中/已确认状态；完整说明在右侧或详情抽屉。任何折扣、返还都应在技能弹层和结算账本中追溯。

## 6. 动效与反馈

| 事件 | 建议时长 | 表现 | 降低动态效果时 |
| --- | --- | --- | --- |
| 页面切换 | 220–300ms | 淡入 + 轻微上移，不移动主要点击位置 | 立即切换 |
| 角色悬停/选中 | 150–220ms | 描边亮起、肖像轻微前移、能力卡淡入 | 只换描边/文字 |
| 手牌选择 | 120–180ms | 抬升 8–12px + 金色边框 | 只换描边 |
| 落汗确认 | 300–450ms | 水滴落在已选实体牌，回执显示 | 静态标记 + 回执 |
| 袖里藏花确认 | 350–500ms | 候选展开、未选牌收回、只留一张 | 即时选中 + 回执 |
| 偷梁换柱确认 | 350–500ms | 两张牌相向滑动，落回原行列 | 即时更新 + 回执 |
| 结算 | 400–650ms | 名次依次入场、少量金纸片，不遮分数 | 静态表格 |

所有动效结束状态必须由实际原型状态决定，不靠动画帧假装动作成功。支持 `prefers-reduced-motion`，设置页“关闭动画”同样生效。

## 7. 可访问性、响应与验收

- 所有入口、选牌、标签页与弹层操作使用语义按钮；有明显的 `:focus-visible`，Esc/返回、Tab 顺序与弹层焦点恢复有效。状态变更有文字回执，颜色不是唯一线索。
- 16:9 优先；窄屏页面可纵向滚动，牌桌允许整体缩放或横向滚动，但不得把手牌、点数与确认按钮截断。图片是装饰层时应 `aria-hidden`，角色名和能力由 DOM 提供。
- 页面图共 12 张，加两张透明肖像图与一张无文字背景。正式 HTML 不可用整张概念图充当交互底图，也不能复制图中错误小字。
- 演示可直接双击 `ui_demo/index.html` 打开，不依赖 CDN、构建、服务器或真实账户。保留现有主流程和可点击功能，视觉改造不能把房间、三招或结算做成静态展示。
- 开发验收至少实际走通：主菜单→单机→选角→准备→牌桌→三种绝技弹层→结算；大厅建房/加房/观战；秘籍、设置和返回；章鱼触发/未触发；余额不足、按钮禁用及降低动态效果。
